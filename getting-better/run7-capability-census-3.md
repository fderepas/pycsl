## Method

- **Population.** `scratchpad/cv14/lister.py` lists every `def` governed by a `#@ \trusted` marker in
  `src/self-annotate/src` (344 stubs; the 2 un-listed markers are closures nested inside trusted bodies, see k352)
  and the size of each LIVE body (`stubs.json`). `pick.py` joins each stub with cv11's `merged11.json` (sid, need
  list) and with cv12 / cv13's probe rows (`prev/scratchpad/cv1{2,3}/probe/results.tsv`, extracted from the
  `run7-cv12` / `run7-cv13` branches by `git archive`). The deepest prior spec that needs no stand-in tree is
  REPLAYED (`k<sid>_R`); stubs without one are ported verbatim (`k<sid>_0`).
- **Selection** (`static.py`). An AST scan of each LIVE body marks the constructs that no run #7 build touched and
  that have no free respelling: `with .. as`, nested `def` / `lambda`, self-recursion, `getattr` / `setattr` /
  `type()` / `eval` / `__import__` / `globals`, `open()`, and unmodelled file-system / tempfile / json.loads calls.
  Small-file stubs WITHOUT such a construct (85) were all probed. For the big files (expressions, statements,
  stmt_control_flow, functions, Transpiler, Module5, pure_ast, core_ir_semantic, types, preamble) only the
  candidates whose prior wall is one of run #7's new capabilities were probed (30 queued; see §5).
- **Chain extension.** At each wall the next link was classified:
  - [R] a behaviour-identical live respelling;
  - [T] a mirror retype (the LIVE signature, or a typed local annotation; the mirror's `int` erasures are the most
    common first wall);
  - [S] a stand-in for an unbuilt capability, either as a body edit or as an emission-level patch of the `.mlw`
    (`mlwx/*.mlw`, `why3 prove --type-only`).
  A chain counts as CLOSED only at an honest TC-OK (input-reading, no facade, every return reachable), read off
  the `.mlw`.
- **Classes** used below:
  - ZERO-LINK: closes at TC-OK with free links only;
  - ONE-LINK: closes at TC-OK with exactly one unbuilt capability simulated, all other links free;
  - ONE-CAP?: one capability seen, the rest of the chain not yet measured;
  - FREE-NEXT: the next link is free and has not been probed yet;
  - CAP: the next wall is one capability, and a further wall is likely (prior chains) or unmeasured;
  - MULTI: two or more capabilities are measured on the chain;
  - HARD: an unmodelled construct with no small fix;
  - DECISION: an open user decision;
  - CORRECT: the remaining wall is a real semantic fact (e.g. a CPython-reachable IndexError under `requires True`).
- **Raw data** (all under `scratchpad/cv14/`):
  - `probe/results.tsv` and `probe/<tag>.{log,patchlog}` (committed). The `<tag>.src.py` / `.mlw` copies are
    regenerated by `probe.sh` from the spec; `*.mlw` is git-ignored. Only the `mlwx/*.mlw` stand-ins are force-added;
  - `spec/*.json`, the new links, applied by cv13's `patch.py`;
  - `mlwx/*.mlw/.log`, the emission-level stand-ins;
  - `notes.tsv`, one row per measured link;
  - `pop.json`, `stubs.json`, `queue_all.list`;
  - `gen_doc.py`, which renders §4 from `notes.tsv`.
- **Runner:** `chunkb.sh` → `multi.sh` → `probe.sh` (cv13's `probe.sh`, repointed).
