## 0. The question, and the headline measurements

PyCSL verifies annotated Python by translating it to WhyML for Why3. It also verifies its own emitter (the
"self-annotation mirror"), and that emitter is written over a JSON-shaped intermediate representation (IR):
IR nodes are `Dict[str, Any]`, values are `Any`. A function of the mirror that cannot yet be proved is a
`\trusted` stub (assumed, not proved); there are **389** at HEAD. In run #3 (report
`getting-better/dict-value-model-r3.md`, review `-r3-response.md`, plan `-r3-impl.md` §1) a model for these
mixed-type values was judged not worth building and was recorded as a **CERTIFIED-BOUNDARY**, with a
reopening test. On 2026-11-13 the user **reopened** the boundary (run log entry 838): build a *real* model of
mixed-type values. A new WhyML value type is allowed (for example an `HAbsent` constructor or a schema-keyed
value), but under the coupling rule (any new WhyML value shape co-lands with an axiom-free Rocq **and** Lean
certificate), with no new axiom, refusal rather than approximation, and every lower-bound plane unchanged.
The user asked for an early read of the Z3 / `pairs_get` E-matching cost. **The question for the reviewer:
which model, built in which order, converts the most of the blocked stubs soundly, at a proof cost the
mirror can afford?**

## 1. The system

### 1.1 PyCSL

PyCSL is a contract language (`#@` comments: `requires`, `ensures`, `assigns`, loop invariants and variants,
`no_exception`, `\trusted`) plus a verifier for a statically analysable subset of Python (`README.md`). The
pipeline in `src/pycsl/` is: ingest (Module 1), a Lark parser for `#@` (Module 2), weaver (3), semantic checks
(4, `core_ir_semantic.py` and the ir-semantic passes in `pycsl.py`), a JSON IR emitter
(`frontend/Module5_IREmitter.py`), and the WhyML transpiler (`Module6_WhyMLTranspiler.py` +
`module6_whyml/*.py`). Why3 1.8.2 generates verification conditions; Alt-Ergo 2.6.3 and Z3 4.13.3 discharge
them (`why3 config list-provers`; no CVC5 is configured on this host). The default proof call is per prover,
best-of-N per goal: `why3 prove -a split_vc -P <prover> --timelimit 30` (`pycsl.py:38787-38804`,
`_dispatch_provers`), followed by a per-function vacuity probe (`ensures false` per function, 5 s,
`pycsl.py:38340-38420`).

### 1.2 The self-annotation mirror and `\trusted`

`src/self-annotate/src/` mirrors the emitter file by file. Each mirror function is either:
- **converted**: its body is the live emitter body **verbatim**, under the fixed contract shape
  `requires True / ensures True / assigns <tight frame>` (type safety plus frame, never value-faithful, never
  vacuous: `config/skills/self-tcb-reduction/SKILL.md`);
- or a **`\trusted` stub**: its signature and contract are assumed without proof.

Count at HEAD: **389** `#@ \trusted` lines (H1); `getting-better/trusted-reasons.tsv` has 387 lines. The
mirror's *annotations* may differ from the live ones (they are the modelling layer: the fidelity checker strips
annotations before comparing bodies). So a mirror may write `rec: Dict[str, PyVal]` where the live code writes
`rec: dict`. `PyVal` is a sentinel name (`PyVal = Any` at run time, `src/self-annotate/src/errors.py:24`) that
selects the certified `hval` model (§2.1). This freedom is what the reopening test (§3.2) exercises.

### 1.3 The three lower-bound planes (L-planes)

A conversion counts only if three disjoint executable oracles pass, unchanged
(`config/skills/self-tcb-reduction/SKILL.md`, §L-planes):
- **L1 mirror fidelity**: `bin/check-self-annotate-sync.sh`, `bin/self-annotate-mirror-check.sh` (mirror body =
  live body modulo `#@` lines and annotations).
- **L2 whole-file Why3 proof**: `pycsl.py <mirror file>` proves the whole home file, 0 non-Valid goals, plus
  `--fun <name>`. Last measured whole-file times (brief): `expressions.py` ~11 h, `statements.py` ~10 h,
  `stmt_control_flow.py` ~5-10 h, `pure_ast.py` ~3.3 h, `Module5_IREmitter.py` ~3 h, `core_ir_semantic.py`
  ~1.8 h, `functions.py` ~1.6 h, `Module6_WhyMLTranspiler.py` ~1 h, small files < 0.5 h.
- **L3 corpus byte-diff inertness**: `bin/byte-diff-sweep.sh` gives a byte-identical `.mlw` for every
  reference program in both corpus trees against a baseline at the base commit. Under rule M1 a
  corpus-affecting build is allowed only if the diff is exactly the intended correction and every moved
  corpus file is re-proved. A baseline is never re-taken to make a diff disappear.

Further gates: non-vacuity (`check-emitted-vacuity.py`), `check-assigns-writes-survival`,
`check-trusted-frame-honesty`, `check-getattr-erasure`, `bin/run-soundness-planes.sh`, and the mirror emission
sweep `bin/mirror-emit-sweep.sh` (every mirror file whose emission moves is reported and re-proved).

### 1.4 The ledger and the coupling rule

The soundness story is mechanised in Rocq and Lean under `src/formal-semantics/`. Its trust ledger has exactly
**3** axioms: `alt_ergo_correct` (`rocq/Phase5b_Soundness.v:598`), `trusted_contracts_axiom`
(`rocq/Phase5b_Soundness.v:612`), `why3_implements_wp_w` (`rocq/Phase6i_Soundness.v:65`); the ledger is named
in, e.g., `rocq/Phase2c_PyValDict.v:20-24`. Certificates may otherwise use only the kernel axioms of
`src/pycsl/proof_axiom_allowlist.py` (Rocq: propositional extensionality, functional extensionality (two
spellings); Lean: `propext`, `Classical.choice`, `Quot.sound`) and are checked by `Print Assumptions` /
`#print axioms`.

**Coupling rule** (`config/skills/self-tcb-reduction/SKILL.md:252-258`): a feature introducing a new WhyML
value shape (record / variant ADT) co-lands with a `src/formal-semantics/` certificate that the new value is
sound, axiom-free, in Rocq **and** Lean; *value* soundness (certificate) and *termination* (a Why3 `variant`
VC) are separate obligations.

### 1.5 Hard rules any route must respect

1. No new axiom; no cited lemma standing in for a missing model; refuse rather than approximate.
2. Verbatim bodies; only annotations may differ.
3. No vacuous facades (a converted body must read real modelled structure).
4. L3 inertness, or (M1) a diff that is exactly the intended correction with every moved file re-proved.
5. The fixed contract shape `requires True`: no well-formedness precondition on the input (so no
   `requires wf_ir x`).
6. No helper extraction in mirrored files (`src/pycsl/**`): new code inline (mirror-coverage ratchet).

### 2.2 The `hval` theory, exactly as emitted

`_emit_pyval_theory` (`preamble.py:8134-8292`) emits (checked against `scratchpad/rp4/em/mono.mlw:214-268`; comments omitted; the last two functions only under the

There is no `axiom`, `lemma` or `goal` declaration. The only specified symbol is `hpairs_key_eq`, whose
`ensures` Why3 turns into a task hypothesis (acknowledged at `preamble.py:8146-8152`). Two observations matter
for the routes:
- **Two dict carriers for one Python dict.** A top-level dict parameter / local is a Why3
  `map string (option hval)`; a dict *nested inside* an hval is an `hpairs` association list. Reads on the
  first are `Map.get`; reads on the second are `pairs_get`, a recursive function. Every `pairs_get` occurrence
  in a goal makes Why3 emit the recursive definition as a quantified equation for the SMT solver: that is the
  E-matching surface (§5).
- **No absent marker, no None, no bool, no tuple.** `None`, `bool` and tuples are wrapped as `HInt`
  (`_pyval_wrap`, `expressions.py:1526`), and an absent key is `HInt pycsl_none` (`val function pycsl_none :
  int`). Consequently an `isinstance(v, int)` test on a read must be `(any bool)` (it cannot tell an absent key,
  a None, a bool and an int apart), and `v is None` has no lowering.

### 2.4 Where the `#UND` hashing refusal stands

In run #3 the hashing family was closed by **route R-gate** (annotations §7.131,
`PYCSL-R349-UNDERIVABLE-HASH-UNDER-CLAIM`) plus **route #430** (§7.132, `PYCSL-R430-CALLEE-UNDERIVABLE-HASH`) and
later route #438 (§7.139, an un-parameterised `tuple` is underivable when hashed). At HEAD (`pycsl.py`): the
sentinel `#UND` is `_U383` (`:6969`), attached to the value of an unknown callee / receiver or un-annotated
return (`:6966`, `:7390`, `:8688`, `:9863-9900`). A hashed site (set element, dict key, `in`, subscript of a set /
dict, `hash()`) whose derived class set contains `#UND` / `#UNKT` or is empty is recorded (`_und430`, `:9985`)
and **refused only if the enclosing non-trusted function claims `no_exception` covering TypeError**
(`:9987-10105`); un-claimed sites are admitted (sound because an ambient exception only ends the function
abnormally; the P1 argument of `dict-value-model-r3-impl.md` §R2). Cross-file: `:17195-17301` (route #439); the
callee bit is checked at `module6_whyml/functions.py:1955-1963`, `:2490-2507`. The positive deny-list ("a list
/ dict / set", unhashable records) stays unconditional — and that is exactly what refuses H4 (§3.2): once a
value is *typed* `PyVal`, it is no longer underivable but "may be a list / dict / set", and every hashing site
of it is refused whatever the claim. **Any route that gives Any-values a real type must therefore also give the
hashing pass a way to know that a given value is a hashable scalar.**

## 6. State-of-the-art lens: how other verifiers model dynamically-typed / JSON-like values

| system | value model | how reads / absence / mutation are handled | lesson for PyCSL |
|---|---|---|---|
| **Why3** (Filliâtre & Paskevich, ESOP 2013) | strictly positive mutually recursive algebraic types; `let rec function` with a `variant`; polymorphism encoded to many-sorted SMT (Bobot & Paskevich, FroCoS 2011) | a recursive logic function reaches the solver as a universally quantified definitional equation with a trigger on the function application; every new `pairs_get` term can fire it again | this is the `pairs_get` cost: one unfolding per key comparison down an association list, multiplied by every case split of the surrounding `match`es. Why3 has no fuel control |
| **Dafny** (Leino, LPAR 2010) | inductive `datatype`s, boxed to Boogie's `Box` for generic containers; `map<K,V>` is a built-in theory | recursive functions are encoded with **fuel** (Amin, Leino, Rompf, "Computing with an SMT solver", TAP 2014): by default one unfolding per call site, extra unfolding only on literal arguments; this exists precisely to stop matching loops; Dafny's JSON libraries (`Dafny-libraries` `JSON`) define a `datatype JSON = Null \| Bool \| String \| Number \| Object(seq<(string, JSON)>) \| Array(seq<JSON>)` | an hval-style ADT is the standard answer; the difference is the fuel discipline. In Why3 the analogue is to make `pairs_get` a `val function` with a *non-recursive* `ensures` per constructor (an "unfold-once" spec) or to use `Map` as the only dict carrier |
| **Viper / Nagini** (Eilers & Müller, CAV 2018) | every Python value is a `Ref`; `typeof(r)` maps it into a `PyType` domain; `dict` is a Viper domain with permission-guarded contents | requires mypy-clean PEP 484 types and refuses what mypy cannot type; `Any` is accepted only as an unconstrained `Ref`; mutation is via permissions (implicit dynamic frames), so aliasing is explicit | Nagini would refuse most of the emitter (`Dict[str, Any]` everywhere). Its answer to aliasing of nested mutable values is a heap with permissions, which PyCSL's value-semantics encoding does not have: route (a)'s functional write-back (`pairs_set`) is only sound when the nested value is unaliased (the r2c escape check) |
| **F\* / Low\* / EverParse** (Ramananandro et al., USENIX Security 2019) | refinement types over inductive types; EverParse generates verified parsers from a format description into *typed* values | the untyped bytes are validated once at the boundary; downstream code works on a typed record with proved properties | the schema-keyed idea (route b): `ir_schema.py` is the format description of PyCSL's IR. The difference: PyCSL has no validated ingestion point under `requires True` (rule 5), so the typed view must be total (a fallback for every off-schema value) |
| **Liquid Haskell** (Vazou et al., ICFP 2014; PLE, POPL 2018) | refinement types on ordinary Haskell ADTs (e.g. aeson's `Value`); **measures** | a measure is a structural function translated to uninterpreted function symbols whose definition is asserted *only at constructor applications and pattern matches* (no quantified axiom); Proof by Logical Evaluation unfolds terminating definitions a bounded number of times | the cheap encoding of `hval_len`, `hval_truthy`, `pairs_get`-on-literal: instantiate the defining equation at the constructor sites the emitter itself produces, instead of a quantified definition |
| **Dependent / nested refinements for JavaScript** (Chugh, Rondon, Jhala, POPL 2012; Chugh, Herman, Jhala, DJS, OOPSLA 2012) | dictionaries with dynamic string keys typed by refinements: `has(d, k)`, `sel(d, k) :: T` | flow-sensitive: after a `typeof` / key test the refinement of `sel(d, k)` is narrowed, so heterogeneous dicts get per-key types *where the code checks* | exactly the narrowing PyCSL lacks (§2.3 `nested_goal`): `isinstance(g, str)` makes the tag match but the narrowed `string` is not propagated to the use |
| **Gillian-JS / JaVerT** (Santos et al., POPL 2018) | JS values are a tagged union in the logic; every operation dispatches on the tag; objects are heap-allocated | faithful, but VC volume grows with the dispatch | the cost model of route (a) at full fidelity: the emitter's handlers are dispatch-heavy, so every dispatch arm multiplies the goals |
| **Creusot / Prusti** (Denis, Jourdan, Marché, ICFEM 2022; Astrauskas et al., OOPSLA 2019) | Rust: `serde_json::Value` is an ordinary `enum`; Pearlite / Prusti pure functions over it | ownership makes nested mutation local (`&mut` reborrows), so functional update of a nested value is sound by typing | the aliasing question PyCSL must answer by analysis (escape check) rather than by types |
| **VeriFast** (Jacobs et al., NFM 2011) | inductive datatypes and fixpoints in the ghost logic | fixpoints are **not** given to the solver as quantified axioms; they are unfolded only by explicit `open` / `switch` / lemma calls | the extreme of the fuel discipline: zero automatic unfolding, everything guided |
| **TypedDict / PEP 589 / 655** (mypy, pyright); Typed Racket occurrence typing (Tobin-Hochstadt & Felleisen, ICFP 2010) | closed record per dict shape, `Required` / `NotRequired` keys; narrowing after `isinstance` / key tests | `d["k"]` gets the declared type; `.get` gets `Optional`; unsound at the `Dict[str, Any]` → TypedDict boundary (only `cast`) | PyCSL already lowers TypedDict to records (carrier 5) and has three closed-key views in the mirror; what is missing is a *modelled* cast from hval to a record view (r3 q7: an L3 clash, fail-closed) |

### (a) One recursive JSON-like value type, faithful operations, narrowing

**What.** Extend or replace `hval` with a value type that has a constructor per runtime kind that the IR
actually carries, and make the operations exception-faithful:
`JInt int | JStr string | JBool bool | JNone | JList jv_list | JDict jv_pairs | JTuple jv_list | JFloat real
| JNode ...`. Observations from §2-§3 that shape it:
- **The faithful value of an absent `.get` is `None`, not a new "absent" marker.** In Python `d.get(k)` on an
  absent key *is* `None`; `d[k]` raises KeyError. So the fix of H7 is a real `JNone` (plus `JBool`, today folded
  into `HInt`), with `.get(k)` → `JNone` and `d[k]` → a KeyError obligation under a claim (today an `HInt 0`
  placeholder that is dead only under `no_exception KeyError`, `expressions.py:1388-1390`). An `HAbsent`
  constructor would model something Python does not have; it is only useful as an internal result of
  `pairs_get` (and there `option` already plays that role).
- **Narrowing must propagate** (`nested_goal`, 034a, 250a): after `isinstance(x, str)` the uses of `x` take
  `hstr_of x`; a conditional-expression test on a value is `hval_truthy`; a key position takes the projected
  key.
- **hval-polymorphic builtins**: `tuple`, `", ".join`, `len`, `in`, `sorted`, iteration with a real length
  (`jv_list_len`) as the loop variant.
- **Mutation**: `setdefault`, `pop`, `update`, item store, `.append` / `.extend` on a nested list, `dict(x)`
  copy. These are functional updates (`pairs_set`, `snoc`) of a value-semantics encoding. They are sound only
  when the nested value is unaliased; the r2c escape check (`statements.py` `_handle_expr_stmt`) is the
  existing precedent, and it is fail-closed.
- **Hashability**: a scalar-tag predicate (`JInt | JStr | JBool | JNone | JTuple of hashables`) that the hashing
  pass can use as a *derivation* (H4), with a TypeError obligation under a claim and the ambient rule
  otherwise.

**Converts (estimate).** Family R (13) and part of family T (8) have a read as their first blocker; family M
(17) needs the mutation set; family I (3) needs the iteration length. cv12's notes show at least one *more*
non-dict wall behind many of these (e.g. s001's set-valued field, route #325, measured in §3.2; s270's untyped
trusted callee; s229's closure; s294's `Dict[str, tuple]`). The prior from r3 and §3.2 (one link per

(s362, with a None tag + a `Tuple[PyVal, ..]` codomain + an hval `tuple()`), and 16 of 43 have a non-value first
wall. My estimate: **1-5 of 48 with a pure value type + reads + narrowing + builtins; more only with the
mutation / by-reference set of route (f)**. **Surface:** `preamble.py` (theory), `expressions.py`
(reads, projections, builtins, narrowing, truth tests), `statements.py` / `stmt_control_flow.py` (stores,
iteration), `functions.py` (param / return typing, tuple codomain), `Module5_IREmitter.py` (selection),

the homes of converted stubs. If done as a new separately gated theory: only the adopting files, but every

### (b) Schema-keyed typed views, with the tagged value only as the total fallback

**What.** Give each literal-key read a *typed projection chosen by the key's schema type*, and keep the tagged
value (route (a)'s type, or today's `hval`) only as the carrier and the fallback. The schemas exist:
`src/pycsl/ir_schema.py` (117 classes, 114 field names; r3 §4.4 measured that 35 key names have a single scalar
type and `name` is `str` in every class), the `TypedDict` views already in the mirror, and for the non-IR
records (why3 JSON goal records, Lean JSON) a mirror-side `TypedDict` written in the annotation layer. Under
`requires True` the input may be off-schema, so a view must be **total**: `hstr_of (get d "name")` returns the
real string on `JStr s` and an opaque string otherwise. That is already how `hstr_of` behaves; what the schema
adds is *which* projection to apply, statically, at reads whose consumer needs a scalar (typed slots, f-strings,
keys, hashing). Off-schema inputs reach the opaque arm, which is sound for the fixed contract shape (type safety
+ frame), and under a `no_exception` claim the off-schema arm is exactly where CPython raises, so it is an
obligation (refused, or unprovable), never a false proof.

**Converts (estimate).** Family T (8: erased value into a `str` slot / f-string / frame) and the read part of
family R are the targets; it is also the only route that answers H4 (a slot typed by the schema as `str` is a
hashable scalar, so `_record_key`'s tuple codomain stops being "may be a list"). It does nothing for family M.
**About 4-10 of 48**, overlapping (a). **Surface:** a key→type table (`Module5_IREmitter.py`, from the mirror
TypedDict annotations; a `JsonSchema`-like view per record kind), projection insertion in `expressions.py`, and
the hashing derivation in `pycsl.py`. **Mirror files moved:** only files that adopt the views (if the views are
gated on the mirror-side TypedDict names) plus the homes. **Corpus:** inert if the views are selected only by
`PyVal`-typed carriers; *not* inert if the existing TypedDict lowering changes (the corpus has TypedDict
programs, annotations §7.44 / §7.54 / §12.12). **Certificates:** if the views project into existing WhyML types
(`string`, `int`, records already covered by `Phase2b_RecordVal`), there is no new value shape and the coupling
rule asks only for the projection lemmas (`hstr_of (HStr s) = s`, totality), small. A modelled `cast` from the
tagged value to a TypedDict record *is* a new shape (record of projections) and needs a Rocq + Lean
side-car. **E-matching risk:** lower than (a): a projection of a `Map.get` is non-recursive; only nested reads go
through `pairs_get`. **Soundness risks:** schema drift (the view must never be assumed, only projected; a wrong
schema type only sends values to the opaque arm); `NotRequired` keys (route #398's discipline).

### (c) Keep int-erasure, add typed views per use site

**What.** Leave `Dict[str, Any]` erased to `int` and insert an opaque, typed conversion where an erased value
meets a typed slot (`str` parameter, f-string, `map string` key). **Assessment: refuse.** Route #252 exists
because an erased int reaching a builtin slot was a false-proof channel, and route #325 because claims true of all
integers were proved of non-int values (their messages quote the measured false proofs). An opaque conversion of
an opaque int also does not read the receiver when the receiver itself is erased (carrier 2:
`f_get_1 <hash>`), so the converted bodies would fail the non-vacuity / input-blind honesty check. It would
convert few stubs honestly (those whose receiver is already a typed map) and moves no certificate, but it is an
approximation of a value, which rule 1 forbids. Listed for completeness.

### (e) A cheaper carrier for nested dicts (an enabler for (a) / (b))

**What.** Reduce the `pairs_get` E-matching surface without changing the Python model: (e1) constant-fold

### (f) By-reference dict values (a heap of mutable dicts with frames)

**What.** cv13's largest operation group is mutation and aliasing (O11 in-place / nested write-back, 11 stubs;
O12 by-reference dicts, 5), and its interim conclusion is that "a model that closes the population must be a
by-reference (mutable, aliased) dict value with writes frames, or the stubs need value-returning live
refactors". The faithful model of Python's dict *objects* is the Viper / Nagini one: a dict value is an address;
a global `heap : map addr dictval` (or one heap per value kind) holds the contents; `d[k] = v`, `setdefault`,
`pop`, `.append` on a nested list are heap updates; a function that mutates a dict argument `writes { heap }`
(or a region of it); aliasing is then free (two names, one address). **Converts:** the M family and O12 rows
that are otherwise short (cv13's open rows s108, s118, s139, s142, s160, s162, s273, s268 have a dict mutation
as their measured wall); plausibly 5-10 more of 48 on top of (a) / (b), unmeasured. **Surface:** the largest of
all routes: every dict-typed parameter, field and local of the mirror changes WhyML type (`addr`), every read
goes through the heap, every frame gains the heap, and the tight `assigns` frames of the fixed contract shape
(rule: `assigns <tight frame>`) must be expressed over heap regions, which the frame-honesty plane
(`check-trusted-frame-honesty`, `check-assigns-writes-survival`) must learn to check. **Mirror re-proof:**
every file that adopts it, likely all 21 hval files plus the dict-heavy ones. **Certificates:** a heap model with
read-over-write and frame lemmas (the `Phase2b_RecordVal` `path_read_back` / `path_frame` pattern, lifted to
addresses), Rocq + Lean; medium. **E-matching risk:** read-over-write on a Why3 `map` is native to the solvers
(array theory), cheaper than recursive `pairs_get`, but the frame obligations multiply. **Soundness risks:**
an unsound alias assumption (two addresses assumed distinct) is a false proof; fresh-allocation reasoning;
iteration over a dict while it is mutated (CPython raises RuntimeError). This is the route with the highest
ceiling and the highest cost; it is a redesign of how the mirror models state, not an extension of `hval`.

**Open questions for the reviewer:**
1. **Value model or state model?** cv13's interim data say mutation and aliasing (O11 + O12) are the largest
   need, and a pure immutable value cannot express `ir_data["functions"].insert(0, f)` or a dict passed to a
   mutating callee. Is a by-reference heap (route (f)) the right object, given that it redesigns how the mirror
   models state and its frames? Or is the honest boundary "pure reads convert; mutation stays trusted"?
2. **Absent vs None.** I argue (§7 (a)) that the faithful fix is a real `None` tag (Python's `.get` *returns*
   None) rather than an `HAbsent` marker, with `d[k]` on an absent key as a KeyError obligation. cv13 writes
   "HNone/HAbsent". Is there an operation where absence must be distinguished from a stored `None` (e.g. `k in
   d` after `d[k] = None`)? On the top-level carrier it already is (`Map.get = None` vs `Some HNone`).
3. **Hashing a typed mixed value.** H4 shows the tuple codomain is refused at its consumer. A scalar-tag
   derivation (hashable iff `JInt | JStr | JBool | JNone | JTuple` of hashables) would make the hashing pass
   *more* permissive for `PyVal` values: is "derived hashable from a tag that is itself only known at run time"
   a derivation, or does it need a TypeError obligation at every hashing site (refused under a claim, ambient
   otherwise, exactly like `#UND`)?
4. **Does `hstr_of`'s opaque arm hide a TypeError?** `hstr_of h` returns `hval_opaque_str h` on a non-`HStr`;
   when the projected value then flows into an operation that CPython would reject on a non-str (`+ "x"`,
   `.split`), the model computes on the opaque string. Under the fixed contract shape (no claim) this is an
   ambient exception and sound by the P1 argument; under a `no_exception` claim, is every such projection site
   an obligation today? I did not audit it.
5. **Is the `pairs_set` cert gap (§1.4) a coupling-rule violation already in the tree?** The certificate proves
   read-back for a prepending `pairs_set`; the emitter uses replace-first / append. The read-back property holds
   for both, but the certificate does not state it for the emitted function.
6. **Z3 brittleness.** Is a model whose value facts Z3 cannot prove but Alt-Ergo proves in 0.1 s acceptable
   under best-of-N, or should the route budget for a fuel-style encoding (route (e)) from the start?
7. **Gate the new theory or extend `hval`?** Extending `hval` re-proves 21 files (~35-40 h) at once; a gated
   second theory keeps them inert but leaves two coexisting mixed-value models (plus `pyval`, `emit_ir`) and
   bridges between them (cv13's O16, 5 stubs). Which debt is cheaper?
