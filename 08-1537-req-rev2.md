## 1. The `open` blow-ups — diagnosis

All **10** unproven `open` goals are the SAME goal: `os.open`'s postcondition
`\result == -1 or \result >= 3` (1 Timeout + 9 Unknown — the 10 are the per-return-path sub-goals).

`os.open` is a one-line wrapper:
```python
#@ ensures \result == -1 or \result >= 3
def open(filepath, flags, mode=0o777, *, dir_fd=None):
    return _filesystem.sys_open(filepath, flags)
```
`_filesystem` is a module global, so the IR-inliner **splices `sys_open`'s entire body** into `open`.
`sys_open` is large and disk-mutating — `_dir_lookup`, `_alloc_inode`, `_write_inode`,
`_dir_find_free`, `_write_entry`, `_read_inode`, `_check_perm`, then fd-table allocation. Proving
`\result >= 3` through all of that (and all its sub-calls' effects) blows up the SMT search across
~10 paths. **This is the exact same inlining-blow-up pattern that `#@ no_inline` already fixed for
`sys_write`** (os 45→39, commit `dcd1d6d`).

`\result >= 3` is backed by the class invariant `self.next_fd >= 3` (UnixInodeFileSystem line 114):
`sys_open` returns `fd = self.next_fd` (or -1), and `next_fd >= 3` is maintained.

## 2. The fix — and it's VALIDATED for `open`

Give `sys_open` a contract + `#@ no_inline` (the established pattern):
```python
#@ requires True
#@ assigns self.disk, self.fd_open, self.fd_inode, self.fd_offset, self.fd_flags, self.next_fd, self.inode_bitmap
#@ ensures \result == -1 or \result >= 3
#@ no_inline
def sys_open(self, pathname: str, flags: int) -> int:
```
Then `os.open` consumes `sys_open`'s contract instead of re-proving the inlined body — and
`\result == -1 or \result >= 3` follows *identically*.

**Measured (this investigation):** with that contract + `#@ no_inline`, **`sys_open` proves its
contract standalone** (`--fun unixinodefilesystem__sys_open` → SUCCESS! All) — i.e. it passes **both**
gates of §3 (performance *and* soundness, against the real `ensures`, not a trivial one). So `os.open`'s
10 goals clear. *(Validated then reverted — pending your prioritization.)*

## 3. The big finding — generalizes to ~31 of 33, but mind the TWO gates

The other 23 remaining goals are the SAME pattern: thin `os.*` wrappers that inline a complex `sys_*`
method. **Applying `no_inline` is correct only when two distinct gates pass — and they fail
differently:**

- **Performance gate** — *does inlining blow up?* If yes, `no_inline` is the fix. (Failure here is
  *fail-loud*: a timeout/unknown you can see.)
- **Soundness gate** — *does the `sys_*` prove the wrapper's REAL `ensures` standalone?* If **no**,
  `no_inline` is **worse than doing nothing**: it converts a visible blow-up into an **invisible false
  assumption** the wrapper (and its callers) then trust. (Failure here is *silent* — the `readlink`
  trap, §4.4.)

A ✅ requires **both**. The prior table's single "viable?" column conflated them; here they are split:

| `makedirs`+`mkdir` | 8+4=12 | `sys_mkdir` | yes (proves standalone w/ **trivial** post) | **UNCONFIRMED** — needs `--fun` w/ `\result==0 or -1` | 🟡 perf-viable, soundness-pending |

## 4. Caveats (the soundness substance)
1. **Trivial-vs-real postcondition.** The 🟡 `sys_*` proved standalone with a *trivial* post. The
   wrapper's `ensures` (e.g. `\result == 0 or \result == -1`) is a **new, stronger obligation** the
   `sys_*` must re-clear — confirmed for `sys_open`, **unconfirmed** for the rest. "Proves standalone"
   ≠ "proves the contract we need." This is why the siblings are 🟡, not ✅.
2. **`assigns` completeness is a PROVEN property, not eyeballed (rev2).** An incomplete `assigns` is
   not merely a frame-VC nuisance — if it is incomplete in a way the callee's own proof tolerates but a
   caller relies on, it is **silently unsound**. So completeness must be *demonstrated*: the callee's
   `assigns` is checked against its body's actual writes by the frame VC, and a **deliberately-omitted
   target must fail that VC** (a one-line negative test per method). `sys_open`'s set (`disk` + all five
   `fd_*` + `next_fd` + `inode_bitmap`) was derived from the body and passes; each sibling's set must be
   *proven* exact the same way, not asserted "mechanical."
3. **`no_inline` is sound *given the soundness gate*.** The callee stays a verified `let`; a false
   `ensures` fails the callee (gated by driver 0650); no TCB growth — **provided the callee actually
   proves its contract** (§3 soundness gate). `no_inline` on a callee that does *not* prove its real
   contract is the §4.4 trap.
4. **`sys_readlink` already fails its own proof** — `no_inline` would *propagate* a false assumption.
   Do NOT no_inline it until its standalone proof is fixed. (This is gate-2 failing in the open; the
   🟡 rows are the danger of gate-2 failing *silently* if not confirmed.)
