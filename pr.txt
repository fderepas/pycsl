Fix compatibility with stdpp 1.13.0 and Rocq 9.1 (qualified Logic import)

## Summary

This PR fixes 7 files to build successfully under `coq-stdpp 1.13.0` and
`Rocq 9.1` (formerly Coq 8.20 was the target). All changes are mechanical
compatibility fixes — no proofs or semantics are altered.

## Background

The why3-semantics library was developed against an earlier version of stdpp.
stdpp 1.13.0 renamed several lemmas and changed the statements of a handful
of others (conditional form vs. unconditional rewrite). Additionally, Rocq 9.1
introduces a naming ambiguity for the bare `Logic` identifier (it now
conflicts with `Stdlib.Init.Logic`), requiring qualification to
`Proofs.core.Logic`.

## Changes

### `proofs/common/mapset.v`

- `elem_of_list_fmap` → `list_elem_of_fmap` (stdpp 1.13.0 rename).

### `proofs/common/zmap.v`

- `lookup_partial_alter` now has a conditional form in stdpp 1.13.0:
  `partial_alter f i m !! j = if decide (i = j) then f (m !! i) else m !! j`.
  The proof `apply lookup_partial_alter.` no longer closes the goal directly;
  replaced with `rewrite lookup_partial_alter, decide_True by reflexivity; reflexivity.`

### `proofs/common/gmap.v`

Three proofs in `lookup_gmap_uncurry`, `lookup_gmap_curry`, and
`lookup_gmap_curry_None` updated for stdpp 1.13.0:

- `lookup_insert` and `lookup_partial_alter` now have conditional forms;
  replaced with `lookup_insert_eq` / `lookup_partial_alter_eq` where the
  equality `i = j` is known at the rewrite site.
- The base case of `lookup_gmap_uncurry` required reordering: `rewrite
  lookup_insert` before `destruct (decide ...)` so that the conditional
  form can be resolved.
- `lookup_gmap_curry`: the `lookup_insert_ne` case in the `j ≠ j'` branch
  needed an extra step `by rewrite <-IH, lookup_empty` to discharge the
  remaining goal after `lookup_insert_ne`.

### `proofs/common/aset.v`

- `elem_of_list` (inductive) no longer exists as such in stdpp 1.13.0;
  the `∈` notation on lists now uses `list_elem_of`. The lemma `in_equiv`
  (which proved `elem_of_list x l ↔ In x l`) is replaced by a one-liner
  using the stdpp 1.13.0 lemma `list_elem_of_In : x ∈ l ↔ In x l`.
- Four occurrences of `elem_of_list_In` → `list_elem_of_In` (bulk rename).

### `proofs/common/amap.v`

- `lookup_insert` → `lookup_insert_eq` at one rewrite site (equality case
  known statically).
- One occurrence of `elem_of_list_In` → `list_elem_of_In`.

### `proofs/core/Task.v`

- `Require Export Logic.` → `Require Export Proofs.core.Logic.`

  Under Rocq 9.1 with the dune logical path `-R . Proofs`, the bare name
  `Logic` is ambiguous between `Proofs.core.Logic` (this library) and
  `Stdlib.Init.Logic` (the Rocq standard library). The qualified name
  resolves the ambiguity.

### `proofs/proofsystem/Util.v`

- Same fix as `Task.v`: `Require Export Logic.` →
  `Require Export Proofs.core.Logic.`

cd why3-semantics

All 66 `.vo` files compile without errors (deprecation warnings for
