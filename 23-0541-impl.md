### Step 3.2 — Extract `dir_ops.py`

**Create:** `src/pycsl_lib/os/dir_ops.py`
**Move from `UnixInodeFileSystem.py`:**
- `_dir_lookup`, `_dir_find_slot`, `_dir_find_free`, `_write_entry`, `_zero_entry`,
- `_blit_dir_entry`, `_blit_disk_entry`, `_read_directory`, `_scan`, `_build_direntry`
- All their contracts + `#@ proof` citations + `#@ sibling_concrete` markers.

**Keep in `UnixInodeFileSystem.py`:**
- The `UnixInodeFileSystem` class (the record + class invariant + fd table + `__init__`).
- The syscalls that DON'T need isolation: `sys_close`, `sys_fstat`, `sys_lseek`, `sys_dup`, `sys_dup2`, `sys_read`, `sys_pread`, `sys_getdents`, `sys_fsync`, `sys_ftruncate`, `sys_utimensat`, `sys_chown`.
- The syscalls that DO need isolation stay for now (moved in Step 3.3).

**Import:** `UnixInodeFileSystem.py` imports the dir helpers from `dir_ops.py` as `val` stubs (interface contracts only). The `#@ interface` mechanism (Track B, commit `b3d65d1`) carries the narrow contracts.

**Key concern (D3):** the dir helpers are currently METHODS on `UnixInodeFileSystem` (they use `self.dir`, `self.disk`). Extracting them as free functions requires either:
- **Option (a):** pass `self.dir` / `self.disk` as parameters (changes the signature, but the `val` stub hides this from callers).
- **Option (b):** make `dir_ops.py` a mixin class that `UnixInodeFileSystem` inherits from (keeps `self.dir` / `self.disk` access, but adds inheritance complexity).

**Recommendation: Option (a)** — free functions with explicit array params. The `val` stub interface carries the contract; the caller (`UnixInodeFileSystem`) passes `self.dir` / `self.disk`. The public `os.*` wrappers in `__init__.py` are unchanged (they call `_filesystem.sys_open(…)`, which stays on `UnixInodeFileSystem` and delegates to the imported `val` stub).
