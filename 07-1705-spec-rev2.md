# 07-1705-spec (rev. 2) — Faithful `array_concat` via an immutable `seq.Seq` snapshot model

**Status:** Draft, reviewed (generic specification — intent and gated phasing, not implementation)
**Date:** 2026-06-07 (rev. 2)
**Source:** the one open follow-on from `07-1321-spec.md` S4 — Python `list`/`bytes`
concatenation (`a += b`, `a + b`) currently lowers to an effect-opaque `array_extend` (unit;
type-correct but length/contents unprovable) because a faithful mutable-array `array_concat` is
rejected by Why3's aliasing discipline.
**Scope:** the **PyCSL tool only** (`src/pycsl`, WhyML emitter). `pure_lib/` is not edited here.
**Doctrine:** no-more-int / EXTREME RIGOR — a list is `array int`, and concatenation must be
modelled so the result's **length and contents are provable** (`\length(a + b) == \length(a) +
\length(b)`, and each element placed faithfully), not opaque. Legacy emission stays
**byte-identical** for every file that does not concatenate (the regression gate).

**Revision 2 — changes from review.** Four substantive additions: (a) a new **P0** probe that
proves the freshness-rebind assumption in hand-written WhyML *before* any emitter change (it is the
make-or-break and was previously only a comment, §2.1, §P0); (b) the `+=` target lowering
**commits to ref-wrapping** and drops the block-scoped `let`-shadow alternative, which is unsound
across loops/conditionals (§P2.1); (c) the import-ordering risk is resolved by **emitting seq
operations qualified** (`Seq.length`/`Seq.get`/`Seq.(++)`) rather than relying on last-import-wins
(§2.3, cross-cutting); (d) **self-concatenation** (`a += a`) is added to the soundness argument and
the acceptance set (§2.4). Acceptance boxes now state **[typecheck]** vs **[PROVE]** explicitly.

---

## 1. Why the direct mutable-array concat is blocked

`07-1321` S4 attempted:

```whyml
val array_concat (x: array int) (y: array int) : array int
  ensures { Array.length result = Array.length x + Array.length y }
  ...
dst := array_concat !dst src        (* a += b *)
```

Why3 rejects it: **"this application creates an illegal alias."** `array.Array` is a *mutable* type
with a region; a `val` taking **two** mutable `array int` arguments requires their regions provably
disjoint, and rebinding `dst` to a mutable result that may alias `!dst` is forbidden. The blocker is
the **mutability**, not the contract — the `ensures` above is exactly right.

## 2. The fix — operate on immutable snapshots

`seq.Seq` is Why3's **immutable** finite-sequence theory: pure `Seq.length`, indexing (`Seq.get`),
and concatenation (`Seq.(++)`). Immutable values have no region, so there is **no aliasing
constraint**. The design snapshots each operand array into a `seq int`, concatenates purely, and
materialises a **fresh** result array:

```
a += b   ≡   a := materialize (snapshot !a ++ snapshot b)
a + b    ≡   materialize (snapshot a ++ snapshot b)
```

with two faithful bridge vals:

```whyml
val snapshot (a: array int) : seq int
  ensures { Seq.length result = Array.length a }
  ensures { forall i:int. 0 <= i < Array.length a -> Seq.get result i = a[i] }

val materialize (s: seq int) : array int
  ensures { Array.length result = Seq.length s }
  ensures { forall i:int. 0 <= i < Seq.length s -> result[i] = Seq.get s i }
  (* result MUST be a fresh region — no alias/writes linking it to any prior array; see §2.1 *)
```

`snapshot` takes **one** mutable array (no two-mutable-arg problem); `++` is pure; `materialize`
returns a fresh array. Composing them, the length-additive and element-placement facts follow from
the three pure `ensures` + the `Seq.(++)` axioms.

### 2.1 Soundness item 1 — `materialize` freshness must be promised *to Why3* (not a comment)

The whole design rests on Why3 *knowing* `materialize`'s result is a fresh, unaliased region, so
that `a := materialize (snapshot !a ++ snapshot b)` rebinds `a` without re-triggering the alias
rejection (the old region `a` pointed to is dropped; the snapshots are region-free immutable
values). For a `val` returning `array int`, Why3 treats the result as fresh **iff** no `alias` /
`writes` clause ties it to an argument — `materialize` has no array argument, so this holds, exactly
as it does for the established `array_slice` / `sorted_1` array-returning vals. This is a
**requirement**, not a hope: `materialize` is declared with no region-linking clause, and **P0
proves the rebind is accepted before any emitter work begins.**

### 2.2 Reuse (do NOT reinvent)
- **`use seq.Seq` already exists** in the preamble (no-more-int-7 §B′), gated by `needs_seq`. Reuse
  that import path and snapshot vocabulary.
- **Array-returning val pattern** is established (`array_slice`, `sorted_1` in `expressions.py`);
  `materialize` follows the same shape, consumed via `let`/`:=`.
- The lowering site is the single `array += array` arm already isolated in
  `statements.py _handle_augassign_stmt` (today's opaque `array_extend`).

### 2.3 Soundness item 3 — import ordering resolved by qualified seq emission

`array.Array`, `map.Map`, and `seq.Seq` all provide the mixfix `([])` and a `length`. Relying on
last-import-wins to make `a[i]` (array), `m[k]` (map), and `s[i]` (seq) each resolve correctly is
fragile and is the main integration risk. **Resolution:** emit *all* seq operations **qualified** —
`Seq.length s`, `Seq.get s i`, `Seq.(++) s t` — so seq never competes for the bare `[]`/`length`
symbols. The established `array.Array`-last ordering is kept for the unqualified array `[]`; map
access is unchanged. This removes the ambiguity by construction rather than by slot-ordering luck.

### 2.4 Soundness item 2 — operand self-aliasing (`a += a`) is sound and must be tested

The composition is aliasing-free for the *result*, but `a += a` (and `parts += parts`) produces
**two** snapshots of the same array: `a := materialize (snapshot !a ++ snapshot !a)`. This is sound
— both are *pre-rebind, immutable, region-free* reads of `!a`, so reading the same region twice is
harmless, and the result (`a` doubled, length `2 * \old(\length(a))`) is correct. The earlier
invariant "the operand array is read once" was inaccurate; the accurate invariant is **"each operand
is read only via a pre-rebind immutable snapshot, so operand self-aliasing is sound."** Self-concat
is added to the acceptance set (it is common in accumulator loops).

## P0 — Freshness-rebind feasibility probe (GATE; hand-written WhyML, no emitter change)

### Requirements
- **P0.1** In a hand-written `.mlw`, declare `snapshot`/`materialize` (§2) and prove that
  `let a = ref arr in a := materialize (snapshot !a ++ snapshot b)` **typechecks and proves**, with
  both the new `!a` and the original `b` still usable afterward. This establishes Why3 accepts the
  fresh-result rebind with no residual region constraint.
- **P0.2** Prove the same for the self-aliasing form `a := materialize (snapshot !a ++ snapshot !a)`.

### Acceptance
- [ ] **[PROVE]** P0.1 round-trip-with-rebind discharges (length-additive + element placement).
- [ ] **[PROVE]** P0.2 self-concat discharges (`\length` doubles).
- [ ] If either fails, **stop** — the snapshot/materialize mechanism is not viable as specified and
      the design must be revisited (e.g. a `seq`-typed list model) before P1.

*Rationale:* this is the single make-or-break assumption; proving it in raw WhyML costs one file and
de-risks the entire emitter effort.

## P1 — Snapshot bridge vocabulary (LOW)

### Requirements
- **P1.1** Emit `snapshot`/`materialize` bridge vals (§2) into the abstract-op block behind a
  `needs_seq`-style flag, so non-concatenating files stay byte-identical. `use seq.Seq` is triggered
  only when the bridge is used; seq ops are emitted **qualified** (§2.3).
- **P1.2** The bridge `ensures` are length- and element-faithful (no int-hash, no opacity), and
  `materialize` carries **no** region-linking clause (§2.1).

### Acceptance
- [ ] **[PROVE]** A round-trip driver (`materialize (snapshot a)` equals `a` element-wise, same
      length) proves *through the emitted vals* (not just the hand-written P0 form).
- [ ] **[typecheck + byte-diff]** Files with no concatenation emit byte-identical WhyML (no
      `seq.Seq` import).

## P2 — Lower `array += array` faithfully (MEDIUM; the blocker)

### Requirements
- **P2.1** `a += b` where the target is array-typed lowers to
  `a := materialize (snapshot !a ++ snapshot b)`. **The target must be ref-wrapped** so the fresh
  result is observable in *every* subsequent statement, including across loop iterations and
  conditional branches. A block-scoped `let`-shadow is **not** acceptable (it does not propagate past
  its block, silently dropping the update inside loops/`if`). If the target local is not already
  ref-wrapped, it is **promoted to a ref at its declaration**, and that promotion is byte-diff-gated
  (only files with array `+=` change). The opaque `array_extend` arm is **removed**, not kept as a
  fallback.
- **P2.2** The src operand `b` is snapshotted whether param, local, or literal; a ref-wrapped src is
  dereferenced first (`snapshot !b`). Operand self-aliasing (`a += a`) is permitted and sound (§2.4).
- **P2.3** No integer-`+` path and no `array_extend` opacity remain for array operands.
- **P2.4** `\length` of the post-concat target, and indexed reads of it, resolve through the
  `materialize` ensures.

### Acceptance
- [ ] **[PROVE]** `cat(a, b)` with `ensures \length(\result) == \length(a) + \length(b)` proves
      (driver `0619`, currently type-only, upgraded to prove the length law).
- [ ] **[PROVE]** Element placement: `(a + b)[0] == a[0]` for non-empty `a`, and
      `(a + b)[\length(a)] == b[0]`.
- [ ] **[PROVE]** Self-concat: `a += a` gives `\length(a) == 2 * \old(\length(a))` (§2.4).
- [ ] **[PROVE]** Loop-update: a `+=` inside a `while`/`for` body is observed *after* the loop
      (catches the let-shadow bug P2.1 forbids).
- [ ] **[PROVE]** Byte-packing shape (`parts = bytearray(); parts += _pack(...); ...`) proves its
      assembled length — the `_pack_inode` motivation from `07-1321-req.md`.
- [ ] **[typecheck + byte-diff]** Full pycsl-reference sweep clean; before/after WhyML byte-diff
      reviewed — only concatenating files (and refs promoted per P2.1) change.

## P3 — `array + array` expression form (LOW; near-free once P2 lands)

### Requirements
- **P3.1** The binary `a + b` on two array operands lowers to `materialize (snapshot a ++ snapshot
  b)` in expression position (e.g. `return a + b`). This is the **same composition as P2 without the
  rebind**, so it is nearly free once P2 lands — it is a separate *test*, not separate machinery.
- **P3.2** Land it on the first real driver that returns/uses a concat expression; until then it is
  inert (the arm exists, exercised by no driver).

### Acceptance (on the first driver)
- [ ] **[PROVE]** `return a + b` proves the length-additive postcondition.
- [ ] **[PROVE]** Element placement on the expression form (mirrors P2).

## Cross-cutting & risks

- **Aliasing-free by construction (corrected).** All composition is over immutable `seq int`; the
  only mutable values are the operand arrays (read via pre-rebind immutable `snapshot`s — operand
  self-aliasing is therefore sound, §2.4) and the fresh `materialize` result. No two-mutable-argument
  val ⇒ no "illegal alias." The freshness of `materialize`'s result is a stated requirement proved by
  P0 (§2.1), not an implicit assumption.
- **Import ordering — resolved.** Seq ops are emitted qualified (`Seq.length`/`Seq.get`/`Seq.(++)`),
  so they never compete with the array/map `([])`. Keep `array.Array` last for the unqualified array
  `[]`. A three-theory driver that indexes an `array int`, a `map`, and a `seq int` *in one function*
  locks the resolution.
- **Ref promotion — the real byte-diff source.** P2.1's ref-wrapping of a previously non-ref `+=`
  target changes how subsequent reads of that variable lower; this is the expected (and only
  expected) byte-diff beyond the concatenation sites themselves, and the gate must confirm no *other*
  files move.
- **Performance.** `snapshot`/`materialize` are abstract vals (no executable cost in proof); they
  carry only the faithful logic facts.
- **Generalisation (out of scope here).** The same bridge could later model other list producers
  (`list(x)`, slicing as seq, repetition `[v]*n`); this spec is concat-only.

## Gating & processing
**probe → reproduce → fix → gate**, order **P0 → P1 → P2**, P3 only on a driver:
1. **P0** hand-written WhyML proves the freshness-rebind and self-concat patterns; if it fails, the
   design is revisited before any emitter change.
2. **P1** bridge vals (qualified seq, fresh `materialize`) + round-trip driver; confirm
   byte-identical for non-seq files.
3. **P2** lowering with committed ref-wrapping; **upgrade driver `0619`** to a proven length law;
   add element-placement, self-concat, loop-update, and byte-packing drivers; remove the opaque
   `array_extend` arm.
4. Gate each: full `--pycsl` sweep (clean), WhyML byte-diff (only concatenating files + promoted refs
   change), traceability row, and update `07-1321-spec.md` S4 (mark the follow-on closed).

**Out of scope:** `pure_lib/` edits; a full `seq int` list model (lists stay `array int`, snapshot
only at concat); multi-byte literal tiling; the expression form P3 unless a driver appears.
