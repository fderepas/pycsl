## Context

`english-01.md` (164 lines) describes `_handle_assign_stmt` in three
behavioural branches:

1. **Shared module-level variable** — emit `target := val` (no `let`).
2. **Fresh local** — emit `let target = … in` with sub-cases for
   record / lambda / array / slice / dict / bounded-int / bool /
   plain-int. Booleans get coerced via `(if val then 1 else 0)`.
3. **Existing local** — emit `target := val` with the same bool
   coercion as the fresh-local branch.

The English text closes with: *"its soundness is captured by the `wp`
fixpoint's `SAssign` arm (`Phase4_WP.v` line 42)"*. The companion
lemma `wp_gen_assign` already exists in
`src/formal-semantics/rocq/Phase6e_Corr_Simple.v` (line 28):

```coq
Lemma wp_gen_assign :
  forall x e Qn Qr Qc Qb Qe pre_es es,
  wp (SAssign x e) Qn Qr Qc Qb Qe pre_es es <->
  wp_w (gen (SAssign x e)) (enc Qn Qr Qc Qb Qe) pre_es es.
Proof. intros. simpl. tauto. Qed.
```

The 1-line proof works because the Coq `gen` function abstracts over
the Python implementation choices: `gen (SAssign x e) = WAssign x e`
regardless of which Python branch fires
(`src/formal-semantics/rocq/Phase6d_StmtGen.v` line 39). The three
branches are Python-side surface-syntax choices (`let … in` vs `:=`,
bool coercion, special record/dict tracking) that converge on the
same semantic `WAssign x e` term.

**Intended outcome**: a new Rocq file
`src/formal-semantics/rocq/Phase6e_HandleAssignEnglish.v` that:

1. Cites `english-01.md` in its header.
2. Defines a Coq dispatcher mirroring the three Python branches
   (`branch_shared`, `branch_fresh`, `branch_existing`).
3. Proves each branch's emitted WhyML satisfies the SAssign WP, by
   reduction to the existing `wp_gen_assign`.
4. Composes them into a single umbrella theorem
   `handle_assign_branches_correct` that quantifies over the branch
   choice.
5. Compiles cleanly under Coq 8.20.1 with no `Admitted.`.

## Recommended approach

Four steps. Steps 1–2 are mechanical (read + design); step 3 writes
the proof; step 4 wires it into the build.

### Step 1 — Read `english-01.md` and extract the formal vocabulary

The English spec talks about Python implementation details
(`safe_target`, `declared_refs`, `_shared_var_names`,
`_record_locals`, etc.) that don't have Coq counterparts. Strip away
that noise and isolate the *semantic* content:

- The three-branch dispatch keyed on (a) is target a shared var, (b)
  is target already in `declared_refs`.
- The value type matters only for syntactic choices (`let … in` vs
  `ref`) — semantically all values get bound to the target via the
  same `WAssign x e`.
- Bool-to-int coercion `(if val then 1 else 0)` is semantically
  invisible at the WP level (Why3 coerces booleans the same way the
  Coq model does implicitly).

Output of this step: a 3-line abstract semantic spec — "an assign is
an assign, regardless of which branch fired."

### Step 2 — Design `Phase6e_HandleAssignEnglish.v`

Sketch (≤120 lines):

```coq
(* Phase6e_HandleAssignEnglish.v — Rocq refinement of english-01.md
 *
 * The English specification describes three Python-side branches for
 * `_handle_assign_stmt` (shared var, fresh local, existing local). At
 * the WhyML-IR level they all produce the same `WAssign x e`. This
 * file documents the branch decomposition as Coq dispatchers and
 * shows that each dispatcher case satisfies the SAssign WP claim
 * already proved as `wp_gen_assign` in Phase6e_Corr_Simple.v. *)

Require Import ZArith String List Bool.
Require Import Phase1_AST Phase2_State Phase4_WP.
Require Import Phase6_WhyML Phase6b_WPW Phase6d_StmtGen.
Require Import Phase6e_Corr_Simple.

(* The Python-side branch choice, modelled as a 3-arm dispatch *)
Inductive assign_branch : Type :=
  | BrShared       (* target ∈ _shared_var_names               *)
  | BrFresh        (* target ∉ declared_refs                   *)
  | BrExisting.    (* target ∈ declared_refs ∖ _shared_var_names *)

(* The Coq counterpart of `_handle_assign_stmt`'s output, parametrised
   over the branch. All three arms collapse to `WAssign x e` because
   the Python `let … in` / `ref` / bool-coerce choices are
   syntax-only and the Coq model abstracts over them. *)
Definition gen_assign_by_branch
    (b : assign_branch) (x : ident) (e : expr) : whyml_stmt :=
  match b with
  | BrShared   => WAssign x e
  | BrFresh    => WAssign x e
  | BrExisting => WAssign x e
  end.

(* Sanity: regardless of branch, the dispatcher equals `gen (SAssign x e)`. *)
Lemma gen_assign_by_branch_eq_gen :
  forall b x e, gen_assign_by_branch b x e = gen (SAssign x e).
Proof. intros [|||]; reflexivity. Qed.

(* Per-branch WP correctness: each Python branch's emitted WhyML
   satisfies the same SAssign WP equivalence as the umbrella
   `wp_gen_assign`. *)
Lemma wp_branch_shared :
  forall x e Qn Qr Qc Qb Qe pre_es es,
  wp (SAssign x e) Qn Qr Qc Qb Qe pre_es es <->
  wp_w (gen_assign_by_branch BrShared x e) (enc Qn Qr Qc Qb Qe) pre_es es.
Proof. intros. rewrite gen_assign_by_branch_eq_gen. apply wp_gen_assign. Qed.

Lemma wp_branch_fresh :
  forall x e Qn Qr Qc Qb Qe pre_es es,
  wp (SAssign x e) Qn Qr Qc Qb Qe pre_es es <->
  wp_w (gen_assign_by_branch BrFresh x e) (enc Qn Qr Qc Qb Qe) pre_es es.
Proof. intros. rewrite gen_assign_by_branch_eq_gen. apply wp_gen_assign. Qed.

Lemma wp_branch_existing :
  forall x e Qn Qr Qc Qb Qe pre_es es,
  wp (SAssign x e) Qn Qr Qc Qb Qe pre_es es <->
  wp_w (gen_assign_by_branch BrExisting x e) (enc Qn Qr Qc Qb Qe) pre_es es.
Proof. intros. rewrite gen_assign_by_branch_eq_gen. apply wp_gen_assign. Qed.

(* Umbrella: the Python `_handle_assign_stmt` is sound for any branch
   choice made by the type-driven dispatch logic in english-01.md. *)
Theorem handle_assign_branches_correct :
  forall b x e Qn Qr Qc Qb Qe pre_es es,
  wp (SAssign x e) Qn Qr Qc Qb Qe pre_es es <->
  wp_w (gen_assign_by_branch b x e) (enc Qn Qr Qc Qb Qe) pre_es es.
Proof. intros [|||]; [apply wp_branch_shared | apply wp_branch_fresh | apply wp_branch_existing]. Qed.
```

The file is intentionally short: the heavy lifting is in
`wp_gen_assign` (1 line, `tauto.`). The new file's contribution is
the **documentation** that all three Python branches preserve
semantic correctness, with a Coq-level enumeration of the branch
choice mirroring the English text's structure.

## Risks and scope cuts

- **Semantic triviality.** All three branches collapse to the same
  `WAssign x e` at the IR level — the Coq dispatcher's three arms
  are textually identical. This is **intentional**: it documents
  that the Python branches are surface-syntax choices that don't
  affect WP soundness. Readers might find the symmetry suspicious;
  the file's header comment must explain this explicitly so they
  don't think the proof is "cheating".
- **No Lean parity.** Lean has the matching infrastructure
  (`Soundness.lean`, `CorrSimple.lean`) but a parallel file would
  duplicate the Coq one. **Mitigation**: document this in
  `module6-mapping.md` as a follow-up; the Module6 `#@ proof lean:`
  directive on `_handle_assign_stmt` keeps citing `wp` (the
  umbrella) rather than the new theorem.
- **English drift.** If `_handle_assign_stmt` gains a fourth branch
  (e.g. async-handling), `english-01.md` and the new Coq file fall
  out of sync. **Mitigation**: the cross-link footer (Step 4)
  signposts the dependency; future edits to one should prompt edits
  to the other.
- **Bool-coercion claim is informal.** The English spec asserts
  bool-coerced `(if val then 1 else 0)` is semantically equivalent
  to the un-coerced form. This holds because Why3's type system
  silently does the same coercion, but the Coq file doesn't
  *prove* it — it relies on the abstraction that `gen` ignores
  syntactic representation. **Mitigation**: documented in the new
  file's header; a stronger proof would require modelling Why3
  type-coercion in Coq, which is far out of scope.
