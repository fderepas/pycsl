# 07-1705-spec-rev4 — Faithful growable lists via a `seq`-typed value model (Creusot-style)

**Status:** Draft (generic specification — intent and gated phasing, not implementation)
**Date:** 2026-06-07
**Source:** `07-1732-findings.md` — the P0 gate killed the `array int` rebind mechanism (rev1–3) and
proved the `ref (seq int)` route. This rev specifies the *different, larger* design the findings
called for.
**Supersedes:** the array-snapshot mechanism of rev1–3 (snapshot/materialize survive only as a
**boundary bridge**, §5, not as the whole mechanism).
**Scope:** the **PyCSL tool only** (`src/pycsl`, WhyML emitter + a promotion analysis).
`pure_lib/` is not edited here.
**Doctrine:** no-more-int / EXTREME RIGOR — model faithfully or defer with an honest reason. Legacy
emission stays **byte-identical** for every file with no growable list (the regression gate).

---

## 1. What P0 settled (the mandate)

`07-1732` proved, in hand-written WhyML:

- **#8 (decisive):** `let a = ref arr in a := Array.make 5 0` is **rejected** — Why3 forbids
  reassigning a `ref` that holds a *mutable, regioned* `array int` to a different such value, even
  one sharing nothing. The failure is at the `:=`, independent of the right-hand side. So **no**
  snapshot/materialize/copy machinery around an `array int` variable can ever work.
- **#9 (the route):** `let a = ref s0 in a := !a ++ t` over `seq int` **type-checks and proves** —
  length-additive, seam placement, and self-concat all discharge in milliseconds. `seq int` is
  *immutable* → region-free → a `ref (seq int)` reassigns like a `ref int`.
- **#3/#4:** a function returning a fresh array is fine **when bound to a fresh local/ref** (just not
  rebound into the operand's own regioned ref). This is what keeps the boundary bridge (§5) legal.
- **#6:** logic `function`s can't be applied in executable code — the "make snapshot pure" escape is
  closed.

**Mandate:** a list variable that must grow is modelled as **`seq int`**, not `array int`.

## 2. Architecture (Creusot-inspired)

Creusot verifies a *growable, mutable* `Vec<T>` by separating two things: the **mutable container**
(`Vec`, whose reallocation Rust owns and the borrow checker proves alias-free) and the **immutable
mathematical value** (`Seq<T>`, the logical `view`), related by the contract, with a **prophecy**
`^v` to talk about a mutable borrow's final value. PyCSL adopts the same *split*, adjusted for what
it has and lacks:

| Creusot | PyCSL rev4 |
|---|---|
| `Seq<T>` (immutable logical view) | **`seq int`** (Why3 `seq.Seq`) — the value the proofs reason about |
| `Vec<T>` (host-owned mutable, growable container) | **PyCSL has none** → replaced by a **region-free `ref (seq int)`** (the #9 route): rebinding *is* the mutation |
| prophecy `^v` (final value of `&mut`) | **not needed** — a `ref (seq int)` is region-free, so Why3 reasons about its before/after directly; no prophetic encoding required |
| `v@.push(x)` in the contract | `!a := !a ++ snapshot(b)` (concat) / `Seq.snoc !a x` (append) — ordinary rebind |

So the value is the immutable `Seq`; the "mutable container" PyCSL doesn't have is replaced by a
region-free ref whose reassignment Why3 already blesses. **The prophetic *contract style*** — specify
a mutating helper by relating the incoming `!r` to the outgoing `!r` — is borrowed as an idiom for
§5.2, but it needs no `^` operator and no new machinery, because a `ref (seq int)` argument's
pre/post values are directly expressible.

### 2.1 Two representations, one per variable

PyCSL now has two list representations; each list variable has **one** for its whole lifetime in a
function:

- **`array int`** (unchanged default): mutable, fixed-length, region-bearing. Required for in-place
  element mutation at scale, 2-D arrays, `\valid`, fixed-size buffers, aliasing.
- **`seq int`** (new): immutable value in a region-free ref. Required for growth (concat now;
  append/extend as the same mechanism, §3.3). Free rebinding; pure length/index/concat/update axioms.

A boundary bridge (§5) converts between them where they meet.

## 3. Scope by need — the seq-promotion analysis

### 3.1 Which variables become `seq int`
A whole-function analysis (sibling of the existing array1d / `+=`-target detection) marks a list
local/param as **seq-modelled** iff it is *ever grown* — primary scope: it is the target of `+=`
with a list RHS, or it is produced by a `+` on lists. Everything else stays `array int`.

### 3.2 Propagation (unification)
Representation must be consistent across data flow, so the mark propagates:
- `b = a` (alias/assign) ⇒ `b` takes `a`'s representation.
- `a` passed to `f(x)` ⇒ either `x` is seq-modelled too, or the bridge fires at the call (§5).
- a function returning a grown list ⇒ its return is seq-modelled.
This is a small constraint-propagation pass over a two-point lattice {array, seq}; concat/growth
forces `seq`, and the mark flows along assignments, calls, and returns.

### 3.3 Append/extend — same mechanism, gated on a driver
`a.append(x)` ≡ `a := Seq.snoc !a x` and `a.extend(b)` ≡ `a := !a ++ snapshot(b)` are the *identical*
region-free rebind as concat — near-free once the seq model lands. Primary scope here is **concat**
(matching the proven P0); append/extend land on the first driver that needs them (YAGNI, but no new
design).

## 4. Operation lowering on a seq-modelled variable

Seq operations are emitted **qualified** (`Seq.…`) so they never compete with the `array.Array` /
`map.Map` mixfix `[]`/`length` (the import-ordering resolution carried over from rev2).

| Python | WhyML (a is `ref (seq int)`) |
|---|---|
| `a = []` | `let a = ref Seq.empty in` |
| `a = [v0, v1, …]` | `let a = ref (Seq.cons v0 (Seq.cons v1 … Seq.empty)) in` (cons/snoc chain) |
| `len(a)` | `Seq.length !a` |
| `a[i]` (read) | `Seq.get !a i` |
| `a[i] = v` (write) | `a := Seq.set !a i v` (functional update + rebind — region-free, #9-legal) |
| `a += b` | `a := !a ++ snapshot(b)` (if `b` seq-modelled: `a := !a ++ !b`) |
| `a + b` (expr) | `!a ++ snapshot(b)` as a seq value (materialised only if it crosses to array code, §5) |
| iterate / `in` | over `!a` via `Seq.get`/`Seq.length` |

The faithful facts (`Seq.length (s ++ t) = Seq.length s + Seq.length t`, indexing, `Seq.set`
update law) come from the standard `seq.Seq` theory — exactly the goals P0 #9 discharged.

## 5. The boundary bridge (`array int` ↔ `seq int`)

Where a seq-modelled value meets `array int`-modelled code (a callee taking `array int`, a 2-D or
`\valid` context, a return whose declared representation differs), one of two bridges fires:

```whyml
val snapshot   (a: array int) : seq int    (* array → seq; one mutable arg, legal *)
  ensures { Seq.length result = Array.length a }
  ensures { forall i. 0 <= i < Array.length a -> Seq.get result i = a[i] }

val materialize (s: seq int) : array int    (* seq → array; result is FRESH, bound to a fresh local *)
  ensures { Array.length result = Seq.length s }
  ensures { forall i. 0 <= i < Seq.length s -> result[i] = Seq.get s i }
```

### 5.1 When each fires, and why it is legal
- **`snapshot`** at an array-modelled value entering a seq context (e.g. the RHS `b` of `a += b`
  when `b` is array-modelled). One mutable argument ⇒ no two-mutable-arg alias problem.
- **`materialize`** at a seq-modelled value entering array code — and its result is bound to a
  **fresh** local/parameter for the callee (#3/#4-legal), **never** rebound into a pre-existing
  regioned ref (#8-illegal). This legality boundary is load-bearing and must be enforced by the
  emitter.

### 5.2 Mutate-by-ref helpers (the prophetic *style*, no prophecy)
A helper that grows a seq-modelled argument takes a `ref (seq int)` and is specified by relating the
incoming to the outgoing seq:

```whyml
let extend_in_place (r: ref (seq int)) (t: seq int) : unit
  ensures { !r = (old !r) ++ t }      (* before/after of a region-free ref — no ^ needed *)
= r := !r ++ t
```

This is Creusot's contract idiom (pre/post of a borrowed value) realised with a plain region-free
ref — Why3 expresses `old !r` directly, so **no prophecy infrastructure is built**.

## 6. Soundness and honest costs

**Provable (the win):** length-additive concat, element placement at the seam, functional-update
correctness, self-concat — all discharge (P0 #9 anchors this).

**Costs, stated plainly (model/representation gaps, in the style of the bitvector/float specs):**
- **No O(1) in-place write.** Every `a[i] = v` on a seq-modelled var is a functional `Seq.set` +
  rebind — sound and provable, but the *cost model* of a seq-modelled variable is logical functional
  update, not in-place mutation. Variables with heavy element-write loops and no growth should stay
  `array int` (the analysis keeps them there).
- **No `\valid` / 2-D / aliasing for seq.** `seq int` is region-free, so it cannot participate in
  2-D array contexts, `\valid` reasoning, or be aliased into. A list that needs *both* growth and a
  2-D/`\valid` context is a **conflict** (§7).
- **A new boundary surface.** The `snapshot`/`materialize` bridge (§5) is the new place where the two
  models meet; its legality rule (§5.1) is a soundness obligation the emitter enforces.

**Fail-safe property (important).** Both ways the promotion analysis can be wrong are *safe*:
- *Under-promotion* (a growable var left as `array int`) ⇒ a forbidden `ref (array int)` rebind ⇒
  **Why3 compile error**, loud and located — never silent unsoundness.
- *Over-promotion* (a non-growable var made seq) ⇒ pays the functional-update cost but stays sound.
There is no analysis bug that yields a *wrong proof*; the worst outcomes are a compile error or a
cost regression. This is the same "fail loud, never silently" discipline the project applies to
`--no-proof`.

## 7. Representation conflicts (a diagnostic, not a silent bridge)

A list that the analysis must mark **both** seq (it is concatenated) **and** array (it is used in a
2-D/`\valid`/aliased context) cannot be bridged mid-function — that would require materialising into
a pre-existing regioned ref (#8-illegal). Such a variable is rejected with a clear diagnostic
("list `x` is both concatenated and used in a 2-D/`\valid` context; split it or copy at the
boundary"), rather than emitting something that won't compile. Fail-safe, §6.

## 8. Phasing & gating

Reuse `07-1732`'s P0 artifact as the feasibility anchor (already proven). Order **P1 → P5**; each
phase: full `--pycsl` sweep clean, WhyML byte-diff (only seq-promoted files change), `[typecheck]`
vs `[PROVE]` stated per box.

| Phase | Delivers | Key acceptance |
|---|---|---|
| **P1 — seq vocabulary** | qualified `Seq.empty/cons/snoc/get/set/length/(++)` in preamble behind `needs_seq` | **[PROVE]** round-trip + #9 concat driver; **[byte-diff]** non-seq files identical |
| **P2 — promotion analysis** | mark seq-modelled vars (concat scope) + propagation (§3); diagnostics only, no emission change | **[review]** marks match expectation on a corpus sample; conflicts (§7) reported |
| **P3 — lower seq locals** | init/len/read/write/concat for seq-modelled **locals** (§4) | **[PROVE]** length law (`0619` upgraded), seam placement, `Seq.set` write, self-concat `a += a`, loop-update |
| **P4 — boundary bridge** | `snapshot`/`materialize` at call/return/2-D boundaries (§5), legality rule enforced | **[PROVE]** cross-model driver (seq local passed to an array callee and back); **[typecheck]** illegal materialise-into-regioned-ref is rejected |
| **P5 — params/returns + helpers** | seq-modelled params/returns; mutate-by-ref helper idiom (§5.2); **remove** the opaque `array_extend` concat arm | **[PROVE]** `extend_in_place` before/after; byte-packing shape proves assembled length; **[byte-diff]** only seq files change |

Until P5 lands, **`array_extend` stays** on `main` — type-correct and honest about its opacity.
