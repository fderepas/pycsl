# PyCSL Tool Gaps — `pure_lib/re` Engine Body Verification

**Date:** 2025-06-07
**Context:** Annotating `pure_lib/re/_engine.py` and attempting body-level proof.
**Status:** Stub-based formal test passes (16/16 VCs), but direct body verification
of `_engine.py` is blocked by multiple PyCSL tool gaps.

---

## R8 — `match` is a Why3 reserved keyword

**Symptom:** `type match = { ... }` in generated WhyML causes a syntax error.

**Root cause:** PyCSL lowercases Python class names to form Why3 type names.
`Match` → `match`, which collides with Why3's pattern-matching keyword.

**Workaround:** Rename the Python class to `ReMatch`.
Same issue affects `Pattern` (see R9).

**Fix:** PyCSL should detect Why3 reserved words (`match`, `end`, `begin`, `let`,
`in`, `if`, `then`, `else`, `with`, `try`, `val`, `type`, `use`, `module`, etc.)
and append a suffix (e.g., `match_` or `py_match`).

---

## R9 — `isinstance` check emits a `val constant` that collides with the type name

**Symptom:** `isinstance(x, Pattern)` generates `val constant pattern : int`
which clashes with `type pattern = { ... }` (the record type for the same class).

**Root cause:** PyCSL emits a module-level `val constant` for the class reference
used in `isinstance`, using the same lowercased name as the record type.

**Workaround:** Rename `Pattern` → `RePattern` so that `type repattern` and
`val constant repattern` don't collide with anything.

**Fix:** PyCSL should namespace the isinstance constant differently, e.g.,
`val constant _isinstance_pattern : int`.

---

## R10 — Missing `use string.String` import for `in` operator on strings

**Symptom:** `str_contains_op` formula references `String.length` and
`String.substring`, but the generated WhyML has no `use string.String` import.

**Root cause:** PyCSL emits a specification for the `in` operator on strings
that uses the Why3 `string.String` theory, but doesn't add the corresponding
`use` declaration to the preamble.

**Workaround:** None available at source level. Manual `.mlw` patching possible
but not sustainable.

**Fix:** When PyCSL detects a string `in` operation, it should emit
`use string.String` in the module preamble.

---

## R11 — `self` parameter missing from method bodies

**Symptom:** `_ColorMatch.group()` body references `self._groups` but `self`
is not in the function signature. Error: `unbound function or predicate symbol 'self'`.

**Root cause:** When PyCSL extracts a method body into a module-level `let`
function, it sometimes omits `self` from the parameter list. Observed for
`_color_match_group`.

**Workaround:** None at source level.

**Fix:** PyCSL method-to-function extraction must always include `self` as the
first parameter for instance methods.

---

## R12 — `isdigit()` loses its receiver in WhyML

**Symptom:** `s[i].isdigit()` becomes `isdigit_0 ()` — a nullary abstract
function with no argument, so it has no connection to the character being tested.

**Root cause:** PyCSL's method-call lowering doesn't handle chained
attribute-then-method patterns like `expr[i].method()`. The receiver
`s[i]` (a `subscript_get` result) is dropped.

**Workaround:** None at source level. Could replace with explicit ord-range
checks, but that changes the Python semantics.

**Fix:** PyCSL should emit `isdigit_0 (subscript_get s !i)` — passing the
receiver as the first argument.

---

## R13 — Class-returning functions have type mismatch

**Symptom:** `_match_whitespace` is declared `let ... : int` but its body
does `raise (Return { py_rematch__string = s; ... })` — returning a record
where an `int` is expected.

**Root cause:** PyCSL models all return types as `int`, but when a function
returns a class instance, the body constructs a record literal. The Why3
type system rejects this mismatch.

**Workaround:** Verify through stubs only (formal test imports through
`__init__.py`, where functions are `val` declarations with `int` return type).

**Fix:** PyCSL needs a representation strategy for class instances:
either box records into integers (with an allocation model), or use a
union/variant return type.

## Summary

| ID  | Gap                                  | Severity | Workaround available? |
|-----|--------------------------------------|----------|-----------------------|
| R8  | `match` is a Why3 keyword            | Medium   | Yes — rename class    |
| R9  | isinstance constant name collision   | Medium   | Yes — rename class    |
| R10 | Missing `use string.String`          | High     | No                    |
| R11 | `self` omitted from method body      | High     | No                    |
| R12 | `isdigit()` drops its receiver       | High     | No                    |
| R13 | Class-return type mismatch           | Critical | Partial — stubs only  |

R8–R9 are naming issues with easy workarounds. R10–R13 are fundamental
code-generation gaps that prevent body-level verification of any module
that uses string operations, method chaining, or class-returning functions.

**Current state:** Stub contracts (16/16 VCs via `formal_0002.py`) provide
useful guarantees at the call-site level. Body-level verification awaits
fixes to R10–R13 in the PyCSL tool.
