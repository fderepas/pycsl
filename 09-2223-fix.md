# 09-2223-fix.md — requested fixes to the composition-wall plan

*Review of `09-2223-plan.md` (2026-07-09), the SOTA-informed answer to the step-back brief `09-2223.md`.
The plan is the strongest of the value-model-wall attempts: its reframe (a frame-only VC needs type-flow
and frame, not value invariants) is a real advance, and "parse, don't validate" (M2 — exit the reflective
world once through a certified decoder) is the right move that directly dissolves the cast-composition
pathology the brief named. This document lists what it needs before commitment, ranked, each as
**CHANGE / WHY / HOW**, then the doubts I cannot resolve on paper, then an **extended S-dec spec** (the
spike must test more than the plan scopes it to). Section refs are to `09-2223-plan.md` unless noted
"brief" (= `09-2223.md`) or "plan-2" (= `value-model-wall-stand-alone-plan-2.md`).*

**One-line verdict.** Greenlight the spike — but the plan's two load-bearing claims (M2 is certificate-free;
M2 dissolves the composition) are **asserted, not shown**, and M3's premise looks wrong for Why3's effect
system. Fix the scope of S-dec so it actually falsifies these, and demote M3 to its own separately-gated
premise-check. M1 + M2 are the real plan; M3 may be a non-problem.

## Required changes (ranked)

### C1 — M2's "no new value shape / ledger-3 / T1 instance" is a hypothesis; the spike must settle it (BLOCKER)

**CHANGE.** §3 and the §0 solution map state the decoder `decode_func : pyval → option ir_func` introduces
**no new value shape** and holds the ledger at 3 "with no new certificate," calling it "a T1 instance of the
certified functorial-map family." Demote this to a hypothesis that **S-dec confirms with an axiom audit**;
do not build M2 downstream on the assumption.

**WHY.** The certified T1 family (from `ir-traversal-residual-stand-alone-plan.md`) is *reconstruction*
`pyval → pyval` — same codomain as the domain. `decode_func` has a **new record codomain** (`ir_func`) and a
mutually-recursive `option`-of-record producer. That is a *different* algebra: a recursive function
*eliminating* `pyval` into a fresh typed shape, not an endofunctor on `pyval`. The S1 result (a record over
already-certified fields is certified by construction) covers the *record type* but not obviously the
*recursive decoder that builds option-of-record from pyval*. The coupling rule (plan-2 §10.5 / brief §1)
is explicit: a new value shape co-lands an axiom-free certificate. Asserting "ledger 3" here is exactly the
kind of un-audited claim the campaign's discipline forbids.

**HOW.** In S-dec, after the decoder type-checks and proves, run the ledger audit: `git diff HEAD --
src/formal-semantics '**/proof_axiom_allowlist.py'` empty **and** `Print Assumptions` (Rocq) / `#print
axioms` (Lean) clean. State two branches: (a) the decoder is covered by an existing certified generator ⇒
no new certificate (confirm which generator, by name); (b) it is a new eliminator ⇒ co-land its axiom-free
certificate (state the proposition: `decode_func` total + `PV.size`-decreasing + sound-on-well-formed).
Either is fine — but it must be **measured**, and the §0 map / §9 brief must not pre-claim (a).

### C2 — The type-clash may MOVE to the sibling call; S-dec as scoped won't catch it (BLOCKER)

**CHANGE.** §2's S-dec build says "lower B-comp's **first statement** through [the decoder]; leave the rest
of the body as-is." That proves the *decode* type-checks — not that the boundary dissolves the composition.
Extend S-dec to run **through the first sibling consumer** (`_collect_calls(f.get("body", []))`).

**WHY.** M2's whole thesis (§3: "sibling calls receive the ADT they already expect") holds **only if** the
decoder's field types are *exactly* what the existing siblings consume. `_collect_calls` is a GenericFold
A-set sibling whose mirror parameter has a concrete WhyML type (in this codebase stmt-lists are opaque
`array int` via `stmts_of`, distinct from `array emit_ir`). `_expr_to_whyml` consumes `emit_ir`. If
`fn_body` / `fn_ensures` don't match those types, the clash the census found (`pyval`/typed mismatch) simply
**reappears at the sibling boundary** instead of at the read — the composition is not dissolved, only
relocated. A spike that stops after the decode would show green and mislead the whole build.

**HOW.** S-dec lowers B-comp through at least: `funcs = decode_func_list(...)`, the `for f in funcs` loop,
`f["name"]`/`f.get("trusted")` accessors, **and** `deps = _collect_calls(f.get("body", [])) & trusted_names`.
Report the first surviving blocker. Specify in §3 the exact WhyML type `fn_body` must have to satisfy
`_collect_calls` (read the mirror signature first) and make the decoder produce *that* type.

### C3 — M3's premise contradicts Why3's effect inference; validate before building (BLOCKER for M3 only)

**CHANGE.** §4 / §1 assert "without per-loop preservation invariants, the frame half of the VC dies inside
any iteration." Treat this as an unverified premise and **check it first**; do not emit ~90-field
invariants until confirmed.

**WHY.** WhyML **infers** a loop's write effect from the mutations in its body — there is no `loop assigns`
in Why3; the function's `writes`/frame is checked against the *inferred* union of all mutations, loops
included. Under `ensures True / assigns F`, the frame obligation is "inferred-writes ⊆ F," discharged by the
effect system **without** any synthesized loop invariant. So the frame does not "die in a loop." M3 may be
solving a problem Why3 doesn't have (or a *different* problem — carrying a record/type invariant across
iterations, which is not "frame preservation"). Emitting a `self.c = old self.c` invariant per unwritten
field per loop, ×90 fields, is a large VC-bloat cost to pay for an unconfirmed need — and `old` in a Why3
loop invariant refers to *function* pre-state, not loop-entry, so the annotation as written may not even
mean what §4 intends.

**HOW.** Before building M3: take one self-state-mutating reflective method with a loop, port it, and check
whether the **frame** VC fails for a reason effect-inference doesn't already cover. If it discharges without
M3 → drop M3. If it fails → capture the *exact* Why3 error and confirm it is a frame (not a typing) failure,
and that a loop-entry-labelled invariant (not `old`) is the fix. Only then build M3.

### C4 — S-dec gates M2 but NOT M3 (B-comp has no self-state); add M3's own benchmark (MAJOR)

**CHANGE.** The order `M1 → S-dec → M2 → M3` implies S-dec de-risks the path to M3. It does not.
`_build_soundness_report` is a **module-level function** (`def _build_soundness_report(ir_data, filename)` —
no `self`); its loops mutate **local** accumulators (`counts`, `vcs`), so its frame is trivial and it never
exercises M3. Add an explicit M3 benchmark (a self-state-mutating reflective method) and gate M3 on it.

**WHY.** The §5 discharge table lists a row "loop over self-state → M3" for B-comp, but B-comp has no
self-state loop — that row is spurious. So a green S-dec/B-comp says nothing about M3, yet the plan sequences
M3 right after. Building M3 on a benchmark that can't test it is the plan-2 C4 error (assert-don't-measure)
in a new dress.

**HOW.** Name a second benchmark **B-frame** = a `\trusted` reflective *method* (has `self`) that mutates
self-state inside a loop; M3 is "cleared" ⟺ B-frame proves whole-body after M3 (same acceptance battery).
Remove the M3 row from B-comp's table (or mark it N/A).

### C5 — B-null's magnitude is unmeasured (MODERATE)

**CHANGE.** §6 narrows B-null to three named sub-classes but gives no counts. Add a census of the residual,
especially **"non-IR-shaped reflective dicts"** (no ADT codomain to decode into).

**WHY.** VALUE-not-count (plan-2 §8 / SKILL §10.7): the plan's payoff is "a substantial fraction of the
70-method class," but if the non-IR-shaped residual is large, M2's reach is small — the decoder needs a
*typed codomain*, and methods reflecting on arbitrary dynamic data have none. The narrowing is honest; its
size decides whether M1+M2 is a big win or a small one.

**HOW.** After S-dec confirms the boundary architecture, classify the 70 census methods by "has an
IR-node-ADT decode target" vs not; report the split. This is the honest yield denominator.

### C6 — Specify the decoder codomain against the ACTUAL sibling/accessor types (MODERATE)

**CHANGE.** §3's `ir_func` record (`fn_name/fn_trusted/fn_abstract/fn_ensures/fn_body`) is written abstractly.
Pin each field's WhyML type to what the real mirror consumes, before the spike.

**WHY.** `fn_ensures = decode_ensures(slookup "contracts" d)` and `fn_body = decode_body(slookup "body" d)`
are hand-waved. `contracts.ensures` is itself a nested heterogeneous structure (a list of clause dicts);
`body` is a stmt-list the sibling treats as opaque `array int`. If `decode_ensures`/`decode_body` are
themselves unbounded reflective decodes, M2 has recursed the problem, not closed it. The decoder must bottom
out in **already-consumed types** (opaque `array int` body, a bounded ensures encoding), or it inherits the
nested-heterogeneity wall.

**HOW.** Specify `decode_body : option pyval → array int` (opaque, content-dropped — sound under the
contract) and state exactly what `decode_ensures` returns and whether any consumer needs its content. If a
consumer needs ensures *content*, that is a distinct blocker to name now.

## My doubts (settle by measurement, not argument)

1. **Does the boundary actually collapse the composition, or relocate the clash?** (C2.) My real fear:
   `_collect_calls`, `_expr_to_whyml`, and the `counts[bucket] += 1` option-map update each want a *specific*
   type, and the decoder can satisfy at most the ones whose type it already knows. If even one consumer wants
   a shape the decoder can't produce from `pyval` without *another* decode, M2 is a partial move and the
   composition survives in the tail. Only a through-the-chain spike (not a first-statement spike) tells.
2. **Is `decode_func` certificate-free?** (C1.) I lean "a record over certified fields needs none," but a
   recursive `pyval`-eliminator into option-of-record is past what S1 measured; I can't rule out a
   co-landing obligation. The axiom audit is the only arbiter.
3. **Is M3 needed at all?** (C3.) I believe Why3's effect inference discharges the frame without synthesized
   loop invariants under `ensures True`, making M3 a non-problem *for the frame*. If M3 is really needed, it
   is for a type/record-typing invariant across iterations — a *different* justification than §4 gives, and
   one that should be stated correctly (loop-entry label, not `old`).
4. **Nested `contracts.ensures`.** (C6.) If any surviving consumer needs the *content* of the decoded
   ensures/body (not just its opaque presence), the nested-heterogeneity wall is inside `decode_ensures`,
   and M2 has not escaped it — it has renamed it. The decoder must provably bottom out in already-consumed
   opaque types.
5. **Yield denominator.** (C5.) "Substantial fraction of 70" is unfalsifiable until the IR-shaped vs
   non-IR-shaped split is measured; the non-IR-shaped class is M2-inaccessible by construction.

## Appendix — the extended S-dec spec (supersedes §2's scope)

S-dec is the plan's falsifier; scope it to actually falsify M1+M2 (M3 gets its own B-frame per C4):

1. **M1 first:** a spike `.mlw` hosting BOTH the `pyval` theory (qualified `PV.` or renamed `pv_size`) and
   the IR-node ADT type-checks; empty VCs run; ledger audit clean. (If M1 fails, the whole plan is blocked —
   report and stop.)
2. **Decoder + through-the-chain lowering of B-comp:** build `decode_func`/`decode_func_list` for only the
   touched fields with `fn_body : <the exact type _collect_calls consumes>`; lower B-comp's statements
   through **`funcs`, the `for f`, the accessors, AND `deps = _collect_calls(...) & trusted_names - {name}`**.
3. **Report the first surviving blocker** and classify it:
   - stalls at the decode → M2 mis-typed; fix the codomain and retry, or the architecture is wrong (brief
     §6 monolithic framing wins → B-null argued from this);
   - clears the decode, dies at `_collect_calls` → the clash relocated (C2 confirmed); name the sibling type
     gap;
   - clears the sibling chain, dies at `counts[bucket] += 1` / set-algebra / `sorted` / the record return →
     residual is in an already-solved class (plan-2 §6); proceed, table updated by measurement.
4. **Axiom audit** on every green step (C1): `Print Assumptions` / `#print axioms` + allowlist diff empty.
5. **No commitment downstream of S-dec before it reports** (plan-2 C4). M2 is built only on outcome (b/c);
   M3 is built only after a *separate* B-frame premise-check (C3/C4).

**If extended-S-dec is green through the sibling chain with a clean axiom audit, M1+M2 is a real,
certificate-honest win and worth the full build — with M3 held back as an independently-gated (and likely
unnecessary) addendum.**
