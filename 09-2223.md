## 1. The big picture — a compiler that verifies itself, and the one thing it cannot verify

**PyCSL** is a deductive verifier for a statically-analysable subset of Python. It lowers that subset to
**WhyML** (the Why3 platform's language), which emits verification conditions (VCs) discharged
automatically by **SMT solvers** (Alt-Ergo, Z3, CVC5). Its trusted base is pinned by a **3-axiom ledger**
mechanised in **Rocq 8.20 + Lean 4.29**; any new target-language *value shape* must co-land an **axiom-free
Rocq+Lean certificate**, so the ledger stays at exactly 3.

The interesting part: **PyCSL's own compiler back-end** — the ~4 kLOC WhyML *emitter* — is written in that
same verifiable Python subset, and PyCSL **verifies a mirror of it against itself**. Each emitter method is
either *verified* (proved against a contract) or a *`\trusted` stub* (an assumed contract). A multi-session
campaign has driven the trusted core down to **1234** stubs. The residual is dominated by the methods that
**reflect on the compiler's intermediate representation (IR)** — and the IR is a tree of Python
`Dict[str, Any]` nodes with `str` payloads.

So the construct the verifier cannot verify *about itself* is exactly the one its back-end is built to
**traverse**: generic, heterogeneous, reflective dictionary access. **A verifier that cannot verify its own
reflection.** That is the wall.

## 2. The scope cut that makes the problem bounded — and simultaneously starves the solver

The self-annotation contract is deliberately **weak**:

```
#@ requires True   #@ ensures True   #@ assigns <tight frame>
```

We verify **type-safety** (every projection is well-typed — no `int`/`string` confusion), **frame** (the
method mutates only its declared footprint), and **termination**. We **never** verify the *value* computed
(no `ensures \result == …`). This is the decisive design choice: it keeps the goal to the *weakest
interesting guarantee* and, we believed, should keep the residual "engineering, not research."

**The step-back realization (this is the crux).** The weak contract is a double-edged sword:
- it is why the problem *looks* bounded (no functional-correctness obligation), **but**
- it is also why the SMT solver has *no leverage*: there are no value invariants to propagate. When a
  method **composes** a reflective read with iteration, a fold, self-state mutation, and calls to other
  emitter methods, the solver must discharge the whole-body VC with nothing but types and a frame — and the
  *composition* of a pointwise-modellable read with unbounded surrounding machinery is where it fails.

The wall is **not** "model a heterogeneous value." That is *solved* (see §3). The wall is **the
composition**, under a contract too weak to give the solver anything to hold onto through it.

## 3. What is already SOLVED and certified (so SOTA does not re-solve it)

Two of the three faces of the residual are **closed**, byte-for-byte inert on an 844-program reference
corpus, ledger held at 3:

- **Heterogeneous values, pointwise** — a certified datatype `pyval = PInt | PStr | PBool | PNone | PList
  (list pyval) | PDict …` with a string-keyed variant `sdict` and a total lookup `slookup`, all with
  **axiom-free Rocq+Lean certificates**. A single generic read `d.get("k")` lowers cleanly to
  `match slookup "k" d with Some (PStr s) -> s | _ -> ""` — a *total, defensive tag-checked projection*.
  Pointwise reflection is a solved, certified problem.
- **Character-level strings** — a character is a 1-character substring op; `for ch in s` / `enumerate(s)`
  becomes an integer-indexed loop with an arithmetic termination measure; character comparison is an
  *unconstrained boolean* so no SMT string theory is ever exercised. No new value shape, no certificate.
- **Closed-key records** — a `@dataclass`/`TypedDict` monomorphizes to a native WhyML record with faithful
  per-field types and **threads across a call boundary**; the record value shape is already certified on
  both provers. No new certificate needed.

## 4. The wall, precisely — measured, not asserted

A **mirror-only defensive-projection** was fully built (route every generic-dict read through the certified
`slookup`/`pyval`) and measured against a whole-body-proof census of **70** reflective `\trusted` methods.
**Net new methods unblocked: zero.** The read is *never the sole blocker*. Every real reader composes it
with a second wall:

- membership of a projected string in a set the emitter models as an integer map;
- **collection-valued** reads (`d.get(k, [])` / `{}`, then `List[Dict]` iteration) whose element is itself
  reflective;
- **self-state mutation** threaded through the method;
- a call to the **giant `_expr_to_whyml` sibling** (the recursive expression emitter) per element;
- a **nested-heterogeneous return** (a dict whose values are simultaneously string, map, and list-of-dicts).

The canonical hard instance, `_build_soundness_report`, stalls at its **first statement**
`ir_data.get("functions", [])`: a collection-valued read whose result is iterated, projected
(`f["name"]`, `f.get("contracts",{}).get("ensures")`), folded into a variable-key integer map
(`counts[bucket] += 1`), set-algebra'd, sorted, and returned as a nested-heterogeneous record. A *pointwise*
`pyval` read model does not lift any of this — the VC is the **composition**.

**Two bounded leads were separately censused and refuted** (so SOTA need not propose them):
1. a `PList`/`PDict` "collection-valued projection" — refuted: the collection-valued reads are over an
   internal **IR-node algebraic datatype**, plain **arrays**, or **module-constant maps**, not generic
   `pyval`, so a pyval-list projection converts ~0;
2. routing the IR-node ADT's argument list — refuted: the arg-*count* model already exists, but the
   methods *iterate and process* the args (composing the expression emitter + self-state), not merely count
   them.

## 5. Two hard constraints that bound admissible answers (both measured as partial impossibilities)

1. **Byte-for-byte additivity.** Every emitter change must be *byte-identical* on the 844-program reference
   corpus (a hard gate). The corpus **itself** uses the target shapes (generic dicts, `.get`, `.values()`
   walks), so a *corpus-facing* generic-reflection rewrite is **provably not byte-diff-0-safe** — no
   recognizer is simultaneously corpus-inert and mirror-covering. This is a *measured partial impossibility*
   for the non-self-hosting case.
2. **One theory per module.** The certified `pyval` datatype's structural size measure collides *by name*
   with the emitter's own IR-node ADT size measure, so a source file that already emits the IR-node ADT
   cannot also host the `pyval` theory. A second measured boundary.

Plus the standing constraints: **first-order, automatic SMT only** (no interactive proof in the emission
path; VCs must discharge in seconds); **the 3-axiom ledger is fixed** (any new value shape co-lands an
axiom-free certificate); **type-safety + frame + termination only** (never value-correctness); and
**self-hosting** (the machinery is emitted by the same verified back-end).

## 6. The sharp open question (for SOTA)

> Given a method that **composes** a pointwise-modellable generic-reflection read (`d.get(k)`, already
> discharged via a certified tagged-union projection) with **iteration, a variable-key homogeneous-map
> fold, set-algebra, calls to a large recursive sibling emitter, and a nested-heterogeneous return** — how
> does a **verifying compiler** discharge the method's **whole-body verification condition as one
> first-order, automatically-SMT-dischargeable goal**, under a **type-safety + frame + termination-only**
> contract (no value invariants to propagate), **byte-diff-0** on real programs and **ledger-preserving**,
> **while the same pipeline must also host a separate IR-node algebraic datatype** (the one-theory-per-module
> constraint)?
>
> A rigorous argument that **no technique can, under these constraints** — pinning the residual as a
> principled trusted boundary — is an **equally valuable** answer.

**Candidate SOTA anchors to map onto these constraints:**
- **Compositional / modular verification of reflective code**: separation logic & higher-order framing
  (Iris, VST), implicit dynamic frames / permissions (Viper, Nagini) — can a *frame-only* contract be made
  compositional through reflection without value invariants?
- **Gradual / tag-checked typing** (Siek–Taha; Typed Racket's `Any`; space-efficient casts) — the pointwise
  read is already this; the open part is *composition* of casts through a fold.
- **Verified compilation loop→recursion / whole-function transformation** (CompCert, CakeML, defunctionalization)
  — the sibling-composition and iteration are the "control" half; can the transformation be *synthesized*, not annotated?
- **SMT leverage under weak specs**: what minimal *auxiliary* invariant (a synthesized ranking / shape
  invariant) restores solver leverage through a composition when the user contract provides none?
- **Refinement types over a universal value** (LiquidHaskell, F\*, Dafny) — do they help the composition, or
  do they (as we suspect) import a trusted inference engine to prove facts these weak VCs never need?
- **Effect / capability typing** for the self-state mutation threaded through the walk.

## 7. Success criteria — the frozen, reproducible benchmark

A proposal is validated by clearing, reproducibly and under §5's constraints (automatic SMT; ledger stays 3
by `Print Assumptions` / `#print axioms`; byte-diff-0 on the reference corpus; **whole-body** proof, never
an idiom in isolation):

- **B-comp (the composition benchmark):** the method `_build_soundness_report`, transcribed verbatim with
  its `\trusted` marker removed, **type-checks and discharges** its `requires True / ensures True / assigns
  \nothing` contract — i.e. the read → iterate → variable-key-map-fold → set-algebra → nested-record-return
  composition is discharged as one whole-body VC.
- **B-null (equally valuable):** a rigorous impossibility argument that, under §5, no first-order/automatic/
  byte-diff-0/ledger-3/frame-only technique discharges B-comp, so the reflective-composition residual is a
  principled `TRUSTED(essential)` boundary.

Reproduce the wall in one command (after removing the `\trusted` marker from `_build_soundness_report`):
`python3 src/pycsl/pycsl.py <mirror-file> --import-path src/pycsl`.
