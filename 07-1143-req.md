# 07-1143-req — PyCSL Tool Requirements for World Confinement

**Date:** 2026-06-07
**Context:** `making-it-pure-5.md` Phases 1–8 are implemented. All 27 `pure_lib/` modules
exist, wired through a shared `World` class (`{clock, fs, proc}`). The coarse probe
(cross-subsystem confinement) passes with ALL VCs proven using existing PyCSL. Four
requirements remain before the architecture can be formally verified end-to-end.

**Evidence supporting feasibility:** the coarse probe (`formal_coarse_probe.py`) already
proves cross-subsystem preservation *without any tool change* — the WhyML `assigns`
clauses on imported class stubs naturally isolate clock fields from proc fields. The
requirements below extend this to (1) whole-program declarations, (2) nested shared
objects, (3) per-object granularity, and (4) reporting.

---

## R1 — HAPPY ownership declarations

### Problem

`making-it-pure-5.md §2` defines **HAPPY** (High-level Assertion-Producing PYthon
requirement): a whole-program integrity property that says "no method outside a named
owner set writes a protected field." Today, this property is only enforced implicitly
by the `assigns` clauses on individual methods. There is no way to *declare* it once
and have PyCSL verify it exhaustively across all modules.

### What the user writes

```python
#@ happy fs_ownership:
#@     protects world.fs.disk, world.fs.fd_open, world.fs.fd_inode,
#@              world.fs.fd_offset, world.fs.fd_flags, world.fs.next_fd
#@     except sys_open, sys_write, sys_read, sys_close, sys_creat,
#@            sys_mkdir, sys_rmdir, sys_link, sys_unlink, sys_rename,
#@            sys_chmod, sys_chown, sys_truncate, sys_symlink,
#@            sys_readlink, sys_stat, sys_fstat, sys_access,
#@            sys_lseek, sys_utimensat, sys_dup,
#@            _set_bitmap, _get_bitmap, _alloc_inode, _alloc_block,
#@            _free_inode, _free_block, _read_inode, _write_inode,
#@            _read_directory, _write_entry, _dir_lookup, _dir_find_free,
#@            _format_disk, _write_block, _now

#@ happy proc_ownership:
#@     protects world.proc.pid, world.proc.ppid, world.proc.uid,
#@              world.proc.gid, world.proc.umask, world.proc.cwd_inode,
#@              world.proc.exit_code, world.proc._argc,
#@              world.proc._env_count, world.proc._path_count
#@     except chdir, setenv, unsetenv, umask_set, exit,
#@            set_argv, set_path

#@ happy clock_ownership:
#@     protects world.clock._ticks
#@     except monotonic
```

### What PyCSL does (expansion)

For every method `m` NOT in the `except` set of a HAPPY `H`:

1. Scan `m`'s body for write sites to any field listed in `H.protects`.
2. At each such write site, inject `#@ check False` (i.e., "this write is forbidden").
3. If no write sites exist, `m` trivially satisfies `H` — nothing is injected.

This is a **front-end-only** transformation. The backend (Why3/Alt-Ergo/Z3) sees
ordinary `#@ check` goals. No new IR node type is needed. No `\trusted` is introduced.

### Soundness argument

- **Direct writes** are caught by the per-site `#@ check`.
- **Indirect writes** (via a callee `g` that writes the protected field) are caught at
  `g`'s own write site — the expansion is universal (every method is scanned), so
  transitivity is covered without call-graph analysis.
- **`\trusted` stubs** that mutate protected fields must carry `#@ \preserves H` (see
  R1.1 below); a `\trusted` bodyless method that writes a protected field without
  `\preserves` is a **hard error** at parse time.

### R1.1 — `\preserves` for trusted stubs

A `\trusted` method that is in the `except` set of a HAPPY must carry:

```python
#@ \preserves fs_ownership
```

This is a declaration that the stub honours the confinement invariant. It enters the
TCB (Soundness Ledger, `making-it-pure-5.md §5`). A `\trusted` method that is NOT
in the `except` set and writes a protected field without `\preserves` is a hard error.

### Acceptance criteria

- [ ] `#@ happy` declarations parse without error on all `pure_lib/` modules.
- [ ] A method outside the `except` set that writes a protected field generates an
      unproven `#@ check False` VC.
- [ ] A method outside the `except` set with no write to any protected field generates
      no additional VCs.
- [ ] A `\trusted` bodyless method writing a protected field without `\preserves` is a
      hard error at parse time.
- [ ] Existing `region_integrity` (if any) continues to work unchanged.

### Effort estimate

Front-end only: parse the `#@ happy` block, build a (field → except-set) map, scan
each method body for field writes, inject `#@ check False` at violations. Comparable
in complexity to `#@ assigns` processing.

## R2 — Nested shared field support for HAPPY

### Problem

HAPPY as currently conceived targets `self.<field>` (a direct field of the current
class). The World architecture needs it over **nested shared fields**: `world.fs.disk`,
`world.proc.cwd_inode`, `world.clock._ticks`. The `world` object is not `self` — it
is a parameter or a module-level global.

### What changes

The write-site matcher in R1's expansion must resolve dotted paths:

```
world.fs.disk[i] = v       →  matches  protects world.fs.disk
world.proc.umask = v        →  matches  protects world.proc.umask
self._clock._ticks = v      →  matches  protects world.clock._ticks
                               (if self._clock IS world.clock)
```

### Scope

1. **Literal dot-path matching** — `world.fs.disk` is matched syntactically against
   write targets that start with the same prefix. No alias analysis needed for the
   common case (one `world` variable passed by name).

2. **Alias tracking (optional, deferred)** — If `x = world.fs` and then `x.disk[i]=v`,
   the matcher should ideally follow the alias. This can be deferred to a second pass;
   the first version can require that writes go through the canonical `world.fs.disk`
   path.

### Acceptance criteria

- [ ] `#@ happy` declarations with dotted `protects` fields parse correctly.
- [ ] A write to `world.fs.disk[i]` in a non-exempt method generates the `#@ check`.
- [ ] A write to `self.disk[i]` inside an exempt fs method does NOT generate a check.

### Effort estimate

Modest extension to the write-site matcher: compare the target's dot-path prefix
against the `protects` list. No new IR or backend change.

## R3 — Parametric HAPPY (per-object confinement)

### Problem

Tier-1 HAPPY (R1) confines by **subsystem** — "only fs methods write fs fields." But
when two objects live in the *same* subsystem (e.g., inode A and inode B are both in
`world.fs.disk`), Tier-1 cannot express "method M writes only inode A, not inode B."
This is the **intra-subsystem fine case** (`making-it-pure-5.md §9 fine, §10`).

### What the user writes

```python
#@ happy inode_confinement(n):
#@     protects world.fs.disk[512 + n*64 : 512 + (n+1)*64]
#@     except _write_inode, _format_disk
```

A method that operates on a specific inode declares its footprint:

```python
#@ footprint inode_confinement(inode_num)
def sys_truncate(self, inode_num: int, length: int) -> int:
    ...
```

### What PyCSL does (expansion)

At every write site `self.disk[i] = v` inside a method declaring
`#@ footprint inode_confinement(inode_num)`, inject:

```
#@ check i >= 512 + inode_num * 64 and i < 512 + (inode_num + 1) * 64
```

This is the same per-site `#@ check` mechanism as R1, but the check is
**parameterized** by the method's footprint argument instead of being `False`.

### Fallback if R3 is too costly

If parametric HAPPY proves too complex to implement, the fallback is:

```python
#@ assigns world.fs.disk[512 + inode_num*64 : 512 + (inode_num+1)*64]
```

This is a narrow, indexed `assigns` clause confined to the inode-granular leaf
operations (`_write_inode`, `sys_truncate`). Tier-1 HAPPY (R1) handles everything
above, so heavyweight framing lives in a tiny audited core.

### Acceptance criteria

- [ ] `#@ happy ... (n)` with parameterized region parses correctly.
- [ ] `#@ footprint` declaration on a method binds the parameter.
- [ ] Per-site `#@ check` uses the bound parameter value.
- [ ] A method with `#@ footprint inode_confinement(3)` writing outside
      `disk[512+3*64 : 512+4*64]` generates an unproven VC.

### Priority

**Lower than R1+R2.** R1+R2 cover all cross-subsystem interactions (the bulk of the
World). R3 is needed only for intra-fs proofs ("file B is preserved after writing
file A"). Can be deferred to a later release.

## R4 — Soundness report (`--soundness-report`)

### Problem

The Soundness Ledger (`making-it-pure-5.md §5`) lists all places where the proof
relies on **axiomatized** or **trusted** assumptions rather than verified code. Today,
the user must manually audit which VCs rest on `\trusted` stubs, `\preserves`
declarations, or specified (axiomatic) contracts. There is no automated way to
surface this.

### What the user runs

```bash
pycsl --soundness-report pure_lib/os/__init__.py
```

### What PyCSL outputs

A structured report (JSON or human-readable) listing, for each VC:

```
VC: sys_write postcondition (result >= -1)
  Bucket: Modelled
  Dependencies: none (body-verified)

VC: sha256 digest_size == 32
  Bucket: Specified
  Dependencies: hashlib.Sha256.digest_size (axiomatic contract, no body)

VC: fs_ownership preservation across sysmod.exit
  Bucket: Confinement (HAPPY)
  Dependencies: \preserves fs_ownership on _clock.monotonic (trusted)
```

### Report categories

| Category | Meaning |
|----------|---------|
| **Modelled** | VC is body-verified — a real proof |
| **Specified** | VC rests on an axiomatic contract (no body) — enters TCB |
| **Stubbed** | VC rests on a signature-only stub — proves nothing |
| **Confinement** | VC rests on a HAPPY `\preserves` declaration — enters TCB |

### Acceptance criteria

- [ ] `--soundness-report` flag is accepted by the CLI.
- [ ] Every VC is classified into one of the four categories.
- [ ] VCs depending on `\trusted` stubs are flagged with the stub name.
- [ ] VCs depending on `\preserves` declarations are flagged with the HAPPY name.
- [ ] Output is machine-parseable (JSON) with a human-readable summary.
- [ ] The report can be run on any `pure_lib/` module without errors.

### Effort estimate

Requires tracking provenance through the VC generation pipeline: for each WhyML goal,
record whether it was generated from a body, a contract-only stub, or a HAPPY
expansion. The Why3 proof results already contain goal names; the mapping to
provenance is the new work.

### Priority

**Lowest of the four.** Useful for auditing but not blocking any proof. Can be
implemented after R1–R3 are stable.

## Summary

| Req | What | Priority | Effort | Blocks |
|-----|------|----------|--------|--------|
| **R1** | HAPPY ownership declarations + `\preserves` | **High** | Medium (front-end only) | Cross-subsystem confinement proofs |
| **R2** | Nested shared field support for HAPPY | **High** | Small (write-site matcher) | R1 on World architecture |
| **R3** | Parametric HAPPY (per-object confinement) | Medium | Medium–Large | Intra-fs proofs (inode isolation) |
| **R4** | `--soundness-report` | Low | Medium | Auditing only |

**R1+R2 together** unlock the full Tier-1 confinement architecture from
`making-it-pure-5.md §2`. The coarse probe already proves the concept works with
existing `assigns` isolation; R1+R2 make it declarative and exhaustive.

**R3** is needed only for the fine probe (intra-subsystem). It has a fallback
(narrow indexed `assigns`) if the parametric mechanism is too costly.

**R4** is orthogonal and can ship independently.
