**The suggested order is right, but item 1 ("cheap A2b de-risk / A4") is underspecified in a way that matters.** You list permutation transitivity, a Counter/multiset lemma, and the json round-trip as interchangeable "another imported framing lemma" options. **The A1-residual seq-model (Part B) may be mis-categorized as design-blocked.** It's parked because "a mutable `array int` cannot live inside a pure `map`." **The byte-identical emission gate is excellent and I want to flag one risk it carries.** Using emission-identical byte-diff as the regression gate for the alias checker (A2b-2 gate (c)) is exactly right — the checker must not change accepted programs. But there's a subtle failure mode: the gate proves the checker doesn't change *emission*, not that it doesn't change *acceptance*. A checker bug that wrongly *rejects* a previously-accepted program won't show up in a byte-diff of emitted WhyML (rejected programs emit nothing). You need a companion gate: the full corpus must continue to *pass the checker* (not just emit identically). The plan's gate (a)/(b) test the new reject/accept behavior on new drivers, and gate (c) tests emission stability — but the "no previously-accepted program is now rejected" invariant needs its own explicit check. Probably you have this implicitly in the full-corpus sweep, but it's worth stating as a distinct gate because it's the false-reject risk you correctly flagged as "worse than a false accept."
