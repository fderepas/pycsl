# 07-2333-req-rev2 — Richer type support via a unified type-propagation pass

**Date:** 2026-06-08 (rev. 2)
**Supersedes:** `07-2333-req.md` (2026-06-07)
**Context:** rev1 catalogued nine "broken type patterns" in the PyCSL transpiler as nine independent
gaps. rev2 makes the **central correction**: four of them (rev1 Gaps **1, 2, 6, 4**) are not separate
bugs — they are **one disease**, the transpiler defaulting every value to WhyML `int`. rev2 unifies
them under a single **type-propagation pass** (the operational form of the no-more-int doctrine),
re-baselines every reproducer against current `main` (the seq + introspection merges moved some
ground), tags each item `[TOOL]`/`[STDLIB]`, and separates genuine transpiler gaps from stub bugs.

---

## 0. The unifying root cause (the whole point of rev2)

rev1's symptoms, side by side:

| rev1 Gap | Symptom | "Root cause" rev1 gave |
|---|---|---|
| 1 str local | `… type string, expected int` | "locals unconditionally lowered to `int` refs" |
| 2 str concat | `… type string, expected int` | "`+` unconditionally emitted as integer add" |
| 6 str field | `… type int, expected string` | "class fields unconditionally generated as `int`" |
| 4 list param | `… array int, expected int` | "stub params generated with `int` regardless of annotation" |

These are the **same sentence four times**: *the emitter assumes `int` wherever it lacks a wired-in
type*. That is exactly the **no-more-int** leak class — a value reaching WhyML as `int` instead of its
faithful type. The fix is not four patches; it is **one type environment threaded through Module6** so
that locals, fields, operators, and parameters all consult a value's true WhyML type class instead of
falling back to `int`. Patch them independently and they drift (str works as a local but not a field,
concat works but slicing doesn't); fix the source and they become coherent.

The remaining rev1 gaps (3, 7, 8, 9) are **genuinely distinct** and kept separate (§3). Gap 5 stays
**won't-fix** (a real WhyML limitation). One rev1 "gap" (8's `warn`) is actually a **stub bug**, not a
transpiler gap (§4).

## 2. The unified type-propagation pass  **[TOOL]** — resolves rev1 Gaps 1, 2, 4, 6

### 2.1 What exists today (don't reinvent)

Module6 already tracks *some* non-int types in **scattered per-name sets** populated by ad-hoc
analyses: `_array_locals`, `_seq_locals` (`07-1705` P2), `_dict_locals`, `_record_locals`,
`_lambda_locals`, `_current_array1d_params`, `_array2d_params`, plus a partial string mechanism
(`_ghost_string_vars`, `types.py`). String **params/returns** already lower to `string` (no-more-int
Stage). The gap is that these are *disjoint, incomplete sets* with an **`int` fallback** wherever a
name appears in none of them — which is exactly where str **locals** (Gap 1), str **fields** (Gap 6),
the str **`+`** operator (Gap 2), and **list stub params** (Gap 4) fall through.

### 2.2 The pass: one WhyML type environment

Introduce a single per-function (and per-class) **WhyML type environment** `Γ_w : name → WhyMLType`,
where `WhyMLType ∈ {int, string, real, array int, seq int, map κ (option ν), record C, variant D, ...}`.
`Γ_w` is computed once from the Python type universe Module4 already has (`symbol_table` τ +
`_get_type_name`) composed with the existing structural analyses (seq-promotion, array1d/2d, dict,
record, variant), and it **subsumes** the scattered sets (they become views over `Γ_w`, or are folded
into it).

**Every emission site consults `Γ_w` instead of defaulting to `int`:**

| Site | Today (the `int` default) | With `Γ_w` |
|---|---|---|
| local pre-decl (`_emit_body_code`) | `let r = ref 0 in` | `let r = ref (e : Γ_w[r]) in` — e.g. a `string` local binds the RHS string, not `ref 0` (**Gap 1**) |
| `BinOp(+)` | integer `+` | dispatch on `Γ_w` of operands: both `string` → `String.concat`/`(^)`; both `real` → `+.`; arrays → seq concat (existing); else int `+` (**Gap 2**) |
| class field decl (record type) | `_name: int` | `_name: Γ_w[field]` from the field's `__init__` annotation — `str` field → `_name: string` (**Gap 6**) |
| imported stub param | `(p: int)` | `(p: Γ_w[p])` from the stub's annotation — `str`→`string`, `list`→`array int` **or** `seq int` if the stub body grows it (the P2 seq-promotion run on the *stub* body, not a blanket "list→array") (**Gap 4**) |
| return / cross-local assign | `int` | `Γ_w[\result]` / `Γ_w[lhs]` (closes residual boundary leaks, incl. §3.1) |

### 2.3 Soundness & the regression gate

`Γ_w` only *adds* faithful types where today there is an `int` leak, so it cannot weaken any existing
proof. The **emission-identical byte-diff** is the gate: a file that uses none of the newly-typed
constructs must emit byte-identical WhyML; the changed-file set must equal exactly the files using a
str local/field/concat or a re-typed stub param. Stage the pass behind that diff (it is a core-emitter
change — high blast radius, §rev1 priority).

### 2.4 Phasing (within the pass)

| Phase | Delivers | Acceptance |
|---|---|---|
| **TP-1** str **locals** (Gap 1) — **ships first, unblocks astmod Phase 1** | `Γ_w` for locals; `let r = ref (e : string)`; str local round-trip | `r: str = escape("x"); return r` proves; byte-identical for non-str files |
| **TP-2** str **`+`** (Gap 2) | `BinOp(+)` dispatch on `Γ_w` → `String.concat`/`(^)` | `a + b` of two str locals proves `== "ab"` |
| **TP-3** str **fields** (Gap 6) | record field types from `__init__` annotations | the `Greeter` reproducer proves (`self._name: string`, invariant + ensures) |
| **TP-4** **stub params** (Gap 4) | stub signature uses `Γ_w[p]` (str→string; list→array/seq per the stub's growth) | `dumps([1,2,3])` type-checks; a list-param stub proves a length law |

Each phase: reproducer proves, a `pure_lib_test/` **and** a `pycsl-reference` driver, byte-diff
reviewed, full sweep clean (§6).

## 3. The genuinely distinct gaps (kept separate)

### 3.1 Gap 3 — residual seq↔int boundary  **[TOOL]**  (re-scoped)
`07-1705-rev4` P3/P5 made concat *relational* length laws prove (`0626`–`0629`). **Remaining:** patterns
that mix a seq-promoted local with an absolute-count or int context still type-leak (the rev1
reproducer `items += [1]; return len(items)` proving `\result == 2`). Fold the *fix* into the
type-propagation pass (§2.2 "return / cross-local assign" row): once `Γ_w[items] = seq int` is honored
at **every** use (len→`Seq.length`, return, assign-to-other-local), the boundary closes. Driver: the
rev1 Gap-3 reproducer proving `== 2`.

### 3.2 Gap 7 — field knowledge across sequential method calls  **[TOOL]**  (re-rated: modeling, not ergonomics)
Not cosmetic — `Counter(3); inc(); inc(); get()` proving `== 5` is genuinely *unprovable* today, not
just ugly, because the Hoare record model doesn't accumulate `_count` equalities across calls. The
sound fix is **functional record-with update** in the postcondition model (hard); the `#@ assert`
stepping-stone is a documented band-aid, not the fix. Keep P3, but label it a proof-modeling gap.

### 3.3 Gap 8 — `raises` in stub signatures  **[TOOL]**  (faithful form)
Real transpiler gap: a stub body that raises must surface `raises { … }`. **Prefer the SPECIFIC
exception type, not generic `Exception`** (source-of-truth: model what CPython actually raises, per the
faithful-exception doctrine — `KeyError`, `ValueError`, …). Two mechanisms: auto-detect `raise <T>` →
`raises { T }`, and an explicit `#@ raises T` contract for stubs whose raise is conditional/abstract.
(The generic `raises { Exception }` of rev1 is a coarsening; avoid it.)

### 3.4 Gap 9 — module-level `let` bindings for method-call results  **[TOOL]+[SEAM]**
`fd_io = w.fs.sys_creat(...)` at module top-level must generate a `let` binding with the type from the
method's return annotation. Overlaps the **module-globals** model (`module_globals`/inline work) and the
**World** model ([STDLIB]); coordinate. Re-verify against current `main` first.

## 4. Not transpiler gaps (split out of rev1)

- **Gap 5 — locals in postconditions: WON'T FIX.** A WhyML/ACSL invariant — postconditions see only
  `\result` and formal params. Document the loop-invariant / return-and-`\result[i]` workarounds. (No
  change from rev1; restated so the type-propagation pass is not mistaken for fixing it.)
- **The `warn` stub is a STUB BUG, not Gap 8. [STDLIB]** `pure_lib/warn/__init__.py` doing
  `raise Exception(message)` is wrong — `warnings.warn` does **not** raise in normal operation (it emits
  a warning to `world.stderr`). The reproducer fails because the *stub* is unfaithful, independent of
  whether the transpiler can express `raises`. Fix the stub (model the World write) separately; don't
  let it ride on the transpiler `raises` work. (This is the general lesson: a failing reproducer may be
  an unfaithful stub, not a tool gap — triage before scheduling.)
