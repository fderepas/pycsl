# Rocq Proof Completion — Skill Reference

You are a formal verification engineer specializing in interactive theorem proving with Rocq (Coq). Your job is to complete proof obligations generated by Why3 when SMT solvers (Alt-Ergo, Z3) fail to discharge verification conditions.

## What You Receive

A `.v` file generated by `why3 prove -P Coq -a split_vc`. It contains:

1. **Imports**: `Require Import BuiltIn.`, `Require int.Int.`, etc.
2. **Type definitions**: `ref`, `contents` (Why3 mutable references)
3. **Parameters**: function arguments and loop variables as `Parameter n: Numbers.BinNums.Z.`
4. **Axioms**: hypotheses from preconditions, loop invariants, and prior computations
5. **Theorem**: the goal to prove, with empty `Proof. ... Qed.` block

## What You Produce

The same `.v` file with proof tactics filled in between `Proof.` and `Qed.`.

## File Structure

```coq
(* This file is generated by Why3's Coq driver *)
Require Import BuiltIn.
Require BuiltIn.
Require int.Int.
Require int.Abs.
Require int.EuclideanDivision.

(* ref type and contents — always present *)
Inductive ref (a:Type) := | ref'mk : a -> ref a.
...

(* Parameters = function args + local vars *)
Parameter n: Numbers.BinNums.Z.
Parameter i: Numbers.BinNums.Z.
Parameter s: Numbers.BinNums.Z.

(* Axioms = what we know is true *)
Axiom Requires : (0%Z <= n)%Z.
Axiom H : (0%Z <= i)%Z.
Axiom H1 : (i <= (n + 1%Z)%Z)%Z.
Axiom LoopInvariant : (0%Z <= s)%Z.

(* Goal = what we must prove *)
Theorem accumulate'vc : (0%Z <= 0%Z)%Z /\ (0%Z <= (n + 1%Z)%Z)%Z.
Proof.
(* YOUR TACTICS HERE *)
Qed.
```

## Essential Tactic: `lia`

**Most PyCSL goals are linear integer arithmetic.** The `lia` tactic solves them automatically.

You must add `Require Import ZArith Lia.` after the Why3 imports to use `lia` and `nia`.

```coq
Require Import BuiltIn.
Require BuiltIn.
Require int.Int.
Require int.Abs.
Require int.EuclideanDivision.
Require Import ZArith Lia.   (* <-- ADD THIS *)
```

### Critical: bringing axioms into scope

Why3 `.v` files declare hypotheses as `Axiom` (global) rather than `forall`
(local). The `lia`/`nia` tactics only see **local** hypotheses. You MUST
use `pose proof` to bring each axiom into the proof context:

```coq
Proof.
  pose proof LoopInvariant as Ha.
  pose proof H as Hi0.
  pose proof H1 as Hi1.
  lia.
Qed.
```

**`pose proof` vs `generalize`**: Both work, but `pose proof` keeps the
original axiom accessible and names the local copy. Prefer `pose proof`
for clarity.

## Tactic Reference (ordered by frequency of use)

| Tactic | Use when | Example |
|--------|----------|---------|
| `lia` | Linear integer arithmetic (most goals) | `Proof. lia. Qed.` |
| `split` | Goal is a conjunction `A /\ B` | `split. - lia. - lia.` |
| `generalize H` | Need to bring axiom into scope for `lia` | `generalize Requires. lia.` |
| `auto` | Goal follows from hypotheses directly | `Proof. auto. Qed.` |
| `intuition` | Propositional logic + subgoals | `intuition lia.` |
| `destruct H` | Axiom is a conjunction to decompose | `destruct LoopInvariant as [H3 H4].` |
| `assert (P)` | Need intermediate fact | `assert (i >= 0) by lia.` |
| `ring` | Polynomial identity (non-linear) | For `n*n = n*n` |
| `nia` | Non-linear integer arithmetic | For `n >= 1 -> n*n >= 1` |

## Proof Patterns by Goal Type

### Pattern 1: Loop Invariant Initialization
Goal form: Prove the invariant holds with initial values (i=0, s=0).
```coq
(* Goal: (0 <= 0) /\ (0 <= n + 1) *)
Theorem vc : (0%Z <= 0%Z)%Z /\ (0%Z <= (n + 1%Z)%Z)%Z.
Proof.
split.
- lia.
- generalize Requires. lia.
Qed.
```

### Pattern 2: Loop Invariant Preservation
Goal form: Given invariant holds before iteration, prove it holds after.
Axioms include current variable values and the loop guard.
```coq
(* Axioms: H: 0 <= i, H1: i <= n+1, H2: i <= n (guard true) *)
(* Ensures: i1 = i + 1, s1 = s + 1 *)
(* Goal: (0 <= i1) /\ (i1 <= n + 1) *)
Theorem vc : (0%Z <= i1)%Z /\ (i1 <= (n + 1%Z)%Z)%Z.
Proof.
generalize Ensures1 H H1 H2. intros. subst. lia.
Qed.
```

### Pattern 3: Loop Variant Decrease
Goal form: Prove variant > 0 and decreases on each iteration.
```coq
(* Goal: (0 <= n - i) /\ (n - i1 < n - i) *)
Theorem vc : (0%Z <= (n - i)%Z)%Z /\ ((n - i1)%Z < (n - i)%Z)%Z.
Proof.
generalize Ensures1 H H2. intros. subst. lia.
Qed.
```

### Pattern 4: Postcondition
Goal form: After loop exits (guard negated), prove the function postcondition.
```coq
(* Axioms: ..., H2: ~(i < n) — note: ~ (i < n), not ~ (i <= n) *)
(* Goal: (n <= s) *)
Theorem vc : (n <= s)%Z.
Proof.
  pose proof H as Hi0. pose proof H1 as Hi1.
  pose proof H2 as Hi2. pose proof LoopInvariant as Hinv.
  assert (i = n) by lia. subst.
  lia.
Qed.
```

### Pattern 5: Polynomial Postcondition (SMT-hard — the main use case)
Goal form: Postcondition involves products of accumulator variables whose
values are defined by polynomial loop invariants. SMT solvers timeout because
proving the postcondition requires multiplying 3+ independent polynomial
hypotheses together at degree ≥12.

**This is the primary reason Rocq proofs exist in PyCSL.**

```coq
(* Hypotheses from loop invariants *)
Axiom LoopInvariant  : ((2 * a)  = (i * (i - 1)))%Z.
Axiom LoopInvariant1 : ((6 * b)  = (i * (i - 1) * (2 * i - 1)))%Z.
Axiom LoopInvariant2 : ((4 * c)  = (i * i * (i - 1) * (i - 1)))%Z.
Axiom H  : (0 <= i)%Z.
Axiom H1 : (i <= n)%Z.
Axiom H2 : ~ (i < n)%Z.

(* Goal: 288 * (a * b * b * c) = n^5 * (n-1)^5 * (2n-1)^2 *)
Theorem postcondition'vc : ((288 * (a * b * b * c)) = ...)%Z.
Proof.
  (* Step 1: bring ALL loop invariants into local context *)
  pose proof LoopInvariant as Ha.
  pose proof LoopInvariant1 as Hb.
  pose proof LoopInvariant2 as Hc.
  pose proof H as Hi0. pose proof H1 as Hi1. pose proof H2 as Hi2.
  (* Step 2: deduce i = n from loop exit condition *)
  assert (i = n) by lia. subst.
  (* Step 3: nia solves the polynomial identity *)
  nia.
Qed.
```

The `nia` (non-linear integer arithmetic) tactic uses Positivstellensatz
certificates to discharge polynomial identities. It handles products of
hypotheses that SMT solvers cannot.

**For 4 accumulators** (when d = Σk⁴ is also present), add:
```coq
  pose proof LoopInvariant3 as Hd.
```

### Pattern 6: Array Bounds
Goal form: Prove array index is within bounds.
```coq
(* Axioms: H: 0 <= i, H1: i < n, Requires: length arr = n *)
(* Goal: 0 <= i /\ i < length arr *)
Theorem vc : (0%Z <= i)%Z /\ (i < _n)%Z.
Proof.
generalize H H1 Requires. intros. lia.
Qed.
```

### Pattern 7: Division by Zero Guard
Goal form: Prove divisor is non-zero.
```coq
(* Goal: b <> 0 *)
Theorem vc : (b <> 0%Z)%Z.
Proof.
generalize Requires. lia.  (* if Requires implies b >= 1 *)
Qed.
```

## Compilation Command

```bash
coqc -R ~/.opam/default/lib/why3/coq Why3 <file>.v
```

The `-R` flag maps the Why3 Coq library directory to the logical path `Why3`. This is required for the `Require Import BuiltIn.` and `Require int.Int.` imports to resolve.

## Common Errors and Fixes

| Error | Cause | Fix |
|-------|-------|-----|
| `Cannot find BuiltIn` | Missing `-R` flag | Add `-R ~/.opam/default/lib/why3/coq Why3` |
| `lia`/`nia` not found | Missing import | Add `Require Import ZArith Lia.` after Why3 imports |
| `Cannot find witness` | Axioms not in scope | Use `pose proof AxiomName as H.` before `lia`/`nia` |
| `omega` not found | Deprecated in Coq 8.14+ | Use `lia` instead |
| Goal unprovable | Axioms too weak | Loop invariant in Python source needs strengthening |
| `Anomaly: ...` | Coq/Why3 version mismatch | Ensure `why3-coq` matches Why3 version |

## Workflow

1. Read the `.v` file — understand the theorem statement and available axioms
2. Add `Require Import ZArith Lia.` after the Why3 imports
3. Use `pose proof` to bring axioms into the proof context
4. For postconditions: `assert (i = n) by lia. subst.` (deduce loop exit)
5. Try `lia` first — it solves most linear goals
6. For non-linear goals (polynomial products), try `nia`
7. If goal is a conjunction, use `split` then solve each subgoal
8. For genuinely hard goals, use `assert` for intermediate lemmas
9. Verify: `coqc -R ~/.opam/default/lib/why3/coq Why3 <file>.v`

## Proof Companion System

Completed proofs are stored in `<file>.proofs/` directories alongside the
Python source. When pycsl runs, it auto-detects these directories and
**replays** each proof with `coqc` for full verification.

```text
myfile.py                               # Python source
myfile.proofs/
  myfile.mlw                            # Frozen WhyML (staleness check)
  proof_PyCSL_Program_myfunction...v    # Completed proof
```

To generate a new proof companion:
```bash
bin/generate-rocq-proofs.sh myfile.py
```

To verify:
```bash
pycsl myfile.py   # auto-detects myfile.proofs/, replays with coqc
```

## Goal Name Convention

Why3 generates file names as: `<source>_<module>_<function>qtvc<N>.v`

- `<source>`: base name of the `.mlw` file
- `<module>`: always `PyCSL_Program` for PyCSL
- `<function>`: the Python function name
- `<N>`: goal number (empty for first, 1 for second, etc.)

The theorem is always named `<function>'vc`.

## When a Goal Is Unprovable

If the axioms are too weak to prove the goal, the issue is in the **Python source annotations**, not in the Rocq proof. Common causes:
- Loop invariant too weak (doesn't track enough state)
- Missing precondition
- Postcondition too strong for what the code does

In this case, report: "Goal unprovable from given axioms — loop invariant needs strengthening" and use `Abort.` instead of `Qed.`.
