# 07-1321-spec — Faithful bytes/bytearray construction & array-ref call-site lowering

**Status:** Draft (generic specification — intent, not implementation)
**Date:** 2026-06-07
**Source requirement:** `07-1321-req.md` (3 emitter bugs found while type-checking
`pure_lib/os/UnixInodeFileSystem.py`)
**Scope:** the **PyCSL tool only** (`src/pycsl`, WhyML emitter). `pure_lib/` is owned by
another agent and is **not** edited here; it is used only as a motivating verification target.
**Doctrine:** no-more-int / EXTREME RIGOR — a Python value lowers to its *faithful* WhyML type
class (here: `bytes`/`bytearray`/`list` → `array int`), and a construct is modelled with a
contract strong enough to *prove the properties the value is meant to carry*, never merely made
type-correct. We reject "make it `array int`-typed but contentless"; constructors must preserve
length **and** elements.

## S1 — Faithful `bytes()` / `bytearray()` constructors (Bug 1; **High**)

### Intent
A program that packs/unpacks bytes (`bytes([...])`, `bytearray()`, `bytes(parts)`) must lower to
well-typed `array int` **and** carry enough contract to prove length- and element-level
postconditions (e.g. `\length(\result) == 2`, `\result[0] == hi_byte`). Today these calls hit the
unannotated-callee fallback and are typed `int → int`, breaking every byte-packing function.

### Requirements
- **S1.1** `bytes(x)` / `bytearray(x)` where `x` is an iterable of ints lowers to a value of type
  `array int` whose contract is **faithful (length + element equality)**:
  `Array.length result = Array.length x` **and** `forall i. 0 <= i < length x -> result[i] = x[i]`.
- **S1.2** `bytes()` / `bytearray()` (no argument) lowers to an `array int` with
  `Array.length result = 0`.
- **S1.3** The construction integrates with the existing named-builtin path (parallel to
  `list()`), reusing the established array-argument coercion so an `array int` argument is passed
  faithfully (not int-hashed).
- **S1.4** Faithfulness over convenience: no value→int coercion is introduced to bridge the
  argument or result. If an argument cannot be lowered to `array int`, that is an honest error,
  not a silent collapse.

### Acceptance
- [ ] `bytes([1,2,3])` / `bytearray([..])` emit an `array int`-typed val with the length+element
      `ensures` of S1.1; a function asserting `\length(\result)==3` and `\result[0]==1` proves.
- [ ] `bytes()` / `bytearray()` emit an `array int` val with `length result = 0`.
- [ ] Minimal repro drivers (a packing function and an empty-buffer function) prove.
- [ ] No regression on the full pycsl-reference sweep; before/after WhyML byte-diff reviewed.

## S2 — Selective dereference of ref-wrapped array locals at call sites (Bug 2; **High**)

### Intent
A local assigned a list literal **and** later element-mutated is wrapped in a `ref` (so element
assignment can write through it). Operator sites already deref it (`(!x)[i]`); **call-argument
sites do not**, passing the `ref` cell where an `array int` is expected. The pattern "create list
→ mutate an element → pass to a callee" (`sys_creat`, `sys_mkdir`, `sys_symlink`, …) must
type-check.

### Requirements
- **S2.1** When a ref-wrapped array local is passed as a call argument, it is emitted dereferenced
  (`!v`), reusing the emitter's existing ref-wrapped-local set (the same set that drives op-site
  deref) — **not** a new tracking mechanism.
- **S2.2** The deref is **selective**: only arguments that are actually ref-wrapped locals are
  dereferenced. A plain (non-ref) argument — e.g. an `int` parameter `inode_num` — is passed
  unchanged. (The requirement's example `(self__write_inode_2 !inode_num !inode)` is **wrong**;
  the correct lowering is `(self__write_inode_2 inode_num !inode)`.)
- **S2.3** Applies uniformly to module-function calls, method calls, and dotted/coerced argument
  paths (`_coerce_dotted_args` and the generic call emission).

### Acceptance
- [ ] "create list, mutate element, pass to callee" lowers to a call passing `!local` for the
      mutated array and the unchanged form for every non-ref argument, and type-checks.
- [ ] A minimal repro driver (build+mutate a list, pass to a helper that reads it) proves.
- [ ] No regression on the full sweep; byte-diff reviewed.

## S3 — Byte-literal repetition `b'…' * N` (Bug 3; **Low — mostly already met**)

### Intent
A byte literal is `array int`, so `b'\x00' * N` is an `array int` of `N` zeros — including as a
slice-assignment RHS (`self.disk[a:b] = b'\x00' * N`).

### Requirements
- **S3.1** Confirm `b'<const-byte>' * N` lowers to an `array int` (`Array.make N v`) — **already
  holds** for the bare case in this tree; add a regression driver pinning it.
- **S3.2** Verify the **slice-assignment RHS** context specifically (`a[i:j] = b'\x00' * N`); if it
  still mis-types, route it through the same `Array.make` lowering.
- **S3.3** Arbitrary multi-byte tiling (`b'abc' * N`, requires a tiled fill) is **out of scope**;
  if encountered it is an honest error/limitation, not a silent int collapse. The `[0] * N`
  workaround remains for callers.

### Acceptance
- [ ] Regression driver: `b'\x00' * N` is `array int` (bare and as slice-assign RHS).
- [ ] No regression on the full sweep.

## S4 — Faithful `array += array` concatenation (Bug 4, hidden; **Medium — verify first**)

### Intent
The requirement's `_pack_inode` builds a buffer with `parts += _pack_uint32_be(...)` — Python
list/bytearray augmented concatenation. Even with S1 fixed, this is only useful if `array += array`
lowers to a **faithful concatenation** (result length = sum of lengths; elements are the ordered
catenation), not an arithmetic `+` on ints.

### Requirements
- **S4.1** Determine whether `array += array` / `array + array` currently lowers faithfully; if not,
  specify a faithful concatenation lowering (length-additive, element-preserving), consistent with
  the no-more-int doctrine.
- **S4.2** If faithful concatenation is a large effort, scope it as a separate follow-on and record
  it explicitly (no silent int fallback in the meantime — reject instead).

### Acceptance
- [ ] A driver exercising `array += array` either proves a length-additive postcondition or fails
      with an honest, documented limitation (never a silent int result).

## Gating & processing

Per-bug **reproduce → fix → gate**, in priority order **S1, S2 (together — they jointly unblock
the filesystem module), then S3, then S4**:

1. **Reproduce** each in this tree with a minimal `06xx.py` corpus driver (the negative ones
   marked `# pycsl-expected: FAIL` until fixed; positive proving drivers after).
2. **Fix** in the WhyML emitter, extending existing machinery (S1 ⊂ B2 named-builtins; S2 ⊂
   arity-2b ref-tracking; S3 ⊂ C1 literal lowering) — no parallel paths, no `\trusted`.
3. **Gate** each: before/after WhyML byte-diff + full `bin/run-reference-tests.sh --pycsl` sweep
   (must stay clean) + a `test-suite/traceability-pycsl.md` row. These are emitter fixes, **not**
   new `#@` directives, so no doc-coherency surface is required.
4. **Land** S1+S2 as one PR (the joint blocker), S3/S4 as follow-ons.

**Out of scope:** any edit to `pure_lib/` (incl. `UnixInodeFileSystem.py`); arbitrary multi-byte
literal tiling (S3.3).

faithfully). **Bug 2/Bug 3 were already fixed** in this tree (pinned with regression drivers).
