# CMMI for Humans — PyCSL's CMMI Implementation

**Purpose:** explain how CMMI v2.0 has been instantiated for PyCSL,
what the resulting framework looks like in practice, and how to
operate it day-to-day. This document is a reference, not a planning
document. The change history lives in
[`cmmi-tailoring-plan.md`](../cmmi-tailoring-plan.md) and three
follow-ups (`-follow-up.md`, `-follow-up-2.md`, `-follow-up-3.md`).

**Status:** complete. CMMI rollout is operationally done — see
[`projects/pycsl/CMMI-DONE.md`](../projects/pycsl/CMMI-DONE.md).

---

## Part 1 — Why CMMI for PyCSL

### The problem CMMI solves here

PyCSL is a Python-to-WhyML compiler producing soundness-critical
proof artefacts. It is developed by one person with heavy LLM-agent
assistance. The codebase had grown ~22.9k LOC across 9 sub-packages
with most of CMMI's discipline already present *in disguise*
(normative reference docs, traceability matrix, a coherency CI gate,
a three-artefact stdlib baseline). The question wasn't "should we
start being rigorous?" — it was "should we standardise the existing
rigour to a known vocabulary, so external reviewers can audit it
and the agents have stable contracts to escalate against?"

The decision (`should-we-cmmi-or-not.md`): **yes, but tailored
hard**. Adopt the CMMI skill set, but bridge to existing artefacts
rather than rebuild them; apply per-system profiles rather than
uniform Profile L; never duplicate code into a CMMI tree.

### The anchor incident — why this matters

On **2026-05-31 13:47:22**, an annotation run hit `itertools.cycle`
and correctly emitted an L3-ceiling fallback:

```python
#@ \trusted reviewer: python-stdlib
# cite: https://docs.python.org/3/library/itertools.html#itertools.cycle
# cite:_note: cycle returns an infinite iterator; iterator-sequence
#             semantics (indefinite cycling) cannot be expressed in
#             the current contract surface. Stub models existence
#             of a return value only.
#@ ensures True
def cycle(iterable: int) -> int:
    return 0
```

The annotator's behaviour was perfect *locally* — it recognised the
gap and stopped. The failure was *globally* — no agent aggregated
that signal across the 11 other iterator-shaped stubs; no agent
drafted a feature plan. The human (you) wrote `missing-iter-feature.md`
by hand. CMMI's framing says: this was a **Reconciliator** failure
at the System level for SY3-Pycsl. The whole framework exists to
catch this class of incident automatically next time.

## Part 2 — The 5-level binding

PyCSL's CMMI implementation maps the standard 5-level V-model
hierarchy onto **the existing code topology**:

| Level | Unit of work | PyCSL anchor | Spec artefact under `BL/` |
|---|---|---|---|
| **Business** | The project as a whole | "Generate a formally proven annotation system with the smallest TCB possible" | `BL/specifications/main.md` — includes `csl-from-scratch/SKILL.md` |
| **System** | One of 9 packages | `src/<package>/` | `BL/SY<N>-<Name>/specifications/main.md` + PlantUML MSC |
| **Component** | A directory inside a system | `src/<package>/<subdir>/` | `BL/SY<N>-<Name>/CO<M>-<Name>/specifications/main.md` |
| **Module** | A single `.py` file | `src/<package>/<subdir>/<file>.py` | **Auto-generated index** — no hand-written content |
| **Unit** | A function or method | A single `def` in a `.py` file | The function's **existing `#@` contract**. No copy. |

### The key invariant: no source duplication

Source code stays at `src/<package>/`. The
`projects/pycsl/BL/SY<N>-<Name>/` tree holds **specifications and
agent definitions only** — never copies of source. Three
consequences:

1. L1 (Business) `specifications/main.md` is a *one-line include*
   of `config/skills/csl-from-scratch/SKILL.md` (which is the
   operational playbook for the whole `*CSL` family) plus a short
   PyCSL-instance preamble. Not new prose.
2. L4 (Module) is auto-generated by `bin/cmmi-mod-index.py`. The
   `.py` file IS the spec; the index just points at it with line
   refs.
3. L5 (Unit) is the in-source `#@` contract. There are no
   `UN<N>-<Name>/` directories materialised at all under Profile-P.

The verifier `bin/cmmi-audit.sh` enforces this via the C8 check
(`find projects/pycsl/BL -type d -name src` must return empty).

### The Squeeze Strategy (BL requirements)

The Business-level requirements are the 9 **Squeeze** layers from
`config/skills/csl-from-scratch/SKILL.md` §0.5. Each Squeeze is a
constraint with a mechanical gate; together they leave very little
room for a bug to hide.

| # | Squeeze | Mechanical gate | Owning System(s) |
|---|---|---|---|
| S1 | CSL contracts (`requires`/`ensures`) | SMT solver via Why3 | SY3, SY6 |
| S2 | Formal semantics (Rocq + Lean) | `coqc` / `lake build` + `Print Assumptions` | SY1 |
| S3 | Reference tests + traceability matrix | `bin/run-reference-tests.sh` | SY3 |
| S4 | Self-annotation | `bin/run-self-annotation-suite.sh` | SY8 |
| S5 | Dual-prover anchoring | `bin/check-proof-crosscheck.sh` | SY2 + SY7 |
| S6 | IR schema validation | `validate_ir()` in `ir_schema.py` | SY3 |
| S7 | TCB tier inventory | `Print Assumptions` audit | SY1 |
| S8 | Real-world test cases | self-annotation + stdlib stubs | SY6 + SY8 |
| S9 | Auto-trust tracking | auto-trust count reported in CI | SY3, SY5 |

The completeness check is mechanical: **every Squeeze must be
owned by ≥1 System; every non-glue System must own ≥1 Squeeze**.
Enforced by `bin/cmmi-audit.sh` C8 step 5.

### Profile-P — the PyCSL tailoring

The CMMI skills define profiles S (Small), M (Medium), L (Large) by
LOC and team size. PyCSL doesn't fit any of them — it's a single
developer with LLM agents producing soundness-critical artefacts.
Profile-P captures the deviation:

```yaml
profile: P
ccb: { members: [developer], self-approve: true }
source_location: src/<package>/       # NOT under BL/
spec_kind:
  L1:
    plan: config/skills/csl-from-scratch/SKILL.md
    preamble: README.md
    requirements_set: csl-from-scratch §0.5 (Squeeze Strategy S1–S9)
  L2: { … per-system includes … }
  L3: { … per-component includes … }
  L4: bin/cmmi-mod-index.py output (auto-generated)
  L5: in-source #@ contracts (auto-discovered)
```

Profile-P appears as a one-line row in every CMMI skill's §6
Tailoring Guidelines table:

> **Profile-P (PyCSL-specific):** Single-developer CCB; source stays
> in `src/<package>/`, never under `BL/SY<N>-<Name>/src/`; L4 Module
> specs are generated indices, L5 Unit specs are the in-source `#@`
> contracts (no separate files); pre-approved per `cmmi-tailoring-plan.md`.

Plus skill-specific Profile-P bindings (per-system Reconciliator
identification in `cmmi-agent-roles`, include-anchor mechanism in
`cmmi-documents`, Squeeze coverage check in `cmmi-coherency-audit`,
etc.).

## Part 5 — Shell tools (`bin/cmmi-*`)

Nine `bin/cmmi-*` tools plus the `bin/agent-feature-supervisor`
wrapper. Each is independently usable and individually documented
below.

### `bin/cmmi-audit.sh`

The **composite verification gate**. Single command answers "is the
framework healthy?".

```bash
bin/cmmi-audit.sh              # all 8 checks
bin/cmmi-audit.sh --quick      # skip the cmmi-mod-index --verify walk (slowest)
```

Checks in order:

| ID | Step | What it verifies |
|---|---|---|
| C8.1+2 | No source duplication | `find projects/pycsl/BL -type d -name src` returns empty |
| C8.3 | Includes resolve | `bin/cmmi-include-expand.py --verify --all` exits 0 |
| C8.4 | L4 indices match reality | `bin/cmmi-mod-index.py --verify --all` exits 0 |
| C8.5 | Squeeze coverage | every S1–S9 has ≥1 owner in `PROJECT.md`; every non-glue System owns ≥1 Squeeze |
| `[QPM]` | Quantitative mgmt status | `bin/cmmi-qpm-charts.py --check` informational (always passes) |
| `[BRIDGE]` | Queue coverage vs logs | `bin/cmmi-queue-coverage-diff.py --summary` informational — the audit step always passes, but the underlying tool's exit code carries the Item 3.5x decommission-safety signal (exit 0 iff coverage ≥99.5% AND zero mismatches) |
| `[REG]` | Regression suite | `pytest test-suite/cmmi-regression/` (29 tests) |
| `[lang]` | Language-surface doc coherency | `bin/doc-coherency.py --check` |

**Exit codes:** 0 = all gates pass; 1 = ≥1 gate failed. Wire into
CI as the final gate (after `bin/doc-coherency.py`).

### `bin/cmmi-mod-index.py`

**Generate L4 Module-level spec indices** for each System.

```bash
bin/cmmi-mod-index.py --system SY3-Pycsl       # one system
bin/cmmi-mod-index.py --all                    # all 9 systems
bin/cmmi-mod-index.py --file <path.py>         # one .py file
bin/cmmi-mod-index.py --verify --system SY3-Pycsl
bin/cmmi-mod-index.py --verify --all
```

Reads `PROJECT.md` for the 9-system inventory, walks
`src/<package>/` recursively, and emits one auto-generated
`specifications/main.md` per `.py` file at
`projects/pycsl/BL/SY<N>-<Name>/CO<M>-<Name>/MO<P>-<Name>/specifications/main.md`.

Each index lists the file's public and private `def`s with line
refs into the source. Skips empty `__init__.py` package markers.
Counts class methods using dotted qualnames.

`--verify` mode: counts `def` entries in each `.py` and compares to
the bullet count in the matching index file. Detects spec drift
(e.g., when source is edited without regenerating indices).

**Read-only with respect to `src/`.** Never writes inside `src/`.

### `bin/cmmi-include-expand.py`

**Resolve `<!-- pycsl-include: source=<path> scope=<tag> -->` anchors**
at view time. Anchors are the include-mechanism that lets BL/L2/L3
specs point at canonical docs without duplicating content.

```bash
bin/cmmi-include-expand.py <file.md>           # expand, print to stdout
bin/cmmi-include-expand.py --verify <file.md>  # check anchor resolves
bin/cmmi-include-expand.py --verify --all      # check every .md in projects/pycsl/
```

Anchor syntax (single-line HTML comment):

```html
<!-- pycsl-include: source=config/skills/csl-from-scratch/SKILL.md scope=L1-BL-plan -->
```

`source=` is resolved relative to the repository root. `scope=` is
metadata only (for audit grep).

Output mode inlines the source file's content between `<!-- BEGIN
... -->` / `<!-- END ... -->` markers; never writes the input file
in place.

**Exit codes:** 0 = all anchors resolve; 1 = ≥1 anchor target
missing.

### `bin/cmmi-metrics-ingest.py`

**Normalise the `metrics/` tree into per-system KPI snapshots.**

```bash
bin/cmmi-metrics-ingest.py             # one-shot snapshot, replaces latest
bin/cmmi-metrics-ingest.py --weekly    # append to snapshots[] time series
bin/cmmi-metrics-ingest.py --show      # print last snapshot to stdout
```

Reads the existing `metrics/` tree (logs, monitor, evaluator,
reviewer outputs from `coordinator.py` and the meta-agents) and
emits a per-system normalised view to
`projects/pycsl/docs/metrics/metrics-store.json`. References source
data via `source_uri` fields — **does not duplicate**.

KPIs collected per snapshot:

- **Per system:** file count, LOC, `#@` contract line count,
  L3-ceiling note count (`# cite:_note:` markers — the gap signals
  the Reconciliator aggregates), proof-success rate (last 7 days,
  None if not observed).
- **Global:** total log files / lines, monitor report count,
  evaluator report count, reviewer report count, coordinator retry
  count drift (last 7 days), doc-coherency event count (last 7
  days).

The `--weekly` mode is invoked by `bin/cmmi-weekly-snapshot.sh`
(cron). Accumulates the time series that `bin/cmmi-qpm-charts.py`
consumes.

### `bin/cmmi-weekly-snapshot.sh`

**Cron-friendly weekly snapshot wrapper.**

```bash
bin/cmmi-weekly-snapshot.sh    # designed for: 0 6 * * 1 ...
```

Uses `flock` on `metrics/.cmmi-weekly-snapshot.lock` to prevent
overlapping runs. Exits non-zero on ingest failure so cron alerts
the developer. Recommended cron entry (documented in `PROJECT.md`
Snapshot Schedule):

```cron
0 6 * * 1 cd ~/git/pycsl && bin/cmmi-weekly-snapshot.sh >> metrics/cron.log 2>&1
```

Mondays at 06:00 local. One snapshot per week → 52/year. Phase 1B
of `cmmi-quantitative-mgmt` (control charts) becomes meaningful at
snapshot 8 (~8 weeks).

### `bin/cmmi-msg-bridge.py`

**One-way mirror from `metrics/logs/` to
`projects/pycsl/message-queues/`** (Phase 1 of the
`communication`-skill transition).

```bash
bin/cmmi-msg-bridge.py                       # incremental sync since last run
bin/cmmi-msg-bridge.py --rebuild             # wipe queue and rebuild
bin/cmmi-msg-bridge.py --dry-run             # report what would change
bin/cmmi-msg-bridge.py --max-age-days 30     # only mirror recent files (default 30)
```

Each `metrics/logs/<agent>.log` line becomes a JSON message at
`projects/pycsl/message-queues/<agent>/inbox-from-logs/<16-hex-uid>.json`:

```json
{
  "schema": "pycsl-cmmi-bridge-v1",
  "uid": "<16-hex>",
  "source_uri": "metrics/logs/<file>:<lineno>",
  "agent": "<agent-name>",
  "ingested_at": "<UTC ISO8601>",
  "line_text": "<original log line>"
}
```

The bridge maintains `.bridge-cursor.json` to track per-agent
progress; subsequent runs are incremental. Anti-duplication: the
queue carries pointers (`source_uri`) to source lines, not copies.

The `--max-age-days N` flag bounds volume for daily cron runs.
Default 30. Use 0 to disable the cutoff.

The queue directory is **gitignored** — runtime artefact, not part
of the source tree.

### `bin/cmmi-bridge-daily.sh`

**Cron-friendly daily bridge run.**

```bash
bin/cmmi-bridge-daily.sh    # designed for: 0 5 * * * ...
```

Wraps `bin/cmmi-msg-bridge.py --max-age-days 30` with `flock`.
Starts the 2-week clock that gates Item 3.4r (the future
`metrics/logs/` fallback removal). Recommended cron entry:

```cron
0 5 * * * cd ~/git/pycsl && bin/cmmi-bridge-daily.sh >> metrics/cron.log 2>&1
```

Daily at 05:00, one hour before the weekly snapshot.

### `bin/cmmi-queue-coverage-diff.py`

**Pre-decommission validator.** Compares queue contents against
`metrics/logs/` source to quantify bridge fidelity.

```bash
bin/cmmi-queue-coverage-diff.py             # default --summary (5% sample)
bin/cmmi-queue-coverage-diff.py --summary
bin/cmmi-queue-coverage-diff.py --detail    # full walk, per-file breakdown
bin/cmmi-queue-coverage-diff.py --json      # raw JSON dump
bin/cmmi-queue-coverage-diff.py --log-filter coordinator
```

For each `metrics/logs/<file>.log:<lineno>`, asserts a queue
message exists with the same `source_uri` AND `line_text`. Reports:

- Coverage rate (covered messages / total eligible log lines)
- Missing-line count (in log, not in queue)
- Content mismatch count (in queue, but text differs from source)

**Exit codes:** 0 = coverage ≥99.5% AND zero mismatches
(decommission-safe per Item 3.5x gate); 1 = below threshold or
mismatches present (NOT safe yet); 2 = setup error.

The Item 3.5x authorisation gate (coordinator decommission)
requires this tool to report SAFE for **≥30 consecutive daily
runs**. The `[BRIDGE]` step in `bin/cmmi-audit.sh` runs it daily.

### `bin/cmmi-qpm-charts.py`

**SPC control charts + Western Electric rule detection** for the
per-system KPIs.

```bash
bin/cmmi-qpm-charts.py             # emit qpm-report-NNN.md
bin/cmmi-qpm-charts.py --check     # informational, exits 0 always
bin/cmmi-qpm-charts.py --json      # raw JSON dump of signals + counts
```

Reads `projects/pycsl/docs/metrics/metrics-store.json` (built by
weekly `cmmi-metrics-ingest.py --weekly` snapshots). For each of 4
KPI series, extracts the time series, computes μ + σ + control
limits (UCL = μ + 3σ, LCL = max(0, μ − 3σ)), renders a Markdown
table + ASCII spark-line.

**Three signal-strength modes:**

| Band | Snapshot range | Behaviour |
|---|---|---|
| weak | n < 8 | Emit time series only; no control limits, no rule detection |
| preliminary | 8 ≤ n < 20 | Compute limits + WE rules; tag "preliminary" |
| stable | n ≥ 20 | Full strong-signal report |

**Four KPIs tracked:**

1. Proof-success rate per system (last 7 days)
2. Agent retry-count drift (coordinator, last 7 days average)
3. L3-ceiling rate per system (`# cite:_note:` snapshot)
4. Doc-coherency events per week (invocation count)

**Four Western Electric rules** detected (when n ≥ 8):

| Rule | Description |
|---|---|
| WE1 | 1 point beyond ±3σ |
| WE2 | 2 of 3 consecutive points beyond ±2σ on same side |
| WE3 | 4 of 5 consecutive points beyond ±1σ on same side |
| WE4 | 8 consecutive points on same side of μ |

Rule violations are written to
`projects/pycsl/docs/audits/qpm-signal-NNN.md` (separate from the
report) so they can be escalated via `cmmi-glue` Workflow 3.

**Band-transition detector** (Item 4.AT): when the latest snapshot
band differs from the previous (weak → preliminary, or preliminary
→ stable), emits a milestone marker at
`projects/pycsl/docs/audits/qpm-milestone-NNN.md`. Idempotent: skip
if a marker already exists with the same transition tag.

`--check` mode (called by `bin/cmmi-audit.sh [QPM]`) prints a
countdown line:

```
countdown: snapshot K of 8 for preliminary mode (~D days at weekly cadence)
```

### `bin/agent-feature-supervisor`

**Reconciliator** — orchestrates an approved
`missing-*-feature.md` plan through the verification gate. The
shell script is a thin wrapper around
`src/pycsl/agents/agent-feature-supervisor.py`.

```bash
bin/agent-feature-supervisor --feature-file <path.md>
bin/agent-feature-supervisor --feature-file <path.md> --skip-gate
bin/agent-feature-supervisor --feature-file <path.md> --allow-llm-delegation
```

V1 is **gate-only**: orchestrates verification, halts on first
failure, never writes code by default. V1.4 added optional coding-LLM
delegation behind `--allow-llm-delegation` (defaults OFF).

**Exit codes** (extend `coordinator.py`'s 72/73 convention):

| Code | Meaning |
|---|---|
| 0 | All phases passed (or finished without action under `--skip-gate`) |
| 74 | Verification gate failure (with rollback if `--allow-llm-delegation` was on) |
| 75 | Human-needed signal raised (load-bearing file in target list) |
| 76 | Rollback failure (per-phase git-tag restore failed) |

See **Part 6** below for the full supervisor lifecycle.

## Part 6 — The agent pipeline

The agent loop closes the cycle that the 13:47:22 incident
exposed. Three agents form the chain:

### Step 1 — Gap detection (`agent-stdlib-annotate --detect-gaps`)

```bash
bin/agent-stdlib-annotate --detect-gaps                      # scan src/pycsl_lib/
bin/agent-stdlib-annotate --detect-gaps --scan-path <file>   # scan a fixture file
```

Walks `src/pycsl_lib/` (or any fixture path), extracts every
`# cite:_note: <text>` line, classifies each into a category, and
writes the aggregate to `metrics/stdlib-gap-report.json`.

**Heuristic taxonomy:**

| Category | Trigger regex |
|---|---|
| `iterator-semantics` | iterator, infinite, yields, lazy sequence, generator |
| `regex-semantics` | regex, regular expression, pattern match |
| `higher-order` | callback, predicate function, function argument, callable |
| `string-content` | string contents, format string, encoding, unicode |
| `io-side-effect` | file system, file handle, socket, stream, I/O |
| `non-deterministic` | random, time, clock, uuid |
| `unclassified` | (none of the above) |

Reads `# cite:_note:` markers PRECEDING each `def` (matches the
contract-block convention). The 2026-05-31 13:47:22 incident's
`itertools.cycle` correctly classifies as `iterator-semantics`.

### Step 2 — Feature-plan proposal (`agent-stdlib-annotate --propose-feature`)

```bash
bin/agent-stdlib-annotate --propose-feature iterator-semantics
bin/agent-stdlib-annotate --propose-feature regex-semantics --proposal-threshold 3
```

When a category's note count passes `--proposal-threshold` (default
5), generates a draft `missing-<category>-feature.md` from the
template at
`config/skills/agent-stdlib-annotate/references/feature-plan-template.md`.

Auto-fills the gap section (anchor function = most-cited stuck
function), the scope table (all stuck functions in the category),
and a quantitative-impact paragraph. **Leaves design options as
`TODO (human)` placeholders** — the LLM doesn't have enough context
to propose them reliably without a person in the loop.

Output lands at `proposed-features/missing-<category>-feature.md`
with `STATUS: DRAFT` header.

### Step 3 — Human approval

The human reviews the draft, fills in the design options,
recommendation, atoms, and implementation surface. To approve:

1. Move the file from `proposed-features/` to the repo root
   (sibling of `missing-iter-feature.md`).
2. Change `STATUS: DRAFT` → `STATUS: APPROVED`.

### Step 4 — Supervised rollout (`bin/agent-feature-supervisor`)

```bash
bin/agent-feature-supervisor --feature-file missing-<category>-feature.md
```

The supervisor:

1. **Parses the `## Implementation surface` section** of the
   feature plan into a phase list. Each phase has a title and a
   list of target files (extracted from file table cells).
2. **Checks every target against the load-bearing deny-list** at
   `config/skills/agent-stdlib-annotate/references/load-bearing-files.md`.
   The deny-list covers 22 files: Module 2–6 sources, grammar
   (`csl.lark`), IR schema, exception model, all `module6_whyml/`
   mixins, formal-semantics dirs, the 3 normative reference docs,
   `annotations.md`, `traceability-pycsl.md`.
3. **If any target is load-bearing**, halts with exit 75 + writes
   `metrics/feature-supervisor/<slug>/halt-report.md` naming the
   files. **Always.** Even with `--allow-llm-delegation`.
4. **Otherwise (no deny-list hits)**, runs the verification gate:
   `pytest`, `bin/run-reference-tests.sh`, `bin/doc-coherency.py
   --check`, `bin/cmmi-audit.sh`, `bin/stdlib-coverage-report.py`.
   Halts with exit 74 on first failure.

### Step 5 (optional) — Coding-LLM delegation

```bash
bin/agent-feature-supervisor --feature-file <path> --allow-llm-delegation
```

For phases with no deny-list hits, the supervisor:

1. Tags `HEAD` as `feature-<slug>-phase-<N>-start` (audit + rollback anchor).
2. Builds a phase-scoped prompt from the
   `config/skills/agent-stdlib-annotate/references/coding-llm-prompt.md`
   scaffold + the phase body + inlined target file contents.
3. Dispatches to `llm_generate` (shared LLM client).
4. Extracts the fenced `diff` block from the LLM output. If
   `# refuse:` or no diff present → exit 75.
5. Validates with `git apply --check`, then applies with
   `git apply --whitespace=nowarn --recount`.
6. Runs the verification gate.
7. On gate failure → `git restore --source=<tag> --worktree
   --staged -- <target files>`, deletes the tag, exits 74. On
   success → keeps the tag for audit trail.

**Safety perimeter (inviolable):**

- Load-bearing deny-list always wins.
- The verification gate always runs after every phase.
- `git push`, `git commit`, `git reset --hard`, `git clean -f`,
  `git rebase` are **NEVER** invoked by the supervisor — enforced
  by the `_git()` wrapper which rejects forbidden args.
- Staging is the human's job; supervisor leaves edits in the
  working tree.
- On gate failure, only the current phase's edits revert (via
  per-phase tag).
- No retry — single attempt per phase.

|---|---|---|---|

| Weekly | QPM report | `bin/cmmi-qpm-charts.py` | After snapshot |

| Per feature | Proposal generation | `bin/agent-stdlib-annotate --propose-feature <cat>` | After detect-gaps |
| Per APPROVED plan | Supervised rollout | `bin/agent-feature-supervisor` | After human approval |

### What to watch (artefact-driven alerts)

| Artefact | When | Action |
|---|---|---|
| `bin/cmmi-audit.sh` exits non-zero | A gate broke | Inspect the failing step, fix, re-run |
| `projects/pycsl/docs/audits/qpm-signal-NNN.md` | A WE rule fired | Review; decide whether to investigate the KPI drift |
| `projects/pycsl/docs/audits/qpm-milestone-NNN.md` | A band transition (weak→preliminary, or preliminary→stable) | Baselines are now meaningful at a new tier |
| `proposed-features/missing-*.md` with `STATUS: DRAFT` | Gap detector found ≥5 stuck functions in a category | Review, fill design options, flip to APPROVED, run supervisor |
| `metrics/feature-supervisor/<slug>/halt-report.md` | Supervisor halted | Read why — load-bearing files, gate failure, or LLM refusal |
| `[BRIDGE]` coverage in audit drops below 99% | Bridge cursor corrupt or coordinator write-path changed | `bin/cmmi-msg-bridge.py --rebuild`; investigate |

## Part 10 — Anti-patterns to avoid

- **Editing `BL/.../specifications/main.md` of an L4 Module index
  by hand.** They are auto-generated; hand-edits are wiped on
  regeneration. Edit the `.py` file instead and re-run
  `bin/cmmi-mod-index.py`.
- **Adding a 10th system without updating `PROJECT.md`
  `squeeze_owners:`.** The C8.5 audit step catches this — coverage
  check fails with "Systems with no Squeeze".
- **Removing entries from the load-bearing deny-list.** Each entry
  is there for a soundness reason. Requires a CCB-tracked commit
  (Profile-P: commit SHA = CR-ID).
- **Running `bin/agent-feature-supervisor --skip-gate` in CI.**
  That mode is for human smoke-testing only.
- **Disabling the daily bridge cron.** The 14-day clock for Item
  3.4r doesn't tick if the bridge doesn't run.
- **Decommissioning coordinator writes (Item 3.5x) without ≥30
  days of ≥99.5% coverage.** The dual-write phase is the safe
  steady state.
- **Manually appending to `metrics-store.json`.** Snapshots are
  generated by `bin/cmmi-metrics-ingest.py --weekly` only.
  Hand-edits skew control limits.
- **Treating L3-ceiling notes (`# cite:_note:`) as bugs.** They
  are *signals* — the annotator correctly recognised an
  expressivity gap. The Reconciliator's job is to aggregate them
  into feature proposals, not to "fix" them per stub.
- **Trying to retrofit the 8 `pycsl-*` domain skills to CMMI
  §1–§6 format.** They are domain skills, not process skills.
  Coherency is enforced by `bin/doc-coherency.py`.
- **Committing the message-queue contents to git.** The
  `projects/pycsl/message-queues/<agent>/` directories are
  gitignored — runtime artefact, not source.

## Appendix A — Glossary

| Term | Definition |
|---|---|
| **Profile-P** | The PyCSL-specific CMMI tailoring profile. Source stays in `src/`; L4 specs are auto-generated indices; L5 specs are in-source `#@` contracts; single-developer CCB; commit SHA = CR-ID. |
| **Squeeze** | A constraint layer with a mechanical gate (per `csl-from-scratch` §0.5). S1–S9 are the BL-level requirements. |
| **Reconciliator** | The role responsible for diagnosing test failures and routing faults at a given V-model level. For SY3-Pycsl + SY6-PycslLib, bound to `agent-feature-supervisor.py`. |
| **L3-ceiling note** | A `# cite:_note:` line emitted by the annotator when it correctly identifies a contract-surface gap. Aggregated by the Reconciliator into feature proposals. |
| **Coverage band** | QPM signal strength tier: weak (n<8), preliminary (8≤n<20), stable (n≥20). |
| **Load-bearing file** | A file on `config/skills/agent-stdlib-annotate/references/load-bearing-files.md`'s deny-list. The supervisor will not autonomously edit it under any circumstance. |
| **Glue system** | A system declared in `PROJECT.md` `glue_systems:` that doesn't own a Squeeze directly (currently SY4 + SY9). The coverage audit doesn't flag them as orphans. |
