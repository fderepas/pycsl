# 07-1311-spec — Quantification over lists and dicts (element / key / value / item domains)

**Status:** Draft (generic specification — intent and gated phasing, not implementation)
**Date:** 2026-06-07
**Companion:** `quantification.md` (typed & bounded binders, P1–P4) — this spec is the
collection-domain follow-on to P3 ("Sets & bounded quantification").
**Scope:** the **PyCSL tool only** (`src/pycsl`). `pure_lib/` is not edited here.
**Doctrine:** no-more-int / EXTREME RIGOR. A bound variable ranges over the *faithful* type of
the thing being quantified (a list element is its element type; a dict key/value is the faithful
key/value type), and a collection-bounded quantifier desugars to a **sound** first-order formula
over the faithful WhyML model — never an int-hash placeholder. Legacy integer quantifiers stay
**byte-identical** (the regression gate).

---

## 0. Motivation & current state

Today PyCSL can quantify over scalar/datatype/record binders (`\forall k : int|bool|str|float|
Color|Point; …`, `quantification.md` P1/P2) and — via P3 — over finite **sets** (`\forall x in S;`
with `use set.Fset`). What it *cannot* yet express directly:

- **Lists:** "every element of `a` is non-negative", "`a` is sorted" as a clean
  `\forall x in a;` / `\forall i in range(\length(a));` instead of the hand-rolled
  `\forall i : int; (0 <= i and i < \length(a)) ==> a[i] >= 0`.
- **Dicts:** "every value stored is positive", "every key is in range" — there is no key/value/item
  domain; the only workaround is `\forall k : int; <key-presence guard> ==> P(d[k])`, which forces
  the user to hand-write the presence guard and assumes a key type.

PyCSL already models these faithfully — a `list` is `array int` (length + `a[i]` reads), a `dict`
is `map int (option int)` (`d[k] = None` ⇔ absent). The gap is purely **surface**: a bounded
`\forall … in <list|dict>;` that desugars onto those models. This spec specifies that surface and
its sound desugaring.

### Reuse (do NOT reinvent)
- The bounded grammar already exists: `forall_in_expr` / `forall_typed_in_expr` /
  `exists_in_expr` / `exists_typed_in_expr` (`Module2_Parser.py`), and the `Forall.domain`
  node field. P3 routes set domains to `Fset`. This spec adds list/dict domains to the **same**
  `domain` machinery — a new *desugaring per domain kind*, not a new node.
- The faithful models exist: `array int` (length, `a[i]`) and `map int (option int)`
  (`Map.get`, `None`/`Some`). No new Why3 theory is required for lists; dicts reuse `option`.

## Q1 — List element & index quantification (LOW; foundational)

### Intent
`\forall x in a; P(x)` (element domain) and `\forall i in range(\length(a)); P(i)` (index domain)
for a list `a`, replacing the boilerplate `\forall i : int; (0 <= i and i < \length(a)) ==> …`.

### Requirements
- **Q1.1 — element domain.** For a list `a` (model `array int`), `\forall x in a; P(x)` desugars to
  `forall _i:int. 0 <= _i < Array.length a -> P[x := a[_i]]` (and `\exists` to the `exists`/`/\`
  dual). The binder `x` ranges over the **element type** (int for `array int`); an explicit
  `\forall x : T in a;` is accepted and checked against the element type.
- **Q1.2 — index domain.** `\forall i in range(\length(a)); P(i)` (and `range(lo, hi)`) desugars to
  `forall i:int. lo <= i < hi -> P(i)`, with `i : int`.
- **Q1.3 — soundness.** The desugaring is a pure rewrite to the existing index-bounded form (which
  already discharges array-bounds and is proven across the corpus); no new abstract val, no
  int-hash. `\length(a)` lowers to `Array.length a` as today.

### Acceptance
- [ ] `\forall x in a; x >= 0` proves for a driver whose body establishes it; the element binder is
      element-typed (a `str` list → `string` binder).
- [ ] `\forall i in range(\length(a)); a[i] <= a[i+1]` (sortedness shape) lowers to the index form
      and proves.
- [ ] Legacy `\forall i : int; … a[i] …` quantifiers are byte-identical (gate).

## Q2 — Dict key quantification (MEDIUM)

### Intent
`\forall k in d; P(k)` and `\forall k in d.keys(); P(k)` — quantify over the **present keys** of a
dict `d`.

### Requirements
- **Q2.1 — key domain.** For a dict `d` (model `map int (option int)`), `\forall k in d;` and
  `\forall k in d.keys();` are equivalent and desugar to
  `forall k:<keyT>. d[k] <> (None: option <valT>) -> P(k)` (presence guard from the faithful map
  model). The binder `k` ranges over the **key type**; `\forall k : T in d;` checks `T` against it.
- **Q2.2 — exists dual.** `\exists k in d; P(k)` desugars to
  `exists k:<keyT>. d[k] <> None /\ P(k)`.
- **Q2.3 — soundness & faithfulness.** No int-hash of keys; the key binder is the faithful key
  type (`int` or `str`). The presence guard is the map model's own `None`/`Some`, so the formula is
  exactly "for every key actually in `d`".

### Acceptance
- [ ] `\forall k in d; k >= 0` (all present keys non-negative) proves/refutes correctly.
- [ ] A string-keyed dict yields a `string` key binder.
- [ ] `\exists k in d; d[k] == v` lowers to the `exists … /\ …` dual.

## Q3 — Dict value & item quantification (MEDIUM)

### Intent
`\forall v in d.values(); P(v)` and `\forall k, v in d.items(); P(k, v)`.

### Requirements
- **Q3.1 — value domain.** `\forall v in d.values(); P(v)` desugars to
  `forall k:<keyT>. match d[k] with Some v -> P(v) | None -> true end` (equivalently
  `forall k. d[k] <> None -> P(value_of(d[k]))`). `v` ranges over the **value type**.
- **Q3.2 — item domain (two-binder).** `\forall k, v in d.items(); P(k, v)` binds the key and the
  value of each present entry: `forall k. match d[k] with Some v -> P(k, v) | None -> true end`.
- **Q3.3 — exists duals** as in Q2.2.
- **Q3.4 — faithfulness.** Value/key binders are the faithful value/key types; the `option`
  destructuring is the map model's own — no projection to int.

### Acceptance
- [ ] `\forall v in d.values(); v > 0` proves/refutes correctly.
- [ ] `\forall k, v in d.items(); (k > 0) ==> (v >= 0)` lowers with both binders bound and proves.

## Q4 — Collection-typed binders (LOW; YAGNI-gated, likely defer)

### Intent
A binder that ranges over *all* lists or *all* maps: `\forall a : list; P(a)`,
`\forall m : dict; P(m)` (e.g. a general algebraic law over arbitrary maps).

### Requirements
- **Q4.1** Extend `_quant_binder_whyml` so `list`/`bytes`/`bytearray` → `array int` and `dict`/
  `set` → the map/set sort, making them legal binder sorts.
- **Q4.2** This is genuinely higher-order-flavoured and rarely needed in source contracts; per the
  `quantification.md` discipline, **reject** (don't int-default) unless a real driver materialises
  it. **Recommended: defer** until a concrete law (e.g. a `#@ lemma` over arbitrary maps) needs it.

### Acceptance (only if pursued)
- [ ] `\forall a : list; \length(a) >= 0` type-checks and proves.

## Cross-cutting

- **Binder typing.** Default element/key binder types follow the collection's faithful model
  (`array int` → `int` element; `map int (option int)` → `int` key/value); the explicit
  `\forall x : T in S;` form (already in the grammar) lets the user pin/override, and Module 4
  **rejects** a mismatch rather than int-defaulting.
- **Domain-kind dispatch.** Module 6 reads `Forall.domain` and the domain's **static type** (list
  vs dict vs set) to pick the desugaring (index-bounded / map-presence / Fset). `.keys()` /
  `.values()` / `.items()` are recognised only in the `in`-domain position of a quantifier.
- **No new heavy theory.** Lists reuse `array.Array`; dicts reuse the existing `map`+`option`
  model; sets stay on P3's `Fset`. Keep any new import behind a `needs_*` flag so non-quantifying
  files stay byte-identical.

## Gating & processing
Per-phase **reproduce → fix → gate**, order **Q1 → Q2 → Q3**, Q4 deferred:
1. A reference-corpus driver per phase (positive proof + a negative `# pycsl-expected: FAIL`
   that the quantifier actually constrains, so it is not vacuously true).
2. Desugaring in Module 6 (+ Module 4 well-formedness for the binder/element-type check); reuse the
   existing `domain` plumbing.
3. Gate: before/after WhyML byte-diff (legacy quantifiers unchanged) + full `--pycsl` sweep +
   traceability rows. New surface (`\forall … in <list|dict>`, `.keys/.values/.items` in quantifier
   position) is documented across the five normative surfaces (doc-coherency) since it extends the
   `\forall`/`\exists` directive family.
4. Land Q1 first (foundational, lowest risk), then Q2+Q3 (dict family), Q4 only on a real driver.

**Out of scope:** `pure_lib/` edits; runtime-heap "all live objects" quantification
(`quantification.md` P4, deferred to the `store`/`typed` models); arbitrary higher-order binders.

## Implementation outcome (2026-06-07)

Reproduce-first showed most of the surface already lowered; only the range domain was broken.

| Item | Outcome | Evidence |
|------|---------|----------|
| **Q1.1** list element `\forall x in a;` | **already worked** (membership desugar `∃i. a[i]=x`); pinned | driver `0620` |
| **Q1.2** range `\forall i in range(lo,hi);` | **FIXED** — was mis-desugared through the array template (`unbound Array.length`); now a direct `lo <= i < hi` bound in `_csl_in` | driver `0620` (+ negative `0622`) |
| **Q2** dict key `\forall k in d;` / `d.keys()` | bare form **already worked** (`Map.get d k <> None`); `.keys()` surface **added** (dict-view atom) | driver `0621` |
| **Q3 values** `\forall v in d.values();` | **ADDED** — `exists k. Map.get d k = Some v` (new `DictView` atom + `MapValueIs` IR + Module6 lowering); quantification over map values, previously unexpressible | driver `0621` |
| **Q3 items** `\forall k, v in d.items();` | **deferred** (two-binder) — honest parse/IR error, not a silent miss | — |
| **Q4** collection-typed binders | deferred (YAGNI) | — |

**Net:** the genuine fix was **Q1.2 (range)**; the genuine new capability is **Q3 value
quantification** (`.values()`). Key quantification already existed (bare `\forall k in d;`).
A note on provability: the element/value *membership* forms lower soundly but are
**trigger-limited** for non-trivial properties (the existential witness) — the **range/index**
form is the SMT-friendly one and is recommended where applicable. The two-binder `.items()` is the
one remaining follow-on.

**Changes:** `Module2_Parser.py` (range stays an expr; `dict_view_expr` atom + `DictView` node),
`Module5_IREmitter.py` (`_csl_in`: range→interval, `DictView`→presence/value-witness),
`module6_whyml/expressions.py` (`MapValueIs` lowering). Drivers `0620`–`0622`. Tool-only.
