# 08-0350-spec — `pure_lib/astmod` contracts for verifying user code that `import ast`

**Date:** 2026-06-08
**Status:** Draft
**Supersedes:** `ast-req.md` (2026-06-08)
**Scope:** Replace the opaque `astmod` stub with contracts derived from the real `pure_ast.py`
implementation, **for the purpose of verifying user code** — not the toolchain itself.

---

## 1  Context

The PyCSL toolchain contains a 3,775-line pure-Python reimplementation of the stdlib `ast` module
(`src/pycsl/pure_ast.py`). Every pipeline stage imports it:

| Consumer | Key functions used |
|---|---|
| Module1_Ingestor | `parse`, `comments`, `walk`, `iter_child_nodes` |
| Module3_Weaver | `parse`, `walk`, `iter_child_nodes`, `NodeVisitor`, `unparse`, `literal_eval` |
| Module4_SemanticAnalyzer | `NodeVisitor`, `walk`, `iter_child_nodes` |
| Module5_IREmitter | `NodeVisitor`, `walk`, `iter_child_nodes`, `get_docstring`, `unparse`, `literal_eval` |
| import_classifier, pycsl.py, ConcurrencyChecker | `parse`, `walk`, `iter_child_nodes`, `dump` |

`pure_lib/astmod/__init__.py` is currently a stub: every AST node is an opaque non-negative `int`
handle and every function a trivial body. So formal tests assert only non-negativity/identity, and
user code that imports `ast` can be verified only up to type compatibility.

**The irony, named and resolved.** `pure_ast.py` is the parser the toolchain *itself* runs, so
`astmod` is a contract for PyCSL's own front-end. That tempts a second, grander reading — using
`astmod` to *self-verify* the parser. **This spec explicitly does not pursue that** (see §2). The
parser stays in PyCSL's trusted base; `astmod` over-approximates it solely so that *user* programs
calling `ast` can be verified.

## 2  Goal — and explicit non-goal

**Goal (a): let user code that does `import ast` verify against meaningful postconditions** — not
just `>= 0`. Concretely, a verified user program may rely on:

1. The **faithful** identity/projection facts (§4.1): `copy_location(n, o) == n`,
   `fix_missing_locations(n) == n`, `increment_lineno(n) == n`.
2. **Referential transparency** of the pure helpers: because `parse`/`dump`/`unparse` carry
   `assigns \nothing`, PyCSL's RT inference (`module5/memoization_rt.py::_detect_purity`, reference
   §2.6 D3) treats them as pure, so `dump(parse(s))` evaluated twice on the same `s` yields **equal**
   results. This is *determinism-via-purity* — it does **not** characterize *which* string is
   produced (see the Ledger, §8).
3. Eventually (Phase 2–3), **`isinstance` dispatch on node types** — the common user idiom — once
   nodes carry a real `τ` tag and `\subtag`/`\typeof` land.

**Non-goal: self-verification of `pure_ast.py`.** `astmod` contracts *over-approximate* the parser;
a green `astmod` test proves facts about the *contract*, not about the 3,775-line body. The body is
TCB. Nothing here narrows that TCB, and the spec must not be read as if it did.

## 3  Classification lens (modelled / specified / stubbed)

Per the project discipline, every function is bucketed and **coverage is reported per bucket**, so a
green suite is never mistaken for faithfulness:

- **Modelled** — a faithful contract preserving real semantics (a real proof).
- **Specified** — an axiomatized contract trusted as written; enters the TCB; sound only for the
  stated property (e.g. "returns a `str`," not *which* string).
- **Stubbed** — signature/handle only; proves nothing about the value.

The word "faithful" in this spec is reserved for the **Modelled** rows (§4.1). Everything else is
specified or stubbed, and §2's promise of "meaningful postconditions" is honest only with that split
stated.

## 4  Function-by-function mapping

### 4.1  Modelled (faithful — identity/projection), already done

These genuinely return an argument unchanged; the contracts are exact and verified.

| astmod | pure_ast.py signature | Contract | Bucket |
|---|---|---|---|
| `copy_location` | `copy_location(new_node, old_node)` | `ensures \result == new_node` | **Modelled** ✅ |
| `fix_missing_locations` | `fix_missing_locations(node)` | `ensures \result == node` | **Modelled** ✅ |
| `increment_lineno` | `increment_lineno(node, n=1)` | `ensures \result == node` | **Modelled** ✅ |

### 4.2  Specified (string-returning — pure, content not characterized)

After Gap 1 (str local binding), these return `str` and carry `assigns \nothing` (giving the §2.2 RT
property). The contract pins the *type and purity*, not the output content.

| astmod | Behaviour | Contract | Bucket | Blocked by |
|---|---|---|---|---|
| `dump` | string repr of the AST | returns `str`; `assigns \nothing` | **Specified** | Gap 1 |
| `unparse` | AST → source string | returns `str`; `assigns \nothing` | **Specified** | Gap 1 |
| `get_docstring` | docstring `str` or `None`(→0) | returns `str`; `assigns \nothing` | **Specified** | Gap 1 |

### 4.3  Stubbed (opaque handle / count proxy — value not modelled)

| astmod | Behaviour | Contract | Bucket | Note |
|---|---|---|---|---|
| `parse` | builds a `Module`/`Expression` AST | `\result >= 0` (handle); `assigns \nothing`; add `mode` param | **Stubbed** | tree structure unmodelled until Phase 2/3 |
| `literal_eval` | evaluates a Python literal | **opaque `int` handle, unconstrained value** | **Stubbed** | **see §4.4 — the old `>= 0` was unsound** |
| `walk` | BFS generator over descendants | count proxy; `\result >= 1` (node itself always yielded) | **Stubbed** | generator semantics unmodelled |
| `iter_fields` / `iter_child_nodes` | yield pairs / child nodes | count proxy | **Stubbed** | generators unsupported |
| `comments` | list of `Comment` w/ positions | count proxy (`\result >= 0`) | **Stubbed** | P2 |
| `get_source_segment` | source text for a node | returns `str` (or int proxy) | **Specified/Stubbed** | P3 |

### 4.4  Soundness fix — `literal_eval`

The earlier proposal `ensures \result >= 0` "only for numeric literals" is **unsound**:
`literal_eval("-5") == -5 < 0` is a direct counterexample, and for list/dict/str results the
`int`-handle model cannot represent the value at all. **Fix:** `literal_eval` returns an
**unconstrained** `int` handle (no `>= 0`), honestly stubbed — its value is not modelled. Do not ship
the `>= 0` postcondition.

## 5  Node type classes (`_NODE_SPEC`) and `isinstance`

`pure_ast.py` generates ~90 node classes (`Module`, `FunctionDef`, `BinOp`, `Constant`, …); user code
relies heavily on `isinstance(node, ast.FunctionDef)`. The corrected dependency story:

- The mechanism for `isinstance` is **`\subtag(\typeof(node), FunctionDef_tag)`** (per `07-1839-spec`
  §4.2) — **not** `\in_globals`, which answers "is this name a module binding," a category error for
  a *type* test. Strike the `\in_globals` approximation.
- **`\typeof` is decided only when the node value carries a concrete `τ`.** Today `parse` returns an
  opaque `int` handle whose `τ = Any`, so `\typeof(node)` is in the *unknown tail* and
  `isinstance(node, …)` stays **symbolic** — it cannot be decided. To decide it, nodes must be modelled
  as a real `variant`/`record` type (a concrete `τ`), which is exactly Gap 6/7.
- **Therefore Phase 3 `isinstance` needs *both* P4 *and* the node-class model** — you cannot dispatch
  on a type you have not given the value. `ast-req.md` listed only P4; that under-stated the
  dependency.

Recommendation unchanged: defer node-class modelling to Phase 2 (after Gap 6/7), and `isinstance`
resolution to Phase 3 (after P4 *and* Phase 2).

## 7  Phased plan

### Phase 0 — done (`eb53368`)
11 contracted functions with identity/non-negativity postconditions; the §4.1 three are **Modelled**,
the rest **Stubbed**.

### Phase 1 — after Gap 1 (str local binding)
1. `dump`/`unparse`/`get_docstring` → `str`, each `assigns \nothing` (enables the §2.2 RT property).
2. `get_docstring(clean=False)` → `\result == doc` where expressible.
3. `comments` (count), `get_source_segment` (`str`) stubs.
4. **Remove the unsound `literal_eval` `>= 0`** (§4.4).
5. Tests use `str` assertions and assert RT (same input ⇒ equal output), **not** output content.

### Phase 2 — after Gap 6+7 (class support + node `τ` tags)
1. `class AST` base (`_fields`); `NodeVisitor` (`visit`/`generic_visit`); `NodeTransformer`.
2. `class Comment` (position ints + `text: str`).
3. Selected node classes (`Module`, `FunctionDef`, `ClassDef`, `Constant`, `Name`, `BinOp`,
   `Assign`, `Return`) carrying a concrete `τ` — the prerequisite for §5.

### Phase 3 — after P4 (`\typeof`/`\subtag`) **and** Phase 2
1. `isinstance(node, ast.FunctionDef)` via `\subtag(\typeof(node), FunctionDef_tag)` — decidable now
   that nodes carry a `τ` (needs both, per §5).
2. `walk`/`iter_child_nodes` richer postconditions where the node model permits.
3. Generated stubs for the full `_NODE_SPEC` hierarchy.

## 8  Soundness Ledger (what a green `astmod` run does NOT guarantee)

| Entry | Not guaranteed |
|---|---|
| `pure_ast.py` body | **Not verified** — it is TCB; `astmod` over-approximates it (§2 non-goal) |
| `parse` | nothing about the *tree* built — only a non-negative handle |
| `dump`/`unparse`/`get_docstring` | *which* string is produced — only that it is a `str` and the call is pure (RT gives equal-on-equal-input, not content) |
| `literal_eval` | nothing about the value (opaque handle; **no** `>= 0`) |
| `walk`/`iter_*` | the actual yields — only a count proxy (`walk`: `>= 1`) |
| `isinstance` (pre-Phase 3) | type membership — `τ(node)=Any` ⇒ symbolic, not decided |

A `--soundness-report` should mark which user-code VCs rest on the Specified/Stubbed rows above.

## 9  Acceptance criteria (bucket-aware; raw VC counts dropped)

VC *count* is not coverage when most VCs are `>= 0`/handle proxies, so criteria are stated per bucket,
and any reported count is split Modelled / Specified / Stubbed.

| Criterion | Phase | Bucket it lands in |
|---|---|---|
| §4.1 identity facts usable in user code | 0 | Modelled |
| `dump`/`unparse`/`get_docstring` return `str` | 1 | Specified |
| RT: `dump(parse(s))` equal on equal `s` (via purity) | 1 | Specified (purity) |
| `literal_eval` carries **no** false postcondition | 1 | Stubbed (fixed) |
| `comments`/`get_source_segment` present | 1 | Stubbed/Specified |
| `NodeVisitor` subclassable in verified user code | 2 | Specified |
| `Comment` with `text: str` usable | 2 | Specified |

| Coverage reported per bucket after each phase | 0–3 | — |
