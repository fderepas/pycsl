KEY FINDING 2 (u1 / u3 / v2 / t1 / v3: setattr by a string tuple or by a library helper; PRE-EXISTING).
Some stdlib helpers call setattr internally:
- `functools.update_wrapper(wrapper, wrapped, assigned=(...), updated=())` runs `setattr(wrapper, name,
  getattr(wrapped, name))` for every name in `assigned`.
- `test.support.swap_attr(obj, "name", v)` sets the attribute with setattr.
With the package module as `wrapper` / `obj`, they replace the submodule attribute `pkg.b` (u1, u3, t1) or a
dependency's function `pkg.b.one` (v2, v3). Rule E' records only attribute stores and Name-callee
`setattr` / `delattr` with a literal name. The module object passed as an argument does set u71's escape flag,
but the store itself is never recorded, so nothing is judged. The program-file rebound-name rule does not know
these callees. Head and L21 PROVE `pkg.b.one() == 1`, and CPython prints 2 (both interpreters).
`functools.wraps(...)(pkg)` (u2) is refused only because its callee is computed.
Fix direction (fail-closed): once a module object escapes into a call ARGUMENT (u71's "imported name used as a
value", or a chain rooted at one such as `pkg.b`), refuse the program. Or, narrower: refuse when the callee is
not a program / verified function, i.e. when an import-bound module is passed to any stdlib or installed-library
function.

KEY FINDING 3 (o5 / o4: INTRODUCED over-refusal of u73's annotation / class-base escapes).
u73 made two positions value positions, so that any store receiver is judged:
- an import-bound name in a parameter, return, module-level or class-level annotation;
- an import-bound name used as a class base.
u71's import-bound set `_mc671` holds EVERY from-import target. So `from typing import List` with
`def g(xs: List[int])` (o5), or `from pkg.k import Base` with `class D(Base)` (o4), now counts as a module-object
escape. rt79 r1 (a `self.b = 1` in an unrelated class, CPython 4 = claim) is then refused again (REBOUND), while
L21 PROVES both programs. o5c (no annotation) still proves at head.
Typed parameters with typing names are ubiquitous, so u71's r1 narrowing is largely undone. It costs only when a
store's attribute name collides with a submodule name of a reached package. That is why u73's corpus sweeps show
0 GONE.
Sound narrowing: in annotation and class-base positions, count only names that CAN denote a module:
- names bound by `import X [as Y]`;
- names bound by `from X import n` where X is a package and n is (or may be) a submodule: an entry of X's
  directory, an unresolvable source, an installed library, or a stdlib package with a submodule n;
- names bound by `from X import n` where the binding of n in X is not a top-level `def` / `class`.
A class object base never reaches `__mro_entries__` (PEP 560 consults it only for non-type bases). A typing alias
such as `List[int]` is not a module, and a class reaches its module only through attributes already on the
escape list (`__globals__`, `__dict__`, `sys.modules`).
Evidence: logs/p-rt83b/{o4,o5,o5c}/P__prog.log (SUCCESS), logs/p-rt83/{o4,o5}/P__prog.log (REFUSED),
logs/p-rt83/o5c/P__prog.log (SUCCESS).
