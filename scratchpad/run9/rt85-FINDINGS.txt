Root causes / suggested fixes
- F1: inlined bodies (apply_inline_globals) are re-resolved in the IMPORTER's namespace. This covers bare names of re-exported
  helpers, builtins captured by any injected def, dotted `m.f` calls, and module constants. Refuse an inline when the method body
  references any free name (call or Var) that is not an in-file def of the method's own file already bound under a batch identity.
  Alternatively, apply the u72 renaming to every free name (constants included) and exclude injected functions from the module
  pass's global `_rewrite_ir_calls` loop.
- F2: default-argument expressions are substituted at the call site with the importer's bindings. Evaluate them in the defining
  module: fold them to that module's constants, or rename them like a batch callee. Otherwise refuse a non-literal default of an
  imported function.
- F3: classes are identified by their bare name across modules. Refuse two classes with the same bare name in one import
  closure, or a dependency class whose base, resolved in ITS OWN file, differs from the importer's type of that name. This
  extends #629 to dependency files.
- F4: in `_resolve_module_imports`, match `m.` only for calls whose remainder has no dot (`m.f`), or process the longest module
  locals first. A `m.sub.f` call must be left to the `m.sub` import, never stripped to `sub.f`.
- F5: `_own72` must exclude lifted nested defs (and methods): only top-level program defs bind a module name.
- O1/O2: when `m.f` cannot be followed but the name is held by the def that the module's own star/conditional import would bind
  (same file and name as the program's from-import), binding to it is faithful. Optional narrowing.
- O3: the route #629 wildcard rule could admit a bare base when the star module IS the single module defining it.
- O4: `_same72` should compare entries modulo the u72 call rewriting (same file + same in-file name), not the raw IR.
