KEY FINDING 1 (p2 / p2b / p8: rule E' escape through a class base; PRE-EXISTING vs L19, REGRESSION vs u69).
Rule E' judges a store to a non-import-rooted receiver only when `_esc671` is set. A class BASE is an allowed
position for an import-bound name. Since PEP 560, though, a non-type base is passed to its own `__mro_entries__(bases)`.
That is an ordinary module-level function of the package, and it receives the package module object as `bases[0]`.
A store through `bases[0]` has receiver root `bases`, not import-rooted, so it is not judged.
Route #483 skips the program file, so the class statement there is never judged. In a dependency, #483 refuses it
("module used as a value"; probe a2).
Results: head proves `zv81p2.b.one() == 1` and CPython prints 2. u69 refused it (logs/q2-rt81c.txt), and L19 proves it.
The same hole is latent for annotations (p1b / p6b: an import-bound name in an annotation is exempt, and
`f.__annotations__` hands the module out) and for callee-position calls that return a module
(p7: `pkg.__loader__.load_module("pkg")`). In p1b / p6b / p7 the import stage now ADMITS the program and only an
unrelated WhyML type-check error stops it.
Fix direction: E' should count as an escape an import-bound name in a class base (or any ClassDef keyword)
whenever the module named there defines `__mro_entries__`. Fail-closed is simpler: any import-bound name used as a
class base, any import-bound name in an annotation (drop the `_ann671` exemption, or treat a read of
`__annotations__` / `__annotate__` / `get_type_hints` as an escape), and any attribute `__loader__` / `load_module` /
`__spec__` in a callee chain. The robust alternative is to restore u69's any-receiver judgement for stores whose
attribute names a submodule, and narrow only on `self.<n>` stores inside methods (the r1 shape).
Evidence: logs/p-rt81/p2/P__prog.log, logs/p-rt81b/p2/P__prog.log (and p2b, p8), logs/p1.txt, logs/p2.txt,
logs/q2-rt81c.txt, logs/q4-rt81c.txt, logs/cpy3.txt, logs/cpy6.txt.

KEY FINDING 2 (x3 / x9 / x4 / x1b: `__all__` the walk cannot see; PRE-EXISTING, bypasses u71 route #626).
(a) CPython's `from pkg import *` reads `pkg.__all__` through `hasattr` / `getattr`, so PEP 562 `__getattr__`
answers it. An `__init__` with no `__all__` binding (count 0, so pycsl follows nothing) and a `__getattr__` that
returns a list for a computed `"__all__"` key loads w.py. x3 / x9: the writer runs and CPython prints 5, while
head proves 4.
(b) The outside-mutation trigger `_alx671` looks only at Attribute `.__all__` and the Constant "__all__". An import
alias `from pkg import __all__ as A` (or `from . import __all__ as A` in a submodule), followed by
`A.append("w")` / `A += [...]`, mutates the literal list in place. pycsl follows ["k"] and CPython loads w. In x4 the
mutation is in a submodule the package's own `__init__` imports; in x1b it is in a module the program imports first.
Fix direction: in the `__init__` check, refuse (`WILDCARD-ALL-UNKNOWN`) when the `__init__` defines a module-level
`__getattr__` (and, to be safe, `__dir__`). In `_alx671`, also count every `ast.alias` whose name is `__all__`, from
any reached module. Add the same to the #483 closure expansion.
Evidence: logs/p-rt81{,b}/{x3,x9,x4,x1b}/P__prog.log (8 x SUCCESS), logs/cpy2.txt, logs/cpy4.txt.

KEY FINDING 3 (p4 / p4b: a string-based monkeypatch; PRE-EXISTING, a new class outside every store rule).
`unittest.mock.patch("pkg.b", K).start()` resolves the dotted string itself and `setattr`s the package attribute.
