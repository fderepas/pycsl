KEY FINDING 1: the rule M local-scope narrowing has a BUG for the comprehension's first iterator (k1, k1f, k2, k2g).
These are false proofs at head. They were also false at L21, so the class is PRE-EXISTING, but this is a hole in the
new u75 code, not an untouched area.
Where: src/pycsl/frontend/ir_resolve.py, the `_lc675` loop (diff lines ~693-697 of
`git diff ba48d5888 0891f99e7 -- src/pycsl/frontend/ir_resolve.py`):
    elif (isinstance(_pp675, (ListComp, SetComp, DictComp, GeneratorExp))
          and not any(_g.iter is _ch675 for _g in _pp675.generators[:1])):
        _sb675 = [_g.target for _g in _pp675.generators]
Walking up from the Name, `_ch675` is the child of the ListComp on the path. For a name inside a generator, that child
is the `comprehension` node, never `generators[0].iter`, so the exclusion never fires.
As a result, a name in the FIRST iterator (which CPython evaluates in the ENCLOSING scope) counts as comprehension-local
whenever some target of the comprehension has the same name. The import-bound module is then exempt from rule M.
The first iterator then hands the module to update_wrapper (k2), or binds it to the target used in the element (k1).
CPython prints 2. Both trees prove `pkg.b.one() == 1`.
The dependency variant (k2d) is refused by #483. So the hole is in the PROGRAM file, where #483 does not judge.
Fix direction: keep the previous node on the upward path (`_gc`). The path from the Name is Name -> List ->
comprehension -> ListComp, so at the ListComp `_gc` is the iter subtree. Then exclude the case
`_ch675 is _pp675.generators[0] and _gc is _pp675.generators[0].iter`.

KEY FINDING 2: a FUNCTION metaclass receives the module class base (k9, k9f). PRE-EXISTING. It bypasses the
u73/u75 class-base reasoning.
u75 section 1: "PEP 560 calls `__mro_entries__` only for a base that is not a type, so a class base never hands the
module out". That is false when the class statement has `metaclass=<a plain function>`. `__build_class__` then calls
the function directly with `bases = (pkg,)`. The metaclass is not a type, so there is no metaclass computation and no
check of the bases. No module hook is needed.
At head, an import-bound module in a class base is only an escape (`_ex671` / `_cb673`). It refuses only together with
a module hook (MODULE-HOOK) or a submodule-named store. Here `bases[0]` is a parameter, and the store happens inside
update_wrapper.
Evidence: logs/p-rt86{,b}/k9/, logs/p-rt86{,b}/k9f/, logs/cpy3.txt. The dependency variant is refused
("metaclass not modelled").
Fix direction: a class base that can be a module (F / S / M) refuses whenever the ClassDef has ANY keyword
(`metaclass=` especially), or always (fail-closed). A module is never a valid base without a hook anyway, so
always-refuse costs nothing on true programs: `class C(module)` is a TypeError in CPython without
`__mro_entries__`.

KEY FINDING 3: the "unshadowed builtin" exemption misses wildcard bindings (k3w). PRE-EXISTING.
`_bn675` collects `alias.asname or alias.name`, which is "*" for a wildcard. A builtin name such as `print` / `hasattr`
/ `repr` bound by `from hw import *` therefore still counts as the builtin. `print(pkg)` hands the module to hw's
function, which calls update_wrapper.
L21 proves it as well. pycsl models `print` as the builtin. The older wildcard-after-binding rule catches only the
order wildcard-then-binding (k3 / k3h, refused).
Fix: count a wildcard import as binding every exempt builtin name (or follow the wildcard's names). Do the same in
`_gb675` (the hasattr / getattr binding check for the o7 admission).

KEY FINDING 4: implicit annotation evaluators (k5n, k11). PRE-EXISTING.
u73/u75 treat an import-bound name in a class / parameter annotation only as an escape. The u73 annotation-evaluator
escape (`get_type_hints`, ...) also does not refuse by itself. Two shapes pass:
- `typing.NamedTuple` evaluates class annotations at class creation (k5n). The annotation
  `functools.update_wrapper(pkg, ...)` ran and replaced pkg.b. pycsl ignores the annotation and proves the claim.
  dataclass is refused (k5).
- `typing.get_type_hints(h)` evals a STRING annotation (k11), which no AST rule sees. The u73 escape (`get_type_hints`
  imported or read as an attribute) only records a reflective escape, and no store follows.
Fix direction: any call argument or Call inside an evaluated annotation is a rule-M value use, the same as outside it.
An annotation evaluator (`get_type_hints`, `get_annotations`, `ForwardRef`, annotationlib, inspect) in a program that
also has a local import should join route #326's list (strings run).
