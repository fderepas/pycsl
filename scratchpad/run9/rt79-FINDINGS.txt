KEY FINDING 1 (d8; rule D, u69 o1 narrowing). Rule D admits a top-level `def b` in a package `__init__` beside a
submodule b.py when no REACHED module spells `b` in an import. A wildcard import in the PROGRAM is the gap. CPython's
`from pkg2 import *` imports every name in pkg2's `__all__` that is not yet an attribute, here the submodule
pkg2.m, and m.py's `import zv7od8.b` loads the submodule and rebinds `zv7od8.b` over the def. Neither the u60
walk nor the #483 closure follows `__all__`-named submodules (`_ent660` drops `*`), so m.py and b.py are never
reached. `_imc669` therefore holds no `b`, and only a NON-program `*` counts. b.py's import-time dynamic code
(`sys.modules[__name__].__class__ = ...`) is never judged either: d7, where the program spells
`from zv7od7 import b`, reaches b.py and is refused for exactly that code.
Results: head proves `zv7od8.b() == 1` and CPython prints 2. Base L19 proves it too, so the class is PRE-EXISTING.
u66 refused it with #621 (logs/q8-rt79c.txt), so u69's narrowing reopened what u66 had closed.
Fix direction: in rule D, count a wildcard in the program too (or any wildcard of a package whose `__init__`
binds `__all__`). More generally, see finding 2.
Evidence: logs/p-rt79/d8/P__prog.log and logs/p-rt79b/d8/P__prog.log (SUCCESS, oom 15->15),
logs/q-rt79/d8/P__prog.mlw (`val b () : int ensures { result = 1 }`), logs/cpy7.txt (b.py loaded / result 2).

both closures: the u60 / #621 / rule-E walk, and the #483 import-time closure. A dependency's
`from zv7w2 import *` with `__all__ = ["b"]` runs zv7w2/b.py, whose import-time writer `hw792.one = _two` would be

KEY FINDING 3 (z1; PRE-EXISTING, new class, #622 family "which file does CPython load"). The `--import-path`
entries (`_EXTRA_IMPORT_PATHS`) are only ever probed as directories (`os.path.join(base, *parts) + ".py"`). A zip
