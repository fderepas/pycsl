`scratchpad/w8/census_fields2.py` walks each `_PY_EXPR_HANDLERS` / `_PY_STMT_HANDLERS`
entry, takes the TRANSITIVE closure of the same-module functions it calls (depth 3 — the

reports all four of its fields missing), and compares the fields mentioned anywhere in that
closure against `pure_ast._NODE_SPEC` for the dispatched node type.

  STATEMENT handlers: 5 candidates, every one resolved:

  · `For.orelse`, `While.orelse` — REFUSED. Probed both ways with `#@ assert 1 == 2` in the
    `else`; both give "`for ... else` / `while ... else` is not modelled ... the clause
    would be silently DROPPED".
  · `With.items` — the CTXBIND ratchet (50), already a tracked plane.
  · `AnnAssign.annotation`, `.simple` — normalized in desugar before Module 5 reaches them
    (`check-dropped-mutation` classifies a non-Name annotated store as NORMALIZED).
  · `Raise.cause` and `Raise` arguments after the first — GENUINELY DROPPED
    (`_py_stmt_raise` reads `exc.func.id` and `exc.args[0]` only), but NOT DEMONSTRABLE.
    Four probe families were built — `-> int`, `-> None`, with and without
    `#@ raises ValueError when True`, each with a violated precondition in the dropped
    position and the SAME violated precondition in `args[0]` as the control — and all of
    them, controls included, fail identically. The reason is upstream of the drop: a call
    inside a `raise` expression emits an application Why3 rejects outright with
    "This function has side effects, it cannot be used as pure", so NOTHING proves over
    that position. A drop in a position where no proof can be obtained cannot produce a
    false proof. REOPENING CONDITION, recorded rather than scoped: if a pure-call-in-raise
    lowering ever lands, re-probe `cause` and `args[1:]` immediately.
