Two thirds of the reference suite's red was one decision, and it turns out
to be a bookkeeping one. `import ctypes` is on the UB-7.4 C-extension
deny-list, and every test in `python-reference/stdlib/ctypes/` (plus its
`_call_fails` twins) errors at the import with "Either annotate the
importing function ... or pass --allow-unverified-imports".

THE TESTS ARE NOT ABOUT THE IMPORT POLICY. Each one is a two-line driver
that calls one ctypes stub and checks its declared contract survives to a
type-checking emission (`# pycsl-flags: --no-proof`,
`# pycsl-expected: PASS`). The deny-list has its OWN dedicated test —
`pycsl-reference/0400`, "UB-7.4: --allow-unverified-imports overrides the
deny-list" — which uses exactly this flag. So the policy is covered, and
these 64 were simply never updated when the deny-list landed.

Added `--allow-unverified-imports` to their `# pycsl-flags:` line. One line
each, no source change, no deny-list weakening.
