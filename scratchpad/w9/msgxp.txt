GATE-INTEGRITY(#44): the suite reported an expected-FAIL test that PROVED as a PASS — all 241 negative witnesses were unenforceable

`bin/run-reference-tests.sh`'s worker classified in this order:

    if SUCCESS      -> PASS
    elif expect_fail -> XFAIL
    ...

So a `# pycsl-expected: FAIL` test that started PROVING was reported as a
PASS and the suite got GREENER.

WHAT THAT MEANS FOR THIS CAMPAIGN. The corpus holds 241 expected-FAIL
files, and every route witness in it — the eighteen from routes #1-#21 and
the eleven this window added (0991-1001) — is one. Their entire purpose is
to demonstrate that a contract FALSE of its program no longer verifies. If
an unsoundness came back, the witness would start proving, and the suite
would have said PASS. **A negative witness that cannot fail is not a test**,
and this campaign has spent four relaunches on the proposition that a gate
which cannot distinguish "nothing is wrong" from "I looked at nothing" is
not a gate. This was that, applied to the campaign's own witnesses.
