# 07-1705-spec — Faithful `array_concat` via an immutable `seq.Seq` snapshot model

**Status:** Draft (generic specification — intent and gated phasing, not implementation)
**Date:** 2026-06-07
**Source:** the one open follow-on from `07-1321-spec.md` S4 — Python `list`/`bytes`
concatenation (`a += b`, `a + b`) currently lowers to an effect-opaque `array_extend` (unit;
type-correct but length/contents unprovable) because a faithful mutable-array `array_concat` is
rejected by Why3's aliasing discipline.
**Scope:** the **PyCSL tool only** (`src/pycsl`, WhyML emitter). `pure_lib/` is not edited here.
**Doctrine:** no-more-int / EXTREME RIGOR — a list is `array int`, and concatenation must be
modelled so the result's **length and contents are provable** (`\length(a + b) == \length(a) +
\length(b)`, and each element placed faithfully), not opaque. Legacy emission stays
**byte-identical** for every file that does not concatenate (the regression gate).

---

## 1. Why the direct mutable-array concat is blocked

`07-1321` S4 attempted:

```whyml
val array_concat (x: array int) (y: array int) : array int
  ensures { Array.length result = Array.length x + Array.length y }
  ensures { forall i. 0 <= i < Array.length x -> result[i] = x[i] }
  ensures { forall i. 0 <= i < Array.length y -> result[Array.length x + i] = y[i] }
...
dst := array_concat !dst src        (* a += b *)
```

Why3 rejects the application: **"this application creates an illegal alias."** `array.Array` is a
*mutable* type with a region; a `val` taking **two** mutable `array int` arguments requires their
regions provably disjoint, and rebinding `dst` to a mutable result that may alias `!dst` is
forbidden. Why3's effect/region typing cannot discharge this for two arbitrary array operands.
The blocker is the **mutability**, not the contract — the `ensures` above is exactly right.

## 2. The fix — operate on immutable snapshots

`seq.Seq` is Why3's **immutable** finite-sequence theory: pure `Seq.length`, indexing `s[i]`, and
concatenation (`++`). Immutable values have no region, so there is **no aliasing constraint** — a
function may take and return any number of sequences freely. The design snapshots each operand
array into a `seq int`, concatenates purely, and materialises a **fresh** result array:

```
a += b   ≡   a := materialize (snapshot !a ++ snapshot b)
a + b    ≡   materialize (snapshot a ++ snapshot b)
```

with two faithful bridge vals:

```whyml
val snapshot (a: array int) : seq int
  ensures { Seq.length result = Array.length a }
  ensures { forall i:int. 0 <= i < Array.length a -> result[i] = a[i] }

val materialize (s: seq int) : array int           (* result is a FRESH array *)
  ensures { Array.length result = Seq.length s }
  ensures { forall i:int. 0 <= i < Seq.length s -> result[i] = s[i] }
```

`snapshot` takes **one** mutable array (no two-mutable-arg problem); `++` is pure; `materialize`
returns a fresh array (like the existing `array_slice` / `sorted_1` array-returning vals, which
are used in `let` bindings without aliasing). Composing them, the length-additive and
element-placement facts follow from the three pure `ensures` + the `Seq.(++)` axioms — so
`\length(a + b)` and `(a + b)[i]` become provable.

### Reuse (do NOT reinvent)
- **`use seq.Seq` already exists** in the preamble (no-more-int-7 §B′ — "immutable list-snapshot
  value model"), gated by a `needs_seq` flag. This spec reuses that import path and snapshot
  vocabulary rather than adding a new theory.
- **Array-returning val pattern** is established (`array_slice`, `sorted_1` in
  `expressions.py`) — `materialize` follows the same shape and is consumed via a `let`/`:=`.
- The lowering site is the single `array += array` arm already isolated in
  `statements.py _handle_augassign_stmt` (today's opaque `array_extend`).

## P1 — Snapshot bridge vocabulary (LOW)

### Requirements
- **P1.1** Emit `snapshot`/`materialize` bridge vals (above) into the abstract-op block, behind a
  `needs_seq`-style flag so non-concatenating files stay byte-identical. `use seq.Seq` (+ the
  existing import ordering vs `array.Array`/`map.Map`) is triggered only when the bridge is used.
- **P1.2** The bridge `ensures` are length- and element-faithful (no int-hash, no opacity).

### Acceptance
- [ ] A trivial round-trip driver (`materialize (snapshot a)` equals `a` element-wise, same length)
      proves.
- [ ] Files with no concatenation emit byte-identical WhyML (no `seq.Seq` import).

---

## P2 — Lower `array += array` faithfully (MEDIUM; the blocker)

### Requirements
- **P2.1** `a += b` where the target is array-typed lowers to
  `a := materialize (snapshot !a ++ snapshot b)` for a ref-wrapped target (rebind a fresh array),
  replacing the effect-opaque `array_extend`. A non-ref array local is given a ref (or the same
  rebind via a fresh `let`), so the result is observable — the opaque fallback is removed, not kept.
- **P2.2** The src operand `b` is snapshotted whether it is a param, local, or literal; a
  ref-wrapped src is dereferenced first (`snapshot !b`).
- **P2.3** No integer-`+` path and no `array_extend` opacity remain for array operands — the result
  length/contents are provable.
- **P2.4** `\length` of the post-concat target, and indexed reads of it, resolve through the
  `materialize` ensures.

### Acceptance
- [ ] `cat(a, b)` with `ensures \length(\result) == \length(a) + \length(b)` **proves** (the S4
      driver `0619`, currently only type-checking, is upgraded to prove the length law).
- [ ] An element-placement driver proves (`(a + b)[0] == a[0]` for non-empty `a`,
      `(a + b)[\length(a)] == b[0]`).
- [ ] A byte-packing shape (`parts = bytearray(); parts += _pack(...); ...`) proves its assembled
      length — the `_pack_inode` motivation from `07-1321-req.md`.
- [ ] No regression on the full pycsl-reference sweep; before/after WhyML byte-diff reviewed
      (only concatenating files change).

---

## P3 — `array + array` expression form (LOW; optional, on a driver)

### Requirements
- **P3.1** The binary `a + b` on two array operands (not just `+=`) lowers to
  `materialize (snapshot a ++ snapshot b)` in expression position (e.g. `return a + b`), reusing P1.
- **P3.2** Pursue only if a real driver needs the expression form; otherwise defer (YAGNI).

### Acceptance (if pursued)
- [ ] `return a + b` proves the length-additive postcondition.

## Cross-cutting & risks

- **Aliasing-free by construction.** All composition is over immutable `seq int`; the only mutable
  values are the operand arrays (read once via `snapshot`) and the fresh `materialize` result —
  no two-mutable-argument val, so no "illegal alias".
- **Import ordering.** `array.Array`, `map.Map`, and `seq.Seq` all provide `([])`; keep the
  established last-import-wins ordering (`array.Array` after `map.Map`) and slot `seq.Seq` so that
  `a[i]` on an `array int`, `m[k]` on a map, and `s[i]` on a seq each resolve to the right theory.
  This is the main integration risk — gate with the byte-diff.
- **Performance.** `snapshot`/`materialize` are abstract vals (no executable cost in proof); they
  exist only to carry the faithful logic facts.
- **Generalisation (out of scope here).** The same bridge could later model other list producers
  faithfully (`list(x)`, slicing as seq, repetition `[v]*n`); this spec is concat-only.

## Gating & processing
**reproduce → fix → gate**, order **P1 → P2**, P3 only on a driver:
1. P1 bridge + round-trip driver; confirm byte-identical for non-seq files.
2. P2 lowering; **upgrade driver `0619`** from type-only to a proven length law, add element-
   placement + byte-packing drivers; remove the opaque `array_extend` arm.
3. Gate each: full `--pycsl` sweep (clean), WhyML byte-diff (only concatenating files change),
   traceability row, and update `07-1321-spec.md` S4 (mark the follow-on closed).

**Out of scope:** `pure_lib/` edits; a full `seq int` list model (lists stay `array int`, snapshot
only at concat); multi-byte literal tiling; the expression form P3 unless a driver appears.
